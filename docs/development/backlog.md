# 개발 백로그 — 게임 (living)

> **목적:** 구현·테스트 중 떠오른 "지금 슬라이스 밖" 할 일 중 **플레이어에게 전달되는 것**(콘텐츠·밸런스·게임필·UI/UX·메타)을 모은다.
> **코드 쪽 백로그는 [`backlog-implement.md`](backlog-implement.md)에 있다** — 아키텍처·리팩터·타입·툴체인·성능·미발현 로버스트니스 버그.
> **작성 시작:** 2026-06-11 · **분리:** 2026-07-10 (한 문서가 너무 길어져 게임/코드 두 축으로 분리)
> **성격:** 계속 갱신하는 living 문서. 슬라이스를 가로지르는 항목만 담는다(한 슬라이스 안의 작업 단계는 `pnpm wf`·세션 투두가 관리).

---

## 사용법 / 운영 규칙

- **조회(슬라이스 시작 시 필수):** 새 슬라이스를 계획할 때 **두 백로그를 모두** 본다. 이번 슬라이스의 테마·영향 범위에 걸리는 항목을 골라 스코프에 포함하고, 계획 문서에 "이 슬라이스가 닫는 백로그 항목"으로 명시한다. 같은 영역을 건드리는 김에 후속·로버스트니스 항목을 함께 처리해 왕복을 줄이는 게 이 문서의 목적이다.
- **추가:** 구현·테스트하다 떠오르면 즉시 해당 테마 표에 한 줄 추가한다. 요약(왜 중요한가)과 출처를 같이 적어야 나중에 의미가 산다.
- **항목 ID는 영구하다.** 세션·QA 문서와 PR 본문이 `F27`·`G1`·`B2`처럼 **ID로만** 참조한다. 재번호·재사용하지 않으며, 파일이 갈려도 ID는 그대로 따라간다. 새 항목은 해당 계열의 다음 번호를 쓴다.
- **새 번호는 `origin/main` 기준으로, 두 파일을 함께 보고 딴다.** 계열 번호는 `backlog.md`와 `backlog-implement.md`에 걸쳐 하나로 이어지므로 **한 파일만 보면 안 되고**, 로컬 main이 뒤처져 있으면 이미 머지된 번호를 다시 딴다. 실제로 이렇게 두 번 충돌했다(2026-07-17 정리) — 피처 브랜치가 낡은 main에서 분기해 `F47`·`F48`을 각각 두 항목이 나눠 가졌다. 번호를 따기 전에 `git fetch` 후 아래로 확인한다.
  ```bash
  git fetch origin
  git show origin/main:docs/development/backlog.md origin/main:docs/development/backlog-implement.md \
    | grep -oE '^\| [A-Z][0-9]+' | grep -oE '[A-Z][0-9]+' | sort -t. -k1.2 -n | uniq -d   # 중복 검사(비어야 정상)
  ```
- **충돌이 이미 났으면 선착순으로 판정한다.** 그 번호를 **먼저 쓴 항목이 지키고**, 나중에 딴 쪽이 다음 빈 번호로 옮긴다(도입 커밋 날짜로 가린다 — `git log -S'<항목 제목>' --reverse`). "참조가 많은 쪽이 지킨다"로 정하지 않는다 — 그 기준은 셀 때마다 답이 바뀌어 또 다툰다. 옮긴 항목에는 `(구 F48 — ID 충돌로 <날짜> 재번호)`를 남겨 옛 참조를 따라온 사람이 길을 잃지 않게 한다.
- **요약은 짧게, 상세는 출처에.** 이 문서는 출처를 **대체가 아니라 집약**한다. 진단·수치·변경 범위 같은 상세는 각 슬라이스의 `*-review-issues.md`·`*-plan.md`(불변 시점 기록)에 두고 여기선 링크만 건다.
- **완료·승격:** 완료되면 표에서 빼고 **아카이브 파일**로 한 줄 옮긴다 — 게임은 [`backlog-archive.md`](backlog-archive.md), 코드는 [`backlog-implement-archive.md`](backlog-implement-archive.md)다(2026-08-06 분리. 슬라이스 시작 조회에 아카이브가 딸려 읽히지 않게 하려는 것이다). 한 슬라이스 분량으로 커지면 `sessions/<날짜>-<feature>-plan.md`로 승격하고 아카이브에 링크를 남긴다.

### J4 진행 기록 (UI 완성도 분해)

각 슬라이스가 무엇을 닫고 무엇을 남겼는지의 축적 기록이다.

- **P0-1 HUD 레이아웃·바·테마 토대** (`feat/hud-layout`) — HUD 바 승격 + 목업 기준 전체 레이아웃 + 테마·해상도 토대. 계획: `sessions/2026-07-02-hud-layout-plan.md`.
  **남긴 것:** ① 쿨다운 라디얼(발사 후 회색 시계형 — 마법 쿨다운 데이터 배선 필요) ② 미니맵 실기능(v2) ③ 보스 체력바 배선(v1 무보스) ④ 분할 XP 바 룩 ⑤ placeholder 노드 4종 배치(2026-07-03 사용자 결정으로 제외).
- **P0-2 마법 아이콘 행** (`feat/spell-icon-row`, PR #52) — HUD 우하단에 `LoadoutLogic.MAX_SLOTS`개 슬롯을 3×2 그리드로 상시 표시하고, 보유 마법을 티어 오름차순으로 분류색 placeholder + 티어 라벨(F1·I2)로 채운다. 슬롯 빌드는 순수 로직 `SpellIconRowLogic.buildSpellIconRow`로 뽑아 `HudController`는 노드 매핑만 한다. 계획: `sessions/2026-07-05-spell-icon-row-plan.md`.
  **남긴 것:** ⓐ 호버 툴팁 + 강화 브레이크다운 ⓑ 쿨다운 라디얼(위 ①과 동일) ⓒ 최종 마법 아이콘 아트.
- **P0-3 일시정지 메뉴** (`feat/pause-menu`, PR #53) — ESC로 여는 수동 일시정지. `GameState.Paused` 신설 + `enterPause`/`resumePause`(기존 `enterLevelUp` 쌍 미러 — 소프트 일시정지라 기존 `state !== Playing` 가드가 전장을 얼린다), ESC 토글 결정은 순수 함수 `PauseMenuLogic.pauseToggleAction`. 계획: `sessions/2026-07-06-pause-menu-plan.md`.
  **함께 닫은 것:** I2(일시정지 중 XP 흡수), I3(정지 발사체 렌더 레이어 — 라이브 검증 결과 미재현).
  **남긴 것:** ⓐ 설정 화면(P1-6, 오디오 J6 선행) ⓑ 호버 툴팁(위 ⓐ와 동일) ⓒ `PauseController.titleLabel` `@property` 미연결 — 타이틀이 정적 텍스트라 언어 전환 시 안 바뀐다. `Title` 노드를 연결하면 닫힌다(코드 무변경). 인게임 언어 토글(P1-6) 때 함께.
- **P0-4 결과 화면 런 통계** (`feat/result-stats`, PR #54, 2026-07-11 머지) — 생존·레벨·킬·마법 강화 브레이크다운·패시브 레벨. B2(전역 강화 상한)를 함께 닫았다. 7단계에서 리워크 1회(DEV 시드 전역 보너스 0 회귀 + 총합 `Lv.N` 제거). 계획: `sessions/2026-07-06-result-stats-plan.md`.
  **남긴 것 — 결과 화면 비주얼 폴리시:** 계획 §2 OUT이 "레이아웃·모션은 `/design-consultation` 단계"로 미뤘다. 구현된 것은 목업의 **색·스크롤·행 포맷** 세 가지뿐이고, 나머지 시각 요소는 `ResultController`가 완성된 문자열을 평범한 `Label` 하나에 넣는 구조라 코드 변경이 필요하다 — ⓐ 생존·레벨 2열 그리드 + 박스 배경, ⓑ 값 우측 정렬(`생존 시간` … `10:32`), ⓒ 킬 종류별 다열 그리드, ⓓ 티어 배지 분류색(F1 빨강·I1 파랑·L1 노랑), ⓔ 섹션 제목 + 3색 범례, ⓕ 마법 행 배경·구분선, ⓖ 헤더 대형 타이포(DEFEAT/VICTORY) + 웨이브 보조줄. 목업: `../decisions/result-stats.html`. 출처: 7단계 인게임 테스트(2026-07-10).
- **P0-5 레벨업 카드 폴리시** (v1에서 닫힘 — 남은 것 전부 이연·이월) — plan §4 P0의 마지막 항목이었고, **2026-07-13 결정으로 v1 작업이 0이 됐다.** 세 갈래로 갈라졌다. ① **스킵 버튼 → 불필요로 확정.** 카드는 고르면 무조건 강해지므로 스킵할 이유가 없다. 대신 사용자가 원한 것은 **리롤(카드 재추첨)**이며, 이는 런당 기본 3회 + 결과 포인트 구매로 증가하는 구조라 세이브(J3)·메타 경제(J7)에 매달린다 → **MVP1 미포함, F37로 이월.** ② **시각 폴리시(아이콘·카드 UI·색)** → 디자인·아트 단계로 이연(**F33**). ③ **"등급색"**은 처음엔 애매했으나 논의 결과 **마법 티어(1~4)가 아니라 카드 1회 뽑기의 품질 등급**(일반·레어·유니크·레전드)을 뜻하는 것으로 확정됐고, MVP1 미포함 신규 기능이라 v2로 분리했다(→ **F34**). I3(정지 발사체 카드 가림)는 pause-menu에서 이미 닫혔다. **이로써 J4의 P0 다섯 항목이 전부 닫혔다.** 출처: 이 대화(2026-07-11·2026-07-13).
