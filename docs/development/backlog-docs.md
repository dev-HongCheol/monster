## 왜 갈라 뒀나 (2026-08-20)

문서 항목이 코드 백로그의 「툴체인 · 워크플로우」 절 하나에 열세 개까지 쌓였다. 그 절은 원래 장비마다 다시 나는 씬 파일 diff, 상태 파일 동기화, 아트 툴체인 같은 것을 담는 자리다. 그래서 정본 구조를 어떻게 바꿀지와 로컬 GPU 환경을 언제 철거할지가 같은 표에 나란히 앉아 있었다. 성격이 다른 항목이 한 표에 섞이면 두 가지가 함께 나빠진다. 슬라이스를 시작할 때 이번 테마와 무관한 행을 계속 지나쳐 읽어야 하고, 문서 작업을 묶어서 한 슬라이스로 집을 때 무엇이 후보인지 한눈에 안 들어온다.

**항목 ID는 옮겨도 그대로다.** `F75`는 코드 백로그에 있었을 때도 여기로 온 뒤에도 `F75`이며, 세션·QA 문서와 PR 본문이 ID로만 참조하므로 파일이 갈려도 참조가 살아 있다. **새 항목도 `F` 계열 다음 번호를 쓴다** — 이 파일은 새 계열 글자를 만들지 않는다.

**완료 항목은 [`backlog-implement-archive.md`](backlog-implement-archive.md)로 옮긴다.** 아카이브를 하나 더 만들지 않는 이유는, 파일을 가른 목적이 슬라이스 시작 시 읽는 양을 줄이는 것인데 아카이브는 애초에 그때 읽는 대상이 아니기 때문이다. 파일만 늘고 이득은 없다.

## 무엇이 여기 들어오나 — 코드 백로그와의 경계

**기준은 산출물이다.** 고쳐야 할 것이 문서이거나 문서를 재는 장치면 여기고, 게임이 실행하는 코드면 [`backlog-implement.md`](backlog-implement.md)다. 그래서 `tests/`에 코드를 쓰는 항목이 여기 있는 것은 모순이 아니다 — 문서 검사기(F82·F94·F97)는 코드로 쓰이지만 재는 대상이 문서다.

경계에 선 것 셋은 이 기준으로 코드 쪽에 남겼다.

- **F10**(`workflow-state.json` 크로스머신 동기화) — 결론을 ADR 004에 적게 되지만 정하는 것은 상태 파일을 커밋하느냐이고, 그건 문서 규칙이 아니라 도구 운용이다.
- **F79**(`main.scene` 일시정지 패널의 `LocalizedLabel` 잔재) — 고치는 대상이 씬이다.
- **F100**(생성 기록을 `source.json`으로) — 지금 기록이 산문 문서에 있다는 것이 문제의 출발점이지만, 실제로 짓는 것은 아트 생성 파이프라인의 데이터 스키마다.
