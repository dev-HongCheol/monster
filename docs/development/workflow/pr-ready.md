# pr-ready — Draft 해제와 머지

Draft PR은 이전 phase에서 이미 만들어져 있고 문서 정리도 거기서 끝났다. 여기서 하는 일은 상태 표시 확정, Draft 해제, 머지 셋이다.

**이 phase에서 문서에 허용되는 변경은 상태 표시뿐이다.** 내용을 옮기거나 줄이는 변경이 지금 들어가면 사용자가 검토하지 않은 채로 머지된다.

## 1. 상태 표시 확정

세션·플랜 문서의 상태를 "완료"로 바꾸고, 이번에 닫은 백로그 항목의 상태 어휘를 맞춘다. 완료 항목은 표에서 빼 아카이브로 한 줄 옮긴다 — 게임은 `backlog-archive.md`, 코드는 `backlog-implement-archive.md`다.

이때 정리가 덜 된 곳(몇 문단으로 자란 백로그 행, 낡은 참조, 깨진 링크)이 눈에 띄면 **여기서 고치지 말고** 이전 phase로 되돌려 처리한다. 기준은 [`user-verification.md`](user-verification.md) §1이다.

상태 표시를 바꿨으면 push해 Draft PR의 diff를 최신화한다.

## 2. Draft 해제와 머지

`gh pr ready <PR>`로 Draft를 풀면 머지가 가능해진다. **squash merge 전에 최종 커밋 메시지(제목과 본문)를 사용자에게 보여 주고 확인을 받는다.**

커밋 타입은 이렇게 고른다.

- `fix:` — 이미 main에 머지된 코드에 회귀가 생긴 경우
- `feat:` — 피처 브랜치 최초 구현 중에 발견하고 고친 것은 전부 여기

머지가 끝나면 `pnpm wf pr-done`.

## 3. gbrain 색인 갱신 (설치돼 있을 때)

머지는 이력이 늘어나는 유일한 시점이라 여기서 갱신한다. 안 하면 다음 슬라이스의 의미 검색이 이번 슬라이스를 못 본다. 게다가 "없다"가 아니라 **엉뚱한 문서를 그럴듯한 점수로** 돌려주므로 조용히 틀린 답이 된다(삭제된 문서가 최상위로 나온 적이 있다). 절차는 `docs/development/spec/ops-gbrain.md` §6.2에 있고, 미설치 환경이면 건너뛴다.

`gbrain serve`를 내렸다가 `/mcp`로 다시 붙이는 단계가 그 절차에 들어 있다. **다시 붙인 뒤 MCP `sources_status`로 `last_sync_at`이 방금인지, `last_commit`이 머지 커밋인지 확인한다** — 돌렸다는 것과 됐다는 것은 다르고, 이 확인이 없어서 갱신이 19일 동안 조용히 건너뛰어진 적이 있다.
