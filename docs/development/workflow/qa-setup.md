# qa-setup — QA 문서와 실패하는 테스트

`superpowers:executing-plans` → `superpowers:test-driven-development`를 호출해 진행한다. 이 phase에서 만드는 것은 둘이다.

- `docs/qa/<feature>-test.md` — 사용자가 에디터를 열고 인게임 테스트를 할 때 볼 문서
- `tests/logic/<Feature>.test.ts` — 아직 실패하는(RED) 테스트. 파일명은 기능 슬러그를 PascalCase로 바꾼 것이어야 아래 게이트가 찾는다

## 테스트를 생략할 수 있는 조건

구현할 코드가 전부 Cocos 프레임워크에 의존해 순수 로직 파일이 없으면 테스트 파일을 만들지 않아도 된다. 대신 `pnpm wf skip-test "<사유>"`로 이유를 남긴다. 이 판단은 AI가 혼자 하며 사용자 확인이 필요 없다.

## QA 문서에 반드시 들어가는 것

| 섹션 | 내용 |
|---|---|
| Impact Map | 변경 파일별 확인 범위 (회귀 기준) |
| 씬/프리팹 변경 사항 | 추가·수정할 노드 (타입·Position·Size·컴포넌트) |
| 에디터 연결 체크리스트 | `@property` 프로퍼티 ↔ 노드 매핑. ✅/❌ 상태 표시 |
| 수동 테스트 체크리스트 | `[ ]` 항목. 코드로 검증할 수 없는 인게임 동작만 |

## 슬라이스마다 새 문서를 만든다

QA 문서는 **그 슬라이스가 무엇을 어떻게 확인했는가**의 시점 기록이라 세션 문서·ADR과 같은 층이다. 다른 슬라이스의 QA 문서는 고치지 않는다 — 항목이 더 이상 유효하지 않아도 거기 가서 취소선을 긋거나 값을 되돌리지 않고, **새 문서에 "이번에 무엇이 바뀌었나"를 적고 이전 문서를 링크한다.** 어기면 그 슬라이스가 실제로 수행하고 검증했다는 기록이 사라져, "그때 무엇이 확인됐나"를 다시 알 방법이 없어진다.

다만 새 문서가 이전 것을 베끼지도 않는다. 씬 구조의 정본은 `main.scene`과 코드이므로, 새 문서는 이번에 바꾼 것과 그로 인해 확인할 것만 담고 나머지는 이전 문서를 가리킨다. 파일명과 상단 브랜치 표기는 그 슬라이스 하나를 가리킨다.

## 에디터 조립 레시피 (프리팹·노드를 새로 만들 때)

사용자는 이 문서만 보고 에셋을 만든다. "코드가 이 컴포넌트를 `getComponent`로 찾는다"는 계약 표만으로는 부족하다.

- **목표 계층 트리**(부모→자식)와 **만드는 순서 번호 목록**을 둘 다 넣는다. `Create → 2D Object → X`로 무엇을 만들고, 무슨 컴포넌트를 붙이고, 어떤 값(Content Size·Anchor·Align·Font Size·Layout 옵션)을 세팅하고, 프리팹화와 `@property` 연결까지 적는다.
- **Position과 Size는 씬 좌표계 기준으로 명시한다.** 의존하는 노드 계층 순서가 있으면 그것도 반드시 적는다.
- **구체 수치를 "사용자 배치"로 떠넘기지 않는다.** Position·Size·Widget 앵커 거리를 실제 값으로 준다(기존 HUD 좌표 컨벤션은 Widget 모서리 앵커 + 1280×720 기준이다).
- **노드의 부모·레이어·형제 순서는 `main.scene`을 읽어 확정한다.** 다른 슬라이스의 계획 문서에서 추정하지 않는다.
- **Cocos 컴포넌트 동작(Layout·Widget 등)은 Context7 공식 문서로 확인한 뒤 기술한다.** 추측하지 않는다. 예를 들어 GRID 레이아웃은 고정 크기 박스 안에 자식을 채우므로, 런타임에 만들어 붙이는 노드는 Content Size를 직접 줘야 에디터에서 보인다.
- 계획·코드·목업이 서로 어긋나면 임의로 고르지 말고 사용자에게 확인한 뒤, 그 결정을 날짜와 근거로 문서에 박는다. 코드가 `addChild`만 하는 식으로 형태에 무관하면 문서가 형태를 스스로 확정해야 한다.

체크리스트 항목은 사용자가 에디터를 열지 않아도 무엇을 해야 하는지 알 만큼 구체적으로 쓴다.

## 미확정 값에는 태그를 단다

구현 전이라 프리팹·씬·에디터 섹션은 계획 기준의 안이다. 미확정 제목·값에 `(잠정 …)`을, 아직 이름이 정해지지 않은 것에 `(가칭 …)`을 붙인다. 구현이 끝나면 실제 컴포넌트에 맞춰 확정하고 그 태그를 `(확정)`으로 바꾼다. 태그가 남아 있으면 검증 4종이 다 차도 다음 phase로 넘어가지 못한다 — 낡은 조립 레시피가 사용자 테스트로 새는 것을 막는 게이트다.

## 나가는 게이트: `ready-impl`

`pnpm wf ready-impl`이 직접 확인한다. QA 문서가 있는가, 테스트 파일이 있거나 스킵 사유가 기록됐는가, 그리고 스킵이 아니라면 **그 테스트가 실제로 실패하는가.** 통과해 버리면(= 실패하는 테스트를 먼저 쓰지 않은 것) 전이가 막힌다. 통과하면 `game/assets/scripts/**/*.ts` 편집이 열린다.
