# 용어 사전 (Game Dev Glossary)

이 문서는 `monster` 프로젝트에서 사용하는 게임 개발 용어를 정리한 참고용 사전입니다.
대화 중 모르는 용어가 나오면 이 문서를 먼저 확인하고, 없으면 추가 요청.

---

## 1. 장르 & 게임플레이

| 용어 | 설명 |
|------|------|
| **메카닉 (Mechanic)** | 게임이 작동하는 핵심 규칙/시스템. 예: 점프, 공격, 인벤토리. "전투 메카닉" = 전투 시스템 자체. |
| **호드 서바이벌 (Horde Survival)** | 끝없이 몰려오는 대량의 적을 처치하며 일정 시간 살아남는 장르. 뱀파이어 서바이버스, Brotato, Hell Maiden. |
| **로그라이크 (Roguelike)** | 한 판 죽으면 처음부터, 매번 다른 무작위 요소. 1980년 게임 Rogue에서 유래. |
| **로그라이트 (Roguelite)** | 로그라이크 + 영구 성장 요소 (죽어도 일부 진행 유지). Hades, Dead Cells. |
| **탄막 (Bullet Hell / 弾幕)** | 화면을 가득 채우는 투사체를 회피하며 진행하는 플레이. 일본 STG에서 유래. Hell Maiden에 포함. |
| **덱 빌딩 (Deck Building)** | 카드 컬렉션에서 자신만의 능력 조합을 만들어가는 메카닉. Slay the Spire, Balatro. Hell Maiden의 차별점. |
| **MVP (Minimum Viable Product)** | 최소 기능 제품. 핵심 가치만 살린 가장 작은 출시 가능 버전. |
| **픽업 (Pickup)** | 게임 중 떨어진 아이템을 줍는 메카닉. 강화/회복 등. |
| **메타 진행 (Meta Progression)** | 한 판이 끝나도 다음 판에 영향을 주는 영구 성장. 도감, 해금된 캐릭터. |
| **시너지 (Synergy)** | 아이템/능력 조합 시 추가 보너스. 1+1=3 효과. |
| **트랜스모그 (Transmogrification)** | 능력은 아이템이, 외형은 스킨이 결정하는 시스템. Diablo 3에서 유래. |
| **웨이브 (Wave)** | 한 번에 몰려오는 적의 묶음. 호드 서바이벌의 단위. |
| **빌드 (Build)** | 한 캐릭터의 무기/아이템/스탯 조합. "원거리 빌드", "탱커 빌드". |

## 2. 시점 & 그래픽

| 용어 | 설명 |
|------|------|
| **탑다운 2D (Top-down 2D)** | 위에서 바로 내려다보는 평면 시점. 뱀서, Brotato, 1세대 젤다. **우리 MVP가 선택한 방식.** |
| **사이드뷰 2D (Side-view 2D)** | 옆에서 보는 시점. 마리오, 메트로이드. |
| **2.5D 등각 (Isometric)** | 비스듬한 위에서 보는 시점. 디아블로, Hades, 발더스게이트. v3+에서 고려할 수 있음. |
| **3D (1인칭/3인칭)** | 카메라가 캐릭터 시점/뒤에. FPS, 액션 RPG. 우리는 안 함. |
| **픽셀 아트 (Pixel Art)** | 개별 픽셀이 보일 정도로 저해상도 의도적 아트. 셀데, 뱀서, Hell Maiden. |
| **고화질 일러스트** | 사실적이거나 매끄러운 셀쉐이딩. 디아블로 4, 모바일 RPG. |
| **셀쉐이딩 (Cel-shading)** | 만화 같은 평면 음영 기법. 젤다 BOTW, Hi-Fi Rush. |
| **Orthographic vs Perspective** | 카메라 투영 방식. Orthographic = 거리 무관 동일 크기 (2D 게임 기본). Perspective = 멀리 있는 것 작게 (3D 기본). |
| **셰이더 (Shader)** | GPU에서 픽셀을 어떻게 그릴지 정의하는 작은 프로그램. 조명, 이펙트, 후처리. |
| **VFX (Visual Effects)** | 시각 효과. 게임플레이 피드백을 위한 시각 연출 일체 — 폭발, 타격 섬광, 마법 이펙트, 잔상 등. 사운드의 **SFX**(§3.5)에 대응하는 시각 버전. 파티클·스프라이트 애니메이션·셰이더로 구현한다. 우리 마법 효과 레이어의 폭발 연출(`ExplosionVfx.prefab`)이 그 예이며, placeholder 단계에선 확장+페이드 스프라이트로 만든다. |
| **파티클 (Particle)** | 작은 그래픽 효과의 모음. 폭발, 연기, 마법 이펙트. |
| **스프라이트 (Sprite)** | 2D 이미지 한 장. 캐릭터/아이템 한 컷. |
| **스프라이트 시트 (Sprite Sheet)** | 여러 스프라이트를 하나의 큰 이미지로 묶은 것. 애니메이션 프레임 보관용. |
| **스프라이트 프레임 애니메이션 (Frame Animation)** | 조금씩 다른 스프라이트 여러 장을 빠르게 갈아 보여 움직임을 만드는 방식(만화 플립북). 우리 잡몹 12종이 이 방식(장당 2~6프레임, §3.1). 스켈레탈과 달리 뼈대가 없고 그린 프레임만 재생한다. |
| **스켈레탈 / 컷아웃 애니메이션 (Skeletal / Cutout)** | 캐릭터를 부위(머리·몸·팔 등)로 나눠 각 부위를 "뼈"에 붙이고 뼈를 움직여 애니메이션하는 방식. 프레임을 장마다 그리지 않아 부드럽고, 부위 텍스처만 갈아끼우면 스킨이 된다. 우리 플레이어·해금 캐릭터가 이 방식(§3.1). |
| **DragonBones** | 우리가 쓰는 스켈레탈 애니메이션 도구·런타임. Cocos에서 `ArmatureDisplay`로 재생한다(art-direction §3.2·부록 A). |
| **슬롯 / 스킨 (Slot / Skin)** | 스켈레탈 캐릭터의 부위 하나(머리·로브·지팡이 등)가 슬롯. 슬롯의 텍스처 세트를 통째로 갈아끼운 것이 스킨. 시트를 다시 안 그려도 돼서 스킨의 한계비용이 낮다(art-direction §3.2, 로드맵 v2 스킨 판매의 토대). |
| **occlusion fill (가려진 부위 채우기)** | 컷아웃 리깅 준비 작업. 팔을 몸에서 떼면 그 뒤 몸통이 비는데, 팔이 움직이면 그 부분이 드러나므로 미리 스타일에 맞춰 그려 채워 둔다. 파이프라인에서 유일하게 손그림 감각이 드는 지점(§8-2)이라 T포즈 생성으로 최소화한다. |
| **T포즈 / A포즈 (T-pose / A-pose)** | 팔을 몸에서 벌린 기본 자세. 이 자세로 생성하면 사지가 몸통을 거의 안 가려 occlusion fill이 크게 준다. 컷아웃 캐릭터를 이 자세로 만드는 이유. |
| **타일맵 (Tilemap)** | 작은 정사각형 블록(타일)을 격자로 배치해 만든 지도. 2D 게임 배경 표준. |
| **디자인 해상도 (Design Resolution)** | 게임 UI·씬을 작업하는 **고정 기준 좌표 크기**(예 1280×720). 모든 노드 좌표를 이 공간에 배치하며 런타임에 변하지 않는다. 실제 화면(브라우저 창·모니터)이 이와 달라도, 엔진이 디자인 해상도 기준으로 구성한 화면을 실제 화면 크기에 맞춰 통째로 스케일한다. 웹의 "기준 뷰포트 폭으로 목업 제작"에 대응. "고정된 크기"의 실체는 특정 노드가 아니라 이 좌표 공간이다. 프로젝트가 명시하지 않으면 엔진 기본값을 쓴다(현재 우리 상태 — HUD 슬라이스에서 확정). Fit 정책·Widget과 함께 다해상도 적응을 이룬다. |
| **Fit 정책 (Fit / Resolution Policy)** | 고정된 디자인 해상도를 가변 실제 화면에 **어떻게 맞출지**의 규칙. 화면 비율이 디자인 해상도와 다를 때 갈린다 — **Fit Height**(세로 맞춤, 좌우로 월드가 더/덜 보임), **Fit Width**(가로 맞춤, 상하로 더/덜), **Show All**(크롭 없이 전체 표시·여백[레터박스] 발생). CSS `object-fit`(contain/cover)을 게임 전체에 적용한 것. Cocos는 Project Settings의 Fit Width/Fit Height 조합으로 정한다. 우리 게임은 카메라가 플레이어를 추적하고 월드가 열려 있어, 크롭이 고정 아레나를 자르는 게 아니라 **보이는 월드 양만** 달라진다(그래서 Fit 계열이 무난). |

## 3. UI / UX

| 용어 | 설명 |
|------|------|
| **카드 UI (Card UI)** | 선택지를 카드 형태로 보여주는 인터페이스. Slay the Spire 풍, Brotato의 무기 선택. |
| **패시브 아이템** | 장착 시 자동으로 효과 발동. 별도 조작 없음. 예: HP +10, 이동속도 +20%. |
| **액티브 아이템 / 액티브 스킬** | 버튼을 눌러 발동. 쿨다운 있음. |
| **HUD (Heads-Up Display)** | 화면 위에 항상 표시되는 정보. HP 바, 점수, 미니맵. |
| **Widget (앵커 / 화면 정렬)** | UI 노드를 부모(화면)의 **모서리·가장자리에 상대적으로 고정**하는 컴포넌트. 상·하·좌·우 정렬 거리를 px 또는 %로 준다. CSS `position: absolute; top/right/left/bottom(+%)`에 대응. 디자인 해상도가 통째로 스케일돼도, 특히 화면 비율이 달라 크롭·레터박스가 생겨도 Widget이 붙은 요소는 **실제 보이는 모서리**에 다시 붙는다. HUD를 절대 좌표가 아니라 Widget으로 배치하는 이유(HP 좌상·타이머 상단중앙·XP 하단 풀폭 등). 요소마다 명시적으로 붙여야 하는 opt-in이다 — 안 붙이면 고정 좌표라 비율이 다른 화면에서 밀릴 수 있다. Canvas의 `alignCanvasWithScreen`이 Canvas를 실제 화면에 맞춰줘 Widget이 참조할 실제 가장자리를 만든다(우리 세 씬 모두 이 상태). |
| **인벤토리 (Inventory)** | 보유 아이템 목록. |
| **도감 (Codex / Compendium)** | 해금된 적/아이템/캐릭터의 목록 화면. |
| **언락 (Unlock)** | 조건 달성 시 해금되는 콘텐츠. |
| **튜토리얼 (Tutorial)** | 첫 플레이 시 조작/시스템을 가르치는 단계. |
| **온보딩 (Onboarding)** | 신규 유저가 게임에 적응하는 초반 경험 일체. |

## 3.5. 사운드 용어

| 용어 | 설명 |
|------|------|
| **SFX (Sound Effects)** | 효과음. 게임 내 액션 사운드 (히트, 발사, 픽업, UI 클릭). BGM과 구분. |
| **BGM (Background Music)** | 배경 음악. 챕터/메뉴별로 반복 재생되는 곡. |
| **SE (Sound Effect)** | SFX의 일본/한국식 표기. 같은 의미. |
| **Foley** | 실제 물리 사운드 녹음. 풋스텝, 문 닫힘, 천 스치는 소리 등. |
| **Ambient** | 환경음. 바람, 새, 도시 소음 등. 분위기 조성용. |
| **Voice (보이스)** | 성우 더빙 또는 캐릭터 음성. |
| **Stinger** | 짧은 음악적 강조. 보스 등장, 레벨업 같은 순간. |
| **Loop point** | BGM이 반복될 때 자연스럽게 이어지는 지점. |

## 4. 개발 용어

| 용어 | 설명 |
|------|------|
| **데이터 주도 설계 (Data-Driven Design)** | 게임 콘텐츠를 코드가 아니라 데이터 파일(JSON 등)로 정의. 새 적 추가 = 데이터 한 줄. |
| **JSON (JavaScript Object Notation)** | 데이터를 텍스트로 저장하는 표준 형식. 예: `{ "hp": 100, "speed": 5 }`. |
| **객체 풀링 (Object Pooling)** | 적/투사체 등을 미리 만들어두고 재활용. 매번 생성/삭제는 느려서 탄막에 필수. |
| **깊이 정렬 (Y-sort / Z-order)** | 어느 오브젝트가 앞에 그려질지 결정. 등각 게임에서 캐릭터가 나무 뒤에 가려지는 효과. |
| **델타타임 (dt / Delta Time)** | 직전 프레임부터 이번 프레임까지 흐른 시간(초). 60fps면 ≈ 0.016. 이동·타이머·피해 등 시간 기반 계산은 프레임 레이트와 무관하도록 dt를 곱해 처리한다. `update(dt)`가 매 프레임 엔진에서 받는 값. |
| **렉 스파이크 (Lag Spike)** | 게임이 순간 멈칫해 한 프레임의 dt가 평소(≈0.016)보다 크게 튀는 현상. 원인: 웨이브 스폰·대량 엔티티·GC(가비지 컬렉션)·에셋 로드·기기 발열. 호드 서바이벌+탄막은 후반 엔티티 폭증으로 가벼운 스파이크(50~300ms)가 흔하다(객체 풀링이 완화책). 시간 기반 로직은 큰 dt에서도 깨지지 않게 설계해야 한다 — 예: 피격 게이트의 `tickDamage`(`logic/PlayerDamageLogic.ts`)는 dt가 T의 몇 배여도 피해를 한 프레임에 1회만 적용하고 초과분을 이월한다. 일시정지(레벨업·백그라운드)발 누적은 `GameManager.update`의 state 가드가 `_tickPlayerDamage`보다 먼저 걸러 피해로 쌓이지 않는다. |
| **localStorage** | 웹 브라우저나 게임이 영구 데이터를 저장하는 공간. 세이브 파일 역할 (웹 빌드 시). |
| **컴포넌트 (Component)** | 객체에 부착되는 기능 단위. Cocos의 모든 노드는 컴포넌트 조합. |
| **씬 (Scene)** | 게임의 한 화면 단위. 메인 메뉴 씬, 인게임 씬, 게임오버 씬. |
| **프리팹 (Prefab)** | 재사용 가능한 객체 템플릿. "적 1종"의 청사진. Cocos `.prefab` 파일. |
| **노드 (Node)** | Cocos의 기본 단위. 트리 구조로 부모-자식. |
| **싱글톤 (Singleton)** | 게임 전체에서 하나만 존재하는 객체. GameManager 등. |
| **이벤트 (Event)** | 어떤 일이 일어났음을 알리는 신호. "적이 죽었다" 이벤트 → HP UI 갱신. |
| **유한 상태 기계 (FSM / Finite State Machine)** | 객체가 가질 수 있는 상태를 유한개로 정의하고 정해진 조건에서만 상태→상태로 전이하게 만든 모델. "지금 무슨 상태인가"와 "다음에 어디로 갈 수 있는가"를 명시해 복잡한 조건 분기를 정돈한다. 우리는 적 행동에 두 개를 쓴다 — **공격 FSM**(`EnemyAttackLogic.tickAttack`, `AttackState`: 조준 Aim → 텔레그래프 Telegraph → 발사 Fire → 쿨다운 Cooldown)과 **돌진 FSM**(`MovementLogic.tickLunge`, `LungeState`: 추격 Chase → 윈드업 Windup → 돌진 Lunge → 쿨다운 Cooldown). 둘 다 가변 상태(현재 상태·타이머·잠근 방향)는 `EnemyController`가 보관하고, 로직 모듈은 그 상태와 dt를 받아 다음 상태를 돌려주는 **순수 함수**만 둬서 cc 비의존으로 결정적 테스트가 가능하다. 정지·빙결이면 `canAct=false`로 FSM 전체를 동결해 헛발사·헛돌진을 막는다(§9.4). |
| **콜드 스타트 / 핫 리로드** | 콜드 = 처음 실행. 핫 리로드 = 실행 중 코드만 갱신. |
| **빌드 (Build)** | 소스를 실행 가능한 형태로 변환. "웹 빌드", "iOS 빌드". |
| **롤 (Roll)** | 난수 1회 추첨, 또는 그렇게 뽑힌 값. 주사위 굴리기(dice roll)에서 유래한 통용어. 보통 `[0,1)` 범위의 무작위 값 하나를 뜻하며 가중 추첨·확률 판정(크리티컬 롤, 루팅 롤)에 쓰인다. 우리 `SpawnDirectorLogic.selectEnemyId(wave, roll)`은 테스트 결정성을 위해 이 값을 **주입**받는다 — 실제 호출부는 `Math.random()`을 넘기고, 테스트는 고정값(roll=0, roll=0.99)을 넣어 결과를 예측 가능하게 한다. |
| **클로버 (Clobber)** | 어떤 값을 (대개 의도치 않게) **덮어써서 망가뜨리는 것**. 두 코드 경로가 같은 변수·메모리·파일에 쓸 때 한쪽 쓰기가 다른 쪽 값을 지워버리는 상황. 예: 백로그 F19 — `_updateAttackTelegraph`(발사)와 `_updateLungeTelegraph`(돌진)가 같은 `_windupActive` 필드에 써서, `update()`에서 나중에 도는 발사 경로가 돌진이 써둔 값을 매 프레임 덮어쓰면(clobber) 돌진 텔레그래프 점멸이 조용히 사라진다. |

| **Pixellab / Retro Diffusion** | 픽셀 아트 전용 AI 생성 도구. |
| **Sref / Style Reference** | 한 장의 이미지를 스타일 기준으로 삼아 일관성 유지하는 Midjourney 기능. 우리는 이보다 강하게 스타일을 고정하는 **LoRA**를 쓰기로 함(부록 C·§8). |
| **업스케일링 (Upscaling)** | 저해상도 이미지를 고해상도로 변환. Upscayl, Magnific AI. |
| **프롬프트 (Prompt)** | AI에게 무엇을 그릴지 알려주는 텍스트 명령. |
| **시드 (Seed)** | AI 생성의 무작위성 기준 숫자. 같은 시드+프롬프트면 같은 결과. |

## 8. 전투 · 마법 시스템

| 용어 | 설명 |
|------|------|
| **호밍 (Homing)** | 발사체가 목표(주로 적)를 추적하는 효과. 속도 자체가 느려지는 게 아니라 방향이 목표를 향해 휘어진다. 적이 회피·이동해도 따라잡을 확률 ↑. 강도(약/강)에 따라 회전 속도와 추적 강도 조절. |
| **AOE (Area of Effect)** | 한 점이 아니라 일정 범위 내 모든 대상에 영향을 주는 효과. 폭발/광역/오라 등. |
| **DOT (Damage Over Time)** | 한 번에 큰 피해 대신 일정 시간 동안 지속적으로 입히는 피해. 화상·중독·출혈 등. |
| **CC (Crowd Control)** | 적의 행동을 제한하는 효과. 마법사 v1은 **슬로우(이동 ↓) < 정지(이동 0, 접촉 피해 유지) < 빙결(이동 0 + 접촉 피해 0, 완전 무력화)** 3단계를 한 적당 **컨트롤 슬롯 1개**로 관리한다 — 가장 센 강도가 적용되고 지속은 활성 소스 중 max(기획 §9.4). |
| **정지 (Stun)** | CC 중간 강도. 적 이동을 완전히 멈추되 **접촉 피해는 유지**(닿아 있으면 아픔). 번개 정체성 = 정지(이동만 묶음)로, 얼음의 빙결(완전 무력화)과 구분한다. 라이트닝 볼트가 확률적으로 건다(기획 §9.4). |
| **노바 (Nova)** | 시전자(플레이어)를 중심으로 사방으로 퍼지는 광역 효과. 자기 주변 광역 공격의 대표 패턴. |
| **오라 / 아우라 (Aura)** | 시전자 주변에 항상 유지되는 효과 범위. 따라다님. |
| **폭발 (Explosion)** | 발사체가 적중하거나 지면에 닿을 때 주위에 추가 AOE 피해. |
| **관통 (Pierce)** | 발사체가 적을 맞춰도 사라지지 않고 계속 진행. 다수 적 일렬 명중. **마법사 v1 설계에는 관통 개념이 없다**(모든 마법은 단일 대상/범위형 — 기획 §7.1). 빔(일렉트로닉)의 라인 타격은 관통이 아니라 "라인 위 1회 다중 명중"이다. |
| **체인 / 연쇄 (Chain)** | 한 적을 맞춘 효과가 인근 다른 적으로 점프해서 전파. 체인 라이트닝의 대표 패턴. |
| **부채꼴 (Fan / Cone)** | 시전자 정면 일정 각도로 퍼지는 형태. 다발 발사 시 자주 쓰는 패턴. |
| **지정 낙하 (TargetedDrop)** | 발사체 비행 없이 바라보는 방향(facing) 일정 거리 지점에 짧은 예고 후 즉발 버스트가 떨어지는 패턴. 메테오·썬더스톰(기획 §9.2). |
| **무작위 폭풍 (RandomStorm)** | 화면 무작위 N개 지점에 지대를 생성하는 패턴. 각 지점은 생성 시 1회 피해 + 수명 동안 상태 재적용 틱. 블리자드(기획 §9.2). |
| **빔 / 라인 (Beam / Line)** | 시전자에서 조준 방향 직선(길이 L·굵기 W)을 따라 1회 타격하는 패턴. 발사체 관통과 달리 라인 위 적을 한 번에 판정한다. 일렉트로닉(기획 §9.2). |
| **시전 단위 dedup (Per-volley dedup)** | 한 번의 시전(volley)이 만든 모든 발사체·지대가 식별자 집합 하나를 공유해, 같은 적을 즉발은 시전당 1회·지대는 틱당 1회만 맞히는 중복 제거 규칙. 안정 식별자로 적 `spawnId`를 쓴다. 다른 시전·다른 마법끼리는 가산(기획 §10.2). |
| **피격 무적 (i-frame / Invincibility Frame)** | 플레이어가 한 번 피해를 받은 직후 짧은 시간(T) 동안 추가 피해를 받지 않는 보호 구간. 고전 액션게임에서 유래. 우리는 모든 피해원(접촉·발사체·돌진·휘두르기)을 하나로 묶는 **전역 i-frame**으로, 플레이어는 고정 주기 T(=피격 틱)마다 1회만 피해를 받는다. 떼에 둘러싸이거나 부채꼴 N발이 동시에 닿아도 그 구간엔 한 방만 들어온다(`logic/PlayerDamageLogic.ts`). |
| **피격 틱 / 틱당 max (Hit Tick / Per-tick Max)** | i-frame 구간의 길이 T이자, 그 구간에 들어온 피해를 정산하는 단위. 한 틱에 여러 피해원이 닿으면 **합산이 아니라 가장 센 한 방**(max)만 그 틱 피해가 된다 — 적이 많아도 즉사하지 않게 하는 뱀서식 규칙. 접촉(초당 DoT)도 `초당값 × T`로 환산해 같은 max 경쟁에 넣되 단일 접촉의 평균 피해율(DPS)은 보존한다. T는 짧을수록 어려운 밸런싱 노브(현재 placeholder 0.5초). |
| **자동 발사 (Auto-fire)** | 플레이어가 별도 키 조작 없이 쿨다운마다 자동으로 마법이 시전되는 모델. 호드 서바이벌의 표준. |
| **발사 형태 (Geometry)** | 마법이 "어디로 몇 발을 어떤 배치로" 내보내는지 — 발사체의 방향·개수·부채꼴 분포 같은 **공간 배치**를 뜻한다. "맞으면/시간에 따라 무슨 일이 일어나는가"의 **효과 레이어**(폭발·DOT·CC·체인·호밍 등)와 구분된다. 마법 패턴 엔진은 geometry를 결정하고, 효과 레이어는 발사체/실행부가 처리한다. |
| **조준 (Aim)** | 발사 기준이 되는 방향. 자동 발사 모델에서는 시전자(플레이어) 위치에서 조준 대상까지의 **단위 방향 벡터**를 뜻하며, 현재 구현은 조준 대상 = 최근접 적이다. 마법 패턴은 이 방향을 기준으로 발사체 방향·부채꼴 중심을 잡는다. 직선/부채꼴처럼 적을 향하는 패턴은 적이 없으면 발사를 보류하고, 자기중심 광역(노바)·메테오 등은 적과 무관하거나 바라보는 방향(facing)을 쓴다. |
| **마법 슬롯 (Spell Slot)** | 한 캐릭터가 동시에 보유·시전할 수 있는 마법 개수. 현재 6개 (테스트·배포 시 확대 가능). |
| **등급 (Tier)** | 분류 내 마법 강도 단계. 1~4. 분류가 달라도 동일 등급 마법은 강도가 비슷하게 설계. 웨이브 n에서는 n 등급 이하 마법만 덱에 등장. |
| **강화 옵션 (Upgrade Option)** | 마법을 강화할 때 무엇을 강화하는지의 종류. 데미지/쿨다운/발사체 수/범위 등. 마법마다 허용 옵션이 다를 수 있음. |
| **강화 레벨 (Upgrade Level)** | 각 강화 옵션이 몇 번 누적 적용됐는지의 단계. 옵션별 0~4 cap. 예: 파이어볼-데미지 강화 2레벨. |
| **분류 강화 (Category Upgrade)** | 특정 분류(화염/얼음/번개/기타) 마법 전체에 적용되는 강화. 개별 강화와 곱셈으로 합산. 옵션별 0~4 cap. |
| **플레이어 강화 (Player Buff)** | 마법이 아닌 캐릭터 자체에 적용되는 영구 패시브. 이동속도/픽업 범위/HP 회복/XP 획득량 등. 보조 마법과 효과가 겹치면 곱셈으로 합산. |
| **보조 마법 (Support Spell)** | "기타" 분류에 속하는 비-공격 마법. 슬롯을 점유하고 항상 ON 상태로 패시브 효과 제공. 직업별 정체성 표현. |
| **덱 시스템 (Deck System)** | 레벨업 시 무작위 카드 4장을 제시하고 하나를 선택해 빌드를 만들어가는 메카닉. 카드 종류: 플레이어 강화 / 마법 추가 / 마법 강화(개별) / 분류 강화. |

## 9. 적 시스템 (Enemy System)

> 적 시스템 설계 전체는 [적 시스템 디자인](../planning/enemy-system.md) 참조. 아래는 용어 정의.

| 용어 | 설명 |
|------|------|
| **이동 알고리즘 (Movement)** | 적이 플레이어 기준으로 "어떻게 경로를 잡는가"의 분류 축. *어떻게 움직이나.* v1: 직진 추격 하나뿐. v2: 지그재그/플랭커/돌진형. 새 알고리즘 = 새 코드 경로라 신중히 확장. 마법의 발사 패턴(geometry)에 대응. |
| **역할·스탯 프로필 (Role / Stat Profile)** | HP·속도·크기 조합이 만드는 전술 역할의 분류 축. *얼마나 빠르고 튼튼한가.* v1: 표준/스워머/탱크. v1엔 이동이 직진 추격 고정이라 **다양성이 여기서 나온다**. 라벨이며 실제 밸런스는 개별 적의 HP/속도/반경 수치가 결정. |
| **직진 추격 (Chase)** | 플레이어 위치로 직선 이동하는 기본 이동 알고리즘. 현재 skeleton의 동작. v1 적의 유일한 이동. |
| **스워머 (Swarmer)** | 역할·스탯 프로필 중 하나. 빠르고 약하며 작아서 다수로 몰려와 포위·압박. HP·크기 낮고 속도 높음. |
| **탱크 (Tank, 적)** | 역할·스탯 프로필 중 하나. 느리지만 HP·크기·접촉 대미지가 높아 우선 처리를 강제. "탱커 빌드"의 탱크와 다른, 적 역할. |
| **플랭커 (Flank)** | 플레이어를 정면이 아닌 측면·후방으로 우회해 포위하는 이동 알고리즘 (v2). |
| **돌진형 / 런지 (Lunge)** | 평소엔 추격하다 일정 거리에서 **짧은 윈드업 후 미끄러지듯 전방으로 가속 돌진**해 경로상 대미지를 주는 패턴 (v2). 이동이자 공격인 cross-cutting. 회피를 유도. |
| **지그재그 (Zigzag)** | 플레이어로 다가오되 진행 방향에 좌우 사인파 오프셋을 더해 흔들며 이동하는 알고리즘. 직진보다 조준·요격이 어렵다. 어둑시니(로스터 S1, `MovementLogic.zigzagDirection`). |
| **유격 / 카이트 / 카이팅 (Kite / Kiting)** | 적이 플레이어에게 **붙지 않고 선호 사거리(`preferredRange`)를 유지**하며 압박하는 이동 알고리즘. 멀면 접근·가까우면 후퇴·그 사이 데드존(±band)이면 정지(영벡터)해 경계에서 접근↔후퇴가 뒤집히는 떨림을 막는다(히스테리시스). 어원은 연(kite) 날리기 = 줄 길이(거리) 유지. 원래는 플레이어가 근접 적을 뒷걸음치며 원거리로 패는 무빙을 뜻하지만, 우리 게임에선 **적이 플레이어를 kite**한다 — 구미호가 여우불 사거리를 유지하며 플레이어의 접근을 강제(로스터 S2a, `MovementLogic.kiteDirection`). |
| **사망 분열 (Death Split)** | 사망 시 소형 적 N마리로 쪼개지는 사망 행동. 군집을 폭증시킴 (v2). 이동이 아니라 사망 행동/변종 모디파이어로 분류. |
| **공격 타입 (Attack Type)** | 적이 "어떻게 피해를 주는가"의 분류 축. v1은 접촉(Contact)만. v2: 단발/부채꼴/확산 발사체, 돌진, 사망 폭발, 사망 분열, 소환. |
| **접촉 대미지 (Contact Damage)** | 적이 플레이어와 접촉 거리 내에 있을 때 초당 입히는 피해. v1 적의 유일한 공격 수단. |
| **텔레그래프 (Telegraph)** | 능동 공격을 하기 전에 플레이어에게 미리 알려주는 예고 신호. 윈드업 모션 / 색 깜빡임 / 바닥 마커. 서바이벌물에서 "예고 없이 맞는" 불공정을 막는 핵심 장치 (v2). |
| **윈드업 (Wind-up)** | 공격 직전 적이 멈칫하거나 자세를 잡는 준비 동작. 텔레그래프의 한 형태. |
| **변종 모디파이어 / 엘리트 (Elite Modifier)** | 같은 베이스 적에 버프 접두사(빠른/거대/분열/방어)를 붙여 적은 콘텐츠로 큰 다양성을 만드는 시스템. Diablo 접두사·뱀서 엘리트 모델 (v2). |
| **스폰 디렉터 (Spawn Director)** | 웨이브 상황에 따라 "어떤 적을 스폰할지" 결정하는 로직. 가중 스폰 테이블에서 적 종류를 무작위 추출. 마법 덱의 카드 추첨에 대응. |
| **가중 스폰 테이블 (Weighted Spawn Table)** | 웨이브 구간별로 적 종류마다 등장 가중치를 부여한 데이터. 후반 웨이브일수록 강한 적·엘리트 가중치를 높여 난이도 곡선을 만든다 (마법의 등급 게이팅과 대칭). |
| **위협 시각 언어 (Visual Language)** | 최종 아트 없이도 플레이어가 적을 구분·위협을 읽게 하는 placeholder 규칙. 색=아키타입, 크기=위협, 피격 흰 플래시, 사망 팝/페이드. 최종 스프라이트가 이 자리를 대체. |
| **피격 플래시 (Hit Flash)** | 적이 피해를 입은 순간 흰색으로 짧게 점멸하는 타격 피드백. |
| **피격 플래시 블렌드 (Hit Flash Blend)** | 피격 플래시의 진행 비율 `[0,1]`. 피격 직후 `1`(완전 흰색) → 시간이 지나며 `0`(원래색)으로 선형 감쇠. 경과시간으로 계산되며(`EnemyVisualLogic.hitFlashBlend`), 적 기본색(tint)↔흰색 보간 비율로 쓰인다. |
| **사망 팝 스케일 (Death Pop Scale)** | 사망 연출 중 크기 배율. `1` → 중간에 peak(예 1.3)로 부풀었다 → 끝에 `1`로 복귀(sin 곡선). 죽을 때 "톡 튀는" 타격감을 준다(`EnemyVisualLogic.deathScale`). 시각 크기(threatScale)와 별개로 곱해져 적용. |
| **사망 페이드 알파 (Death Fade Alpha)** | 사망 연출 중 불투명도 `[0,1]`. `1`(불투명) → `0`(투명)으로 선형 감소하며 소멸(`EnemyVisualLogic.deathAlpha`). Sprite `color.a`에 적용되며, Sprite 머티리얼이 알파 블렌드여야 보인다. |
| **보스 (Boss)** | 특정 웨이브에 등장하는 단일 강적. 고유 패턴·HP. 로드맵상 v2 또는 v1.1. |
