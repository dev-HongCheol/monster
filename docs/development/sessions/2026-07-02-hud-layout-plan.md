## 1. 배경과 목적

마법·적 콘텐츠 동결 후 완성도 축으로 전환하는 첫 UI 슬라이스다(로드맵 v0.3). 지금 HUD는 HP·웨이브·타이머·레벨·XP가 전부 **텍스트 라벨**이고, 이후 모든 UI가 공유할 **테마·해상도 토대가 없다.** 이 슬라이스는 두 가지를 한다.

1. **HUD를 게임답게** — HP·XP를 시각 바로 승격하고, 전체 HUD를 화면 모서리에 앵커한 반응형 레이아웃으로 배치한다.
2. **이후 UI가 얹힐 토대를 깐다** — 색·간격·타입스케일을 담은 `theme` 상수 모듈과, 프로젝트가 명시하지 않고 있던 디자인 해상도 + Fit 정책을 확정한다.

이 토대 덕에 다음 UI 슬라이스(일시정지·설정·도감·결과 통계)가 같은 테마·앵커 규칙 위에서 일관되게 붙는다.

## 2. 스코프

### 이번 슬라이스가 포함하는 것 (IN)

1. **디자인 해상도 + Fit 정책 확정** — 프로젝트 설정에 명시(현재 기본값). §4 참조.
2. **`theme.ts` 상수 토대** — placeholder 팔레트(색), 공통 사이즈·간격, 타입스케일. 이후 `/design-consultation`이 값만 교체.
3. **순수 로직 `HudFormatLogic.ts`** — 타이머 `mm:ss` 포맷·바 비율(0~1 클램프·0 나눗셈 가드). 현재 `HudController`에 인라인인 포맷을 순수 함수로 추출(ADR 002 scripts/logic 분리) + TDD.
4. **HP 바 + XP 바 승격** — 텍스트 → 시각 바. `HudController`가 `barRatio(cur,max)`로 바를 갱신한다. 목업 배치대로 HP 바는 좌하단, 레벨+XP 바는 하단 풀폭에 둔다.
5. **HUD 전체 레이아웃 (목업 청사진 기준)** — `docs/decisions/hud-layout.html`/`.png`의 전체 배치를 **Widget 앵커**로 구성한다. 목업은 최종 레이아웃 청사진이고(사용자 확인: "전체적인 레이아웃, 지금 다 구현하는 게 아님"), 이번 슬라이스는 그 위에 아래 §3.4의 실제 요소와 placeholder를 얹는다. 목업에 없던 **웨이브·타이머는 좌상단에 텍스트로 추가**한다(사용자 지시). 타이머는 지금처럼 `mm:ss` 카운트다운을 유지한다.
6. **레이아웃 placeholder 배치** — 미니맵(좌상, 정적 빈 사각형)·보스 체력바(상단 중앙, 기본 비활성)·메뉴 버튼(우상, ≡, 배선 없음)·스킬 그리드 6칸(우하, 보유 마법 표시용 빈 슬롯)을 배치한다. 데이터·기능 배선 없이 레이아웃 앵커 지점만 잡는다.

### 이 슬라이스가 닫는/전진시키는 백로그 항목

- **테마 J4(UI 완성도)** — 부분 전진(HUD 바·레이아웃·테마 토대). 설정·도감·결과 통계 등 J4 잔여는 후속 슬라이스.
- 신규 토대(디자인 해상도·Fit·`theme.ts`)는 백로그 항목이 아니라 이 슬라이스가 처음 세우는 UI 공통 기반이다.

### 명시적으로 범위 밖 (OUT → 다음 슬라이스)

목업 청사진에는 있으나 이번 슬라이스에서 **배선하지 않는** 요소부터 정리한다. 목업이 최종 레이아웃 청사진이므로 자리는 잡되(placeholder), 실제 데이터·기능은 후속으로 미룬다.

- **미니맵 실제 기능** — 월드→미니맵 투영·적/플레이어 도트. UI 기획에서 단일 아레나라 저우선 + v2/이월로 확정된 항목이다. 이번엔 좌상단에 정적 빈 사각형만 둔다.
- **보스 체력바 데이터 배선** — v1엔 보스가 없고(`ui-completeness-plan.md §3.B`) 보스 HP 바도 v2/범위 밖으로 확정된 항목이다. 이번엔 상단 중앙에 기본 비활성(no boss = 안 보임) placeholder 노드만 두어 v2 앵커 지점만 남긴다.
- **스킬 그리드 쿨다운 라디얼** — 최종 목표는 습득한 마법이 스킬 슬롯을 채우고, 발사 후 쿨다운 동안 회색으로 덮였다가 시계 방향 라디얼로 회색이 줄어드는 표현이다(사용자 확정 비전). 여기엔 마법별 쿨다운 데이터 배선 + 라디얼 채움 로직이 필요해 이번 슬라이스에선 빈 슬롯 placeholder까지만 하고 라디얼은 후속 슬라이스로 뗀다.
- **메뉴 버튼 → 일시정지 배선** — 일시정지 메뉴는 별도 슬라이스(P0). 이번엔 ≡ 버튼을 배선 없이 자리만 잡는다.
- **분할 XP 바 룩** — 목업은 XP 바가 5칸으로 나뉘어 있으나 `ProgressBar` 한 컴포넌트로는 분할이 안 된다(다중 스프라이트 필요). 이번엔 단일 바로 두고 분할 여부·색은 `/design-consultation`의 비주얼 시스템에서 정한다.

그 밖에 원래부터 범위 밖인 항목:

- **다른 화면** — 일시정지·설정·도감·메인 메뉴 확장·결과 화면 통계. 테마·앵커 토대는 재사용하되 화면 자체는 별도.
- **게임오버 사경로 정리** — `ui-flow-draft.md §4`에서 확정했으나(사용자 결정), 이번 슬라이스에 **넣지 않는다**(사용자 지시). 별도 처리.
- **마법 아이콘 최종 아트** — placeholder 단색 사각형만. 최종 아이콘은 아트 단계(7-9주).
- **세이브 의존 요소** — 없음(HUD는 세이브 무관).
- **수치 밸런스** — 바 색·크기·위치는 placeholder, 최종 룩은 `/design-consultation`.

## 3. 접근

### 3.1 디자인 해상도 + Fit 정책 (프로젝트 설정)

현재 `project.json`이 기본값이라 디자인 해상도가 명시돼 있지 않다(엔진 기본값 사용). 이를 명시적으로 설정한다. 세 씬 Canvas는 이미 `alignCanvasWithScreen: true`라 실제 창에 맞춰 스케일된다 — 그래서 HUD는 절대 좌표가 아니라 Widget 앵커로 배치한다(§3.4). 값은 §4에서 확정.

### 3.2 `theme.ts` 상수 토대 (`game/assets/scripts/ui/theme.ts`)

이후 모든 UI가 참조할 단일 출처. CSS 변수·디자인 토큰에 대응한다.

- **색:** `HP_FILL`(빨강)·`XP_FILL`(파랑)·`BAR_BG`(어두운 배경)·`PANEL_BG`·`TEXT_PRIMARY` 등 `cc.Color` 상수(placeholder 값).
- **사이즈·간격:** HUD 바 높이·여백·아이콘 크기 등 공통 수치.
- **타입스케일:** 라벨 폰트 크기 단계.

`cc.Color`를 쓰므로 순수 로직이 아니라 UI 상수 모듈이다(테스트 대상 아님). design-consultation이 나중에 값만 바꾼다.

### 3.3 순수 로직 `HudFormatLogic.ts` (`game/assets/scripts/logic/`)

Cocos 비의존 순수 함수 — TDD 대상.

- `formatTimer(remainingSec): string` — 음수 클램프 후 `mm:ss`(초 2자리 패딩). 현재 `HudController._updateWaveInfo`에 인라인인 로직을 이관.
- `barRatio(cur, max): number` — `max ≤ 0`이면 0, 아니면 `cur/max`를 0~1로 클램프. HP·XP 바 공용.

`HudController`는 이 함수들을 import해 얇게 쓴다.

### 3.4 `HudController` 배선 + 레이아웃

목업(`docs/decisions/hud-layout.html`/`.png`)을 청사진으로 삼되, 목업에 없던 웨이브·타이머를 좌상단에 더한 최종 배치는 다음과 같다.

```
┌─────────────────────────────────────────────────────┐
│ [미니맵]          [보스 HP 바(비활성)]            [≡] │  좌상 placeholder / 상단중앙 placeholder / 우상 placeholder
│  Wave 7                                               │  ← 목업에 없던 웨이브·타이머를 좌상에 추가
│  18:32                                                │
│                                                       │
│                  (게임 플레이 영역)                    │
│                                                       │
│                                    ┌────┬────┬────┐    │
│  HP ▓▓▓▓▓▓▓░░ 205                  │ S1 │ S2 │ S3 │    │  좌하 HP 바(실제) / 우하 스킬 그리드(placeholder)
│                                    ├────┼────┼────┤    │
│                                    │ S4 │ S5 │ S6 │    │
│  Lv.40  XP ▓▓▓▓▓▓▓▓▓░░░░░░░░░░░░░░░░░░░░░░░░░░░         │  하단 풀폭 레벨+XP 바(실제)
└─────────────────────────────────────────────────────┘
```

- **HP·XP 바 (실제 배선):** `@property(ProgressBar) hpBar` / `xpBar` 추가. `update()`에서 `bar.progress = barRatio(cur, max)`. 바 Sprite는 흰(또는 둥근) 텍스처 1장을 `theme` 색으로 틴트 — HP는 빨강, XP는 파랑(같은 텍스처 재사용). HP 바는 좌하단, 레벨+XP 바는 하단 풀폭. 바 위 숫자 라벨(HP `205`, 레벨 `Lv.40`)은 목업대로 **유지**(바 + 숫자 병기).
- **웨이브·타이머 (실제 배선, 좌상 이동):** 기존 `waveLabel`·`timerLabel`을 좌상단으로 재배치한다(미니맵 placeholder 아래). 타이머는 `formatTimer`로 교체하되 동작은 동일한 `mm:ss` 카운트다운(승리 조건).
- **레이아웃 앵커:** 각 HUD 요소 노드에 `cc.Widget`을 붙여 앵커한다 — 미니맵·웨이브·타이머는 좌상, 보스 바는 상단 중앙, 메뉴 버튼은 우상, HP 바는 좌하, 스킬 그리드는 우하, 레벨+XP는 하단 좌우 앵커 풀폭. 실제 노드 배치·앵커·오프셋은 QA 문서 레시피로 명시하고 사용자가 7단계 에디터에서 만든다.
- **placeholder 4종 (자리만, 배선 없음):**
  - **미니맵** — 좌상 정적 빈 사각형(테두리 + "MINIMAP" 라벨). 기능 없음.
  - **보스 체력바** — 상단 중앙, `active = false` 기본. v1엔 보스가 없어 인게임에선 보이지 않으며, v2 보스 도입 시 배선할 앵커 지점만 남긴다.
  - **메뉴 버튼(≡)** — 우상 버튼 모양만. 콜백 배선 없음(일시정지는 별도 슬라이스).
  - **스킬 그리드 6칸** — 우하 3×2. 습득한 마법이 채워질 자리이나 이번엔 빈 슬롯 사각형만. 데이터 바인딩·쿨다운 라디얼은 후속(§2 OUT).

### 3.5 두-Canvas 구조

`main.scene`은 게임/UI 두 Canvas로 분리돼 있다(card-layer-fix). HUD는 **UI Canvas** 아래에 둔다. 신규 바·아이콘 노드도 UI Canvas 하위에 배치.

## 5. 테스트 전략 (TDD, RED 먼저)

순수 로직 `HudFormatLogic.ts`가 있으므로 **skip-test 아님.** `tests/logic/HudLayout.test.ts`에 RED부터.

- **`formatTimer`:** `0→"00:00"`, `65→"01:05"`, `600→"10:00"`, 음수 클램프(`-3→"00:00"`), 초 2자리 패딩(`9→"00:09"`).
- **`barRatio`:** 정상(`50,100→0.5`), 가득(`100,100→1`), 초과 클램프(`120,100→1`), `max=0→0`(0 나눗셈 가드), 음수 cur 클램프(`-5,100→0`).

바·레이아웃·테마 색은 Cocos 컴포넌트(ProgressBar/Widget/Sprite)·에디터·`cc.Color` 상수라 순수 테스트 대상이 아니다 — 7단계 수동 검증.

- **디자인 해상도 + Fit 정책** 설정 경로(Project Settings).
- **HUD 노드 레이아웃 레시피** — 각 요소의 부모(UI Canvas)·Widget 앵커·오프셋·크기. HP/XP 바 노드(배경 + FILLED/ProgressBar Fill)·틴트 색.
- **바 스프라이트** — 흰(또는 둥근) 텍스처 SpriteFrame(placeholder). 에셋이라 사용자가 준비, `.meta`는 7단계 생성.
- **에디터 연결 체크리스트** — `@property hpBar`/`xpBar` ↔ ProgressBar 노드.
- **수동 테스트** — 창 크기 변경·전체화면 시 HUD가 모서리에 유지되는지, HP/XP 바가 값에 맞게 차는지.

## 7. 리스크

- **낮음(로직):** 새 순수 로직은 포맷·비율 두 함수뿐, 테스트로 고정.
- **에디터 레이아웃(Widget 앵커)** 이 새 위험 지점이나, 값 아닌 배치라 QA 레시피 + 7단계 수동 검증으로 잡는다. 창 리사이즈 시 앵커 유지가 핵심 확인 항목.
- **디자인 해상도 변경 파급:** 씬 좌표가 새 디자인 해상도 기준으로 재계산될 수 있다(백로그 F9 카메라 churn과 유사). 설정 후 세 씬의 무관 diff를 커밋 전 확인한다.
