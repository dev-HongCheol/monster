# gbrain 색인 갱신이 조용히 건너뛰어지고 있었다

- **작성일:** 2026-08-13
- **브랜치:** `feat/canon-spec-move` (이 슬라이스의 스코프는 아니다 — 기록과 백로그 등재만 여기서 한다)
- **성격:** 운영 도구 이슈 진단. PR #76 머지 직후 9단계 색인 갱신을 실행하다 드러났다.
- **정본:** 갱신 절차의 정본은 [`gbrain-setup.md`](../gbrain-setup.md) §6.2다. 이 문서는 그 절차가 왜 실행 불가능했는지의 기록이고, 고친 절차는 정본이 든다.

---

## 1. 증상 — 19일치 이력이 색인에 없었다

PR #76을 머지한 뒤 절차대로 색인을 갱신하려는데, `sources list`가 `monster` 소스의 마지막 동기화를 **2026-07-25**로 보고했다. 그 사이 머지된 슬라이스가 여럿인데 색인은 하나도 받지 못한 상태였다.

이것이 위험한 이유는 `gbrain-setup.md` §6.2가 이미 적어 둔 대로다. 낡은 색인은 "모른다"라고 답하지 않고 **가장 비슷한 것을 그럴듯한 점수로** 돌려주므로, 지연을 모르는 사람은 조용히 틀린 답을 믿는다.

## 2. 원인 — 문서화된 명령이 실행될 수 없는 상태였다

§6.2가 지시하는 명령은 이것이다.

```bash
cd ~/gbrain
bun src/cli.ts sync --source monster --full
```

그런데 이 명령이 DB를 열지 못하고 끝난다. gbrain MCP 서버(`gbrain serve`)가 상시 실행 중이고, 브레인이 **PGLite라 단일 쓰기**여서 별도 CLI 프로세스가 같은 DB를 동시에 열 수 없기 때문이다. 서버는 Claude Code가 띄운 stdio 자식 프로세스라 세션 내내 살아 있다. 즉 **AI가 절차를 따르려 할 때는 항상 잠겨 있다.**

§6.2에는 서버를 내리라는 말이 없다. 절차를 그대로 따르면 실패하고, 실패해도 아무것도 막지 않으므로 그냥 넘어간다 — 그래서 갱신이 19일 동안 건너뛰어진 것이 아무에게도 보이지 않았다.

## 3. MCP 우회가 만든 두 번째 문제

CLI가 막히자 MCP 도구(`sync_brain`)로 우회했다. 문서 색인 자체는 들어갔지만 두 가지가 어긋났다.

**소스를 지정할 수 없다.** `sync_brain`은 `repo` 경로만 받고 `--source`에 해당하는 인자가 없다. 그래서 새 문서 31개가 `monster`가 아니라 `default` 소스로 들어갔다. `default`는 `local_path`가 없어 다시는 동기화되지 않으므로, 그대로 두면 **영구히 낡은 사본**이 검색에 섞인다. 이후 `monster`를 제대로 동기화하자 같은 슬러그가 두 벌이 됐다.

**코드 전략을 돌릴 수 없다.** §6.2는 문서와 코드 두 줄을 요구하는데(`--strategy code`), MCP 도구에는 그 인자가 없다. 코드 색인은 손댈 방법이 아예 없었다.

## 4. 이번에 한 복구

1. `gbrain serve`(PID 13796)를 중단해 PGLite 잠금을 풀었다.
2. `sync --source monster --full`과 `sync --source monster --strategy code --full`을 돌렸다. 문서 37페이지·844청크, 코드 8페이지·55청크가 들어갔고 체크포인트는 머지 커밋 `4f93474`다. 결과는 337페이지·lag 0s·embed 100%다.
3. `default`에 남은 31페이지를 지웠다. **`sources archive default`도 `sources remove default`도 쓸 수 없다** — gbrain이 id가 `default`인 소스를 코드로 보호한다(`src/commands/sources.ts:497`·`:375`). 페이지 키가 `(slug, source_id)`라서 `delete <slug> --source default`로 한 건씩 지웠고, `monster` 사본이 그대로인지 첫 건에서 확인한 뒤 나머지를 돌렸다. 소프트 삭제라 72시간은 복구 가능하다.

## 5. 남은 처방 — F77

절차 문서가 실행 가능해져야 한다. 최소한 §6.2에 **serve를 내리고 다시 붙이는 단계**가 들어가야 하고, stdio 서버는 CLI에서 되살릴 수 없으므로 "`/mcp`로 재연결한다"까지 적어야 한다. MCP 경로를 계속 쓸 생각이라면 소스 지정과 코드 전략을 지원하는지부터 확인해야 하는데, 지금 버전에는 둘 다 없다.

**자동화(`/sync-gbrain` 스킬 도입)는 이 문제를 푸는 답이 아니다.** 같은 잠금을 그대로 만나기 때문이다. §8이 그 스킬을 보류 항목으로 들고 있는데, 도입하더라도 잠금 처리를 먼저 정해야 한다.
