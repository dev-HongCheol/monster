### 2-1. 절 제목은 흔들리지만 접두어로는 잡힌다

F93은 "자동 검증 절의 `[ ]`만 센다"가 되어야 한다. 수동 체크리스트의 `[ ]`는 사용자가 7단계에 채우므로 비어 있는 게 정상이다. 그래서 절을 어떻게 가를지가 설계 핵심이다.

| 판정 방식 | 잡히는 문서 |
|---|---|
| 완전 일치 `## N. 자동 테스트로 검증` | **3 / 55** |
| 접두 `^## \d+\. 자동` | **30 / 55** |
| 접두 `^## (\d+\. )?자동` (번호 없는 판 포함) | **46 / 55** |
| `## N. 자동 검증` (직전 슬라이스 표기) | 2 / 55 |

**완전 일치로는 못 가르고 접두어로는 갈린다.** 새 제목 문자열을 만들어 고정하는 설계는 폐기한다 — 어떤 문자열을 골라도 기존 문서 대부분과 안 맞고, 특히 `## N. 자동 검증`은 2개뿐이라 그 길로 가면 **가장 최근 문서부터** 검사에서 빠진다.

### 2-2. 새로 만든 문서는 커밋 전까지 어떤 검사에도 안 걸린다

이 계획 문서를 처음 썼을 때 존재하지 않는 파일 둘을 링크로 걸었는데도 `wf check-links`가 초록이었다. `tests/helpers/DocFs.ts:32`가 `git ls-files`로 **추적 파일만** 훑기 때문이다. 이번에 만드는 검사도 같은 성질을 물려받는다. 실무상 문제는 안 된다 — 6단계는 `pass review` 전에 커밋을 요구한다. 다만 **"방금 쓴 문서가 초록이다"를 통과로 읽으면 안 된다**는 것을 QA 문서에 적어 둔다.

## 3. 무엇을 넣나 — 네 조각

### 3-1. `.git-blame-ignore-revs` (eol-policy 계획 §8 이월분)

`feat/eol-policy`가 PR을 따로 낸 **유일한 이유**가 이 파일이었다. 재정규화 squash SHA를 무시 목록에 넣어 1,777줄의 `git blame`을 살린다. 적을 SHA는 머지 커밋 **`9ee8519`** 하나다.

**전제를 실측으로 확인했다.** 그 커밋은 재정규화 단독이 아니라 16개 파일을 담았으므로(wf 절차가 계획·QA 문서를 같은 브랜치에 요구한다), "무시하면 신규 파일 blame까지 망가지는가"를 임시 저장소에서 재현했다.

```
c1: a.txt 생성 → c2: a.txt 재정규화 + b.txt 신규 (c2를 무시 목록에)

a.txt  ^df148ce ... OLD LINE        ← 이전 커밋(c1)으로 되돌아간다
b.txt  7f399958 ... brand new file  ← 무시된 c2 자신이 그대로 남는다
```

**이전 판본이 없는 줄은 무시 대상 커밋에 그대로 귀속된다.** 부작용이 실재하지 않으므로 SHA를 그대로 적는다. 감수하는 것 하나 — 그 커밋에 섞인 실제 수정 줄(`workflow-state.json`·`backlog-implement.md` 몇 줄)의 blame은 엉뚱한 이전 커밋으로 밀린다. 대상이 상태 파일과 백로그 한두 줄이라 감수한다.

**파일만으로는 절반이다.** GitHub는 자동으로 읽지만 로컬 `git blame`은 `blame.ignoreRevsFile` 설정이 있어야 본다. 커밋되지 않는 설정이므로 새 장비에서 되살릴 자리가 필요하고, 그 자리는 [`spec/ops-environment.md`](../spec/ops-environment.md) §5(프로젝트 설정 파일)다.

```bash
git config blame.ignoreRevsFile .git-blame-ignore-revs
```

**나머지 셋과 결합이 0이다.** 게이트 설계가 흔들리면 이것만 먼저 착지시킬 수 있다.

### 3-2. F92 — `check-qa`가 코드 스팬 안팎을 가른다

코드 **스팬**을 지우는 것은 `blankFences`(`LinkCheck.ts:81`, export됨)가 아니라 `blankInlineCode`(`:105`)이고 **그 함수는 export되어 있지 않다.** F92의 거짓 실패는 스팬 형태였으므로 `blankFences`만 가져다 쓰면 아무것도 안 고쳐진다.

`extractLinks`(`:151`)가 이미 `blankInlineCode(blankFences(normalizeEol(md)))` 조합을 쓴다. 그 조합을 `scrubCode()` 하나로 뽑아 export하고 양쪽이 부른다 — 중복도 함께 준다.

**배관이 `check-links`와 다르다.** `check-links`(`workflow.mjs:822`)는 vitest를 띄우기만 하면 되지만 `check-qa`는 단독 커맨드(`:801`)이면서 `pass()`의 게이트(`:598`)로도 돌고, `qaDocPath(state)`로 **현재 슬라이스 문서 하나**를 지목한다. vitest는 상태 파일을 모르므로 그대로 옮기면 테스트가 장비 상태에 의존한다. 성격으로 가른다.

```
tests/helpers/QaDoc.ts   (순수 — 마크다운 문자열 in, 위반 out)
   ├── tests/logic/DocsHygiene.test.ts : 레포 전체 스윕 + fixture 단위 테스트
   └── .claude/workflow.mjs  check-qa  : vitest를 띄운다 (check-links와 같은 형태)
                                        + 현재 슬라이스 문서 판정은 CLI에 남긴다
```

`.mjs`가 `.ts`를 import할 수는 없다(`tsconfig.tests.json`에 `allowJs`가 없어 `pass ts`가 TS7016으로 막힌다 — `F78`이 실측으로 접었다). CLI에 남는 것은 로직 사본이 아니라 **상태에서 경로를 얻는 한 줄**이다.

### 3-3. F93 — 6단계 절차 1번을 게이트로 만든다

`pass review` 앞에 검사를 건다. 자동 검증 절에 `[ ]`가 남아 있거나 통과 근거 줄이 없으면 막는다. 설계는 다섯 조각이다.

**① 절 판정은 접두어로 한다.** `^## (\d+\. )?자동`, 괄호 접미사 허용. §2-1대로 46/55를 즉시 덮는다.

**② 조용한 건너뛰기를 두 갈래로 가른다.** "제목 없으면 건너뛴다"만 두면 제목을 안 쓰는 것으로 게이트가 침묵한다 — 이 슬라이스가 죽이려는 형태 그대로다.

| 어디 | 무엇을 묻나 | 없으면 |
|---|---|---|
| CLI(`check-qa`) | **현재 슬라이스** 문서에 절이 있는가 · 그 안에 `[ ]`가 0개인가 · 근거 줄이 있는가 | **막는다** |
| vitest(레포 전체) | 절을 가진 46개 문서의 절 안에 `[ ]`가 0개인가 | 절이 없는 9개는 건너뛴다 |

**무엇을 어디서 묻는지는 실측이 정했다.** §2대로 절 안의 미체크는 이미 **0건**이라 레포 전체에 걸어도 오늘부터 초록이고, 되돌아가면 빨개진다 — 불변식으로 딱 맞는 모양이다. 반면 근거 줄은 **15개 문서에 없다.** 그것을 레포 전체에 걸면 과거 문서를 소급해 고쳐야 하는데 [`spec/docs-references.md`](../spec/docs-references.md) §9(과거 기록 불수정)에 정면으로 걸린다. 그래서 근거 줄은 **현재 슬라이스 문서에만** 요구한다. 레거시 예외 목록이 필요 없는 배치이기도 하다 — 얼려 둘 목록이 아예 안 생긴다.

두 판정은 묻는 것이 달라 두 벌이 아니다. [`spec/docs-references.md`](../spec/docs-references.md) §13(신규부터)과 §9(과거 기록 불수정)를 둘 다 지키면서 구멍을 닫는 배치다.

**③ 통과 근거에 PR 번호를 요구하지 않는다.** verification 시점에는 PR이 아직 없다 — Draft PR은 다음 phase(`user-verification` §2)에서 만든다. 게이트가 요구하는 것은 **날짜 + 피처 N/N + 전체 M/M**까지다. PR 번호는 규약으로 두고 `approve-pr` 시점에 채운다.

**④ 탈출구를 둔다.** `wf skip-test` 슬라이스나 자동 검사가 실제로 0건인 문서를 위해 근거 줄에 `스킵 — <사유>`를 허용한다. 절 자체는 **항상** 요구한다. §7의 `정본: 없음 — <사유>`와 같은 모양이다.

**⑤ rework 2회차를 막는다.** 근거 줄이 「있는가」만 보면 1회차 근거로 2회차를 통과한다. 낡은 N/N이 남는 것은 없느니만 못하다 — 있으니까 아무도 안 본다. `resetVerification`이 `canon_updated`를 비우는 자리에서 자동 검증 절의 해시를 함께 스냅샷하고, 게이트는 **현재 해시가 스냅샷과 달라야** 통과시킨다.

### 3-4. `wf start` 기준점 가드 (계획 중 발견)

`.claude/workflow.mjs:406`의 `ensureFeatureBranch`가 낡게 시작하는 길을 둘 열어 두고 있다.

```js
const exists = git(["rev-parse","--verify","--quiet",`refs/heads/${branch}`]).status === 0;
const r = exists ? git(["switch", branch])             // 기준점을 안 본다
                 : git(["switch","-c",branch,"main"]); // 로컬 main. fetch 안 한다
```

- **브랜치가 이미 있으면** 그 자리가 어디든 그냥 체크아웃한다. 오늘 이 경로로 샜다.
- **없으면** 로컬 `main`에서 자르는데, 그것이 origin보다 뒤처졌는지 안 본다. 이 사고는 이미 두 번 났다 — `backlog.md` 머리말이 2026-07-17 정리에서 F47·F48 ID 충돌로 기록해 뒀다.

지뢰가 많다. **로컬 브랜치 47개가 전부 origin/main보다 뒤에 있다**(최대 92커밋). 다음 슬라이스 이름이 그중 하나와 겹치면 조용히 재현된다.

처방은 `ensureFeatureBranch` 안에서 `git fetch origin`을 돌리고 **기준점이 `origin/main`을 담고 있는지** 확인해, 아니면 막고 무엇을 하라고 말하는 것이다(`git merge --ff-only origin/main` 또는 다른 이름). 자동으로 rebase하지 않는다 — 브랜치에 남의 커밋이 있을 수 있고, 그 판단은 사람 몫이다.

- `wf start`가 낡은 기준점에서 막히는가(§3-4). 같은 샌드박스에서 브랜치를 하나 뒤처지게 만들어 재현한다.

스윕은 `DocFs.loadDocs(tracked)`가 이미 읽어 온 마크다운을 걸러 쓴다. `readdirSync`로 QA 폴더를 다시 훑지 않는다 — 그 헬퍼가 있는 이유가 그것이다.

## 5. 구현 순서

```
1. .git-blame-ignore-revs + ops-environment.md §5     ← 결합 0. 먼저 착지시킨다

```

2→3이 유일한 실제 의존이다.

## 6. 하지 않는 것

- **F76(QA 머리말 `이전 문서:` 필드)을 담지 않는다.** 이 슬라이스에서 유일하게 산문 예산을 먹는 조각이고(약 300자), 게이트 장치도 따로 필요하다 — `CanonRef.isEnforced`가 쓰는 파일명 날짜 경계가 QA 문서에는 없어서(`<feature>-test.md`) 기존 55개를 `LEGACY_QA_DOCS` 상수로 얼려야 한다. 게이트 셋과 성격이 달라 함께 담으면 슬라이스가 두 겹이 된다. 백로그에 열린 채로 둔다.
- **F80·F88·F89 소급분을 건드리지 않는다.** 전부 「신규부터」로 이미 끊어 둔 것들이라 손대면 이번 경계와 충돌한다.
- **과거 QA 문서 51개를 소급해서 고치지 않는다.** §3-3 ②의 vitest 쪽 건너뛰기가 그 결정의 구현이다.
- **F78(`insertCanonRow` 두 벌)을 닫지 않는다.** 같은 배관을 쓰지만 열면 `canon` 커맨드 경로 전체를 다시 검증해야 한다.
