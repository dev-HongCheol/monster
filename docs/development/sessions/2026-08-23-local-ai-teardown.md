- **정본:** 없음 — 명세를 안 바꾼다. 디스크에서 환경을 걷어낼 뿐이고, 복구 절차 정본인 [`comfyui-setup.md`](../comfyui-setup.md)·[`kohya-setup.md`](../kohya-setup.md)는 **그대로 남긴다**(§3·§6). 배경 제거가 fal로 옮겨 간 사실은 앞 슬라이스가 이미 정본에 반영했다

## 1. 왜 이 문서가 따로 필요한가

지울 목록의 실체는 `docs/temp/2026-08-06-local-ai-cleanup-inventory.md`에 있는데, **그 폴더가 `.gitignore` 대상이라 이 장비 밖에서는 존재하지 않는다.** 그래서 절차 정본만 읽고는 무엇을 지울지 알 수 없다 — "문서가 근거로 인용하는 생성 PNG"라는 식별 기준만으로는 124장 중 어느 것인지 정해지지 않는다.

**되돌릴 수 없는 작업인데 목록이 한 장비에만 있는 상태**가 위험하다. 그 장비가 죽으면 무엇을 지웠는지도, 무엇을 남겼어야 했는지도 알 수 없다. 그래서 폴더 단위 목록과 확인 절차만 여기로 옮긴다. 실측 명령과 세부 파일 목록은 원본에 남긴다.

## 2. 2026-08-06 조사 이후 바뀐 것

**가장 큰 선행 조건이 사라졌다.** 그 조사는 삭제를 막는 함정으로 「후처리 도구가 ComfyUI venv 안에 산다」를 들었다.

> **후처리(실행 지침 §8)가 아직 안 끝났다.** 지금 ComfyUI venv를 지우면 알파 임계값을 걸 도구도, 트림 상자를 잴 도구도 없어진다.
> — 2026-08-06 정리 목록 §6

그래서 지우기 전에 `rembg` 별도 venv(A안, 300MB)나 Pillow·numpy venv(B안, 50MB) 중 하나를 세우라고 돼 있었다. **2026-08-22에 둘 다 필요 없어졌다** — 후처리가 통째로 레포 안 TypeScript로 들어왔기 때문이다(PR #89).

| 종전에 필요했던 것 | 어디로 갔나 |
|---|---|
| `rembg` (배경 제거) | fal 매팅 `bria/background/remove` — `tools/art/FalMatting.ts` |
| Pillow·numpy (알파·트림·발 밑선 실측) | `pngjs` + `tests/helpers/SpriteMetrics.ts` |

**파이썬 의존이 0이 됐다.** 따라서 A안·B안 선택 자체가 없어지고, 정리 목록 §9의 1번(「후처리 환경을 먼저 확보한다」)은 이미 충족된 상태로 시작한다.

**`u2net.onnx` 168MB가 남길 것에서 지울 것으로 바뀌었다.** 정리 목록 §7이 「§6에서 A안을 고를 때만 남긴다」는 조건부로 적어 뒀는데, A안을 안 고르므로 조건이 성립하지 않는다.

**대피 목적지도 바뀐다.** 정리 목록 §5는 `F:\ai\archive\`를 쓰라고 했으나 그건 **지울 폴더 안쪽**이다. 그대로 하면 방금 대피시킨 것을 함께 지운다. 목적지를 `F:\ai` **바깥**으로 잡는다.

레포에 텍스트 재현 기록이 커밋돼 있어야 바이너리를 지울 수 있다. 2026-08-23에 직접 확인했다.

## 4. 대피 — 먼저 한다

목적지는 `F:\ai-archive\`다. **복사가 아니라 이동**이어야 원본이 지울 폴더 안에 안 남는다.

- [ ] `ComfyUI\output\` 12개 폴더 (139MB / 124장) — 문서가 근거로 인용하는 이미지다. `F60_mage_4dir_v3`(4방향 실패 실측) · `F60_mage_bridge`(알파 잔여 4.3% 사례) · `F58_wizard_final`(화풍 확정 컷)이 여기 있다
- [ ] `train\f58_anime\img\10_f58anime\` (40파일 / 20.5MB) — 확정 씨앗과 캡션. **재학습을 하게 되면 유일하게 허용된 씨앗이다** (유료 출력은 라이선스가 학습 씨앗 사용을 막는다)
- [ ] `f58_anime_style.safetensors` 최종본 1개 (81.5MB) — 폴백 보험. 중간 에폭 9개는 안 남긴다
- [ ] `F:\ai\*.py` 15개 (수십 KB) — 생성 드라이버·후처리 스크립트

합계 약 0.16GB. **대피가 끝나면 눈으로 확인하고 다음으로 넘어간다.**

## 6. 지우면 안 되는 것

아트와 무관한데 함께 지우기 쉬운 것들이다.

- **Ollama + 임베딩 모델 2개** (1.08GB) — gbrain 의미 검색용이다. `snowflake-arctic-embed2`와 `snowflake-arctic-embed-l-v2`는 같은 ID의 별칭이라 디스크에는 한 벌뿐이고, 별칭을 지우면 색인이 「그런 모델 없다」로 실패한다
- **Python 3.12.10** — 아트 때문에 깐 것이 아니다
- **`comfyui-setup.md` · `kohya-setup.md`** — §3이 든 이유로 남긴다
- NVIDIA 드라이버 · Visual Studio 2022 · Git · GitHub CLI — 아트 이전부터 있던 것들

### 지운 것

`ComfyUI`(12.75GB) · `sd-scripts`(5.05GB) · `cache`(3.07GB) · `train`(0.50GB) · 루트 로그 4개 · `%USERPROFILE%\.u2net\u2net.onnx`(167.8MB). `.u2net`은 비어서 폴더째 지웠다.

### 빈 `F:\ai`는 남았다

도구의 안전 가드가 드라이브 바로 아래 경로 삭제를 막는다(`Remove-Item on system path 'F:\ai' is blocked`). **하위가 0개인 빈 폴더라 기능적으로는 철거가 끝난 상태**이고, 지우려면 사람이 탐색기나 셸에서 직접 하면 된다.

이 가드 때문에 한 번 중단된 자리가 있다. `ComfyUI` 삭제와 `F:\ai` 삭제를 한 스크립트에 묶었더니 **뒤엣것이 막히면서 앞엣것도 안 돌았다.** 하위 항목을 하나씩 지목해 지우라는 §5의 지시가 이 상황에서 실제로 값을 했다 — 통째로 지우는 명령이었으면 가드에 막혀 아무것도 못 지웠거나, 가드가 없었다면 대피본까지 함께 날아갔다.
