## 1. 스코프

레벨업 카드 선택 패널 위로 적과 플레이어가 겹쳐 보이는 렌더 순서 문제를 고친다. 원인을 정공법으로 끊기 위해, 게임 월드와 UI를 **레이어로 분리하고 각자 전용 카메라로 렌더**해서, 노드 계층 순서나 런타임 `addChild` 시점과 무관하게 UI가 언제나 게임 월드 위에 그려지도록 만든다. 같은 `CardSelectPanel`과 씬 UI를 건드리는 김에, 카드 설명 라벨이 양끝부터 잘려 다른 카드로 오인되는 표시 버그(F8)도 함께 닫는다.

포함하는 것:

1. **게임 월드 / UI 레이어 정리** — 게임 월드 객체는 모두 `DEFAULT` 레이어, UI 객체는 모두 `UI_2D` 레이어로 통일한다(현재 양쪽이 뒤섞여 있다 — §3 감사 표).
2. **UI 전용 카메라 추가** — 기존 카메라는 `DEFAULT`만 렌더하게 좁히고, 새 UI 카메라가 `UI_2D`만 더 높은 우선순위로 위에 렌더한다.
3. **카드 라벨 잘림(F8) 수정** — 카드 설명 라벨의 넘침 처리를 바꿔 텍스트가 양끝부터 잘리지 않게 한다.

미루는 것 (이번 스코프 밖):

- **동시 적 수 상한 제거·대량 적 성능(G1)** — 무관. 적이 Canvas에 런타임으로 붙는 구조 자체는 이 슬라이스의 레이어 분리로 렌더 문제만 해소하고, 스폰 부모 구조는 건드리지 않는다.
- **마법 효과 레이어(A 테마)** — 무관.
- **씬 카메라 크로스머신 churn(F9)** — 카메라를 건드리므로 인접하지만, 별개 이슈다. 이번에 카메라 노드를 추가하면 직렬화 diff가 한 번 더 생기니 §6에서 커밋 위생만 언급한다.

## 2. 현재 동작 (출발점)

- 씬 `main.scene`은 **단일 `Canvas` + 단일 `Camera`** 구조다. 게임 월드(Player·BulletParent·적·발사체)와 UI(HUD·GameOverPanel·CardSelectPanel)가 **전부 이 한 Canvas의 자식**으로 들어가 있다.
- 그 단일 카메라의 `visibility`는 `DEFAULT | UI_2D | IGNORE_RAYCAST`(값 1108344832)라, 게임 월드와 UI를 **한 카메라가 한꺼번에** 렌더한다. 그래서 둘 사이의 앞뒤 순서는 오직 **Canvas 자식 배열 순서(계층 깊이)** 로만 정해진다.
- 적은 `EnemySpawner.onLoad`에서 스폰 부모를 `playerNode.parent`(= Canvas)로 잡아, 풀에서 꺼낼 때마다 **런타임에 Canvas의 자식으로 `addChild`** 된다. `addChild`된 노드는 항상 자식 배열 맨 뒤로 붙고, 2D에서 맨 뒤 = 가장 위에 그려진다. 따라서 **에디터에서 카드 패널을 마지막 자식으로 옮겨 두어도** 스폰된 적이 다시 그 뒤에 붙어 위로 올라온다.
- 레이어 코드는 없다. `game/assets/scripts` 어디에서도 `layer`·`Camera`·`visibility`를 건드리지 않는다(전수 검색 0건). 즉 레이어 배정은 전부 씬·프리팹에 직렬화돼 있고, 수정은 에디터/씬/프리팹 작업이다.

## 3. 근본 원인 — 레이어 배정이 뒤섞여 있다

레이어 값: `DEFAULT = 1073741824`, `UI_2D = 33554432`.

| 대상 | 현재 레이어 | 정상값 | 상태 |
|---|---|---|---|
| Player (씬) | DEFAULT | DEFAULT | ✅ |
| BulletParent (씬) | DEFAULT | DEFAULT | ✅ |
| Canvas (씬) | UI_2D | UI_2D | ✅ |
| HUD + 자식 전부 (씬) | UI_2D | UI_2D | ✅ |
| GameOverPanel + 자식 전부 (씬) | UI_2D | UI_2D | ✅ |
| **CardSelectPanel + 자식 전부** (씬) | **DEFAULT** | UI_2D | ❌ |
| **Enemy.prefab** 루트 | **UI_2D** | DEFAULT | ❌ |
| **Bullet.prefab** 루트 | **UI_2D** | DEFAULT | ❌ |
| **XPItem.prefab** 루트 | **UI_2D** | DEFAULT | ❌ |
| **ExplosionVfx.prefab** 루트 | **UI_2D** | DEFAULT | ❌ |

게임 월드 객체 4종(적·발사체·경험치·폭발 VFX)이 UI 레이어에 올라가 있고, UI 패널 하나(CardSelectPanel)가 게임 레이어에 내려가 있다. 지금은 카메라가 두 레이어를 한꺼번에 보니 이 뒤섞임이 드러나지 않다가, 계층 순서로만 정렬되는 상황에서 런타임에 붙는 적이 카드 패널(DEFAULT) 위로 올라오면서 문제가 보였다. (HUD·GameOverPanel은 UI_2D라 같은 증상이 덜 보였지만, 같은 단일 카메라 구조에선 안전이 보장되지 않는다.)

## 4. 접근 — 레이어로 분리하고 카메라 둘로 렌더

### 4-1. 레이어 정리

§3 표의 ❌ 항목을 모두 정상값으로 바꾼다.

- 게임 월드 프리팹 4종(`Enemy`·`Bullet`·`XPItem`·`ExplosionVfx`)의 **루트 노드 레이어를 `DEFAULT`** 로. 프리팹 인스턴스는 루트 레이어를 물려받으므로, 런타임에 풀에서 꺼내는 적·발사체도 자동으로 `DEFAULT`가 된다(코드 불필요).
- `CardSelectPanel`과 **그 모든 자식**(CardButton_0/1/2, CardNameLabel_*, CardDescLabel_*)의 **레이어를 `UI_2D`** 로.

### 4-2. 카메라 둘로 분리

- **게임 카메라**(기존 `Camera`): `visibility`를 **`DEFAULT`만**(1073741824)으로 좁힌다. `clearFlags`는 `SOLID_COLOR` 유지(맨 아래 카메라가 화면을 지운다), `priority`는 0 유지.
- **UI 카메라**(신규): `visibility`를 **`UI_2D`만**(33554432)으로, `clearFlags`는 **`DEPTH_ONLY`**(게임 카메라가 그린 화면을 지우지 않고 그 위에 UI만 덧그린다), `priority`는 **게임 카메라보다 높게**(예: 1). Cocos는 priority가 낮은 카메라부터 그리므로, priority가 높은 UI 카메라가 나중에 = 게임 월드 위에 그려진다. 투영·`orthoHeight`는 게임 카메라와 동일하게 맞춘다(같은 화면 정렬).

이렇게 하면 게임 월드는 게임 카메라가, UI는 UI 카메라가 더 위에서 그리므로, **계층 순서나 런타임 `addChild`와 무관하게 UI가 항상 위**가 된다.

> **주의(중복 렌더 방지):** 두 카메라의 `visibility`가 겹치지 않아야 한다. 한 노드의 레이어가 두 카메라 마스크에 모두 걸리면 두 번 그려진다(공식 문서 경고). 그래서 §4-1의 레이어 정리가 §4-2의 전제다 — 먼저 레이어를 깨끗이 나눈 뒤 카메라 마스크를 좁힌다.

### 4-3. F8 — 카드 설명 라벨 잘림

`CardDescLabel_0/1/2`가 너비 150·`overflow=CLAMP`·`wrapText=false`라 긴 설명이 **양끝부터** 잘려(`"파이어볼 발사체 수 +1레벨"` → `"이어볼 발사체 수 +1레"`) 다른 카드로 오인된다. 라벨 넘침 처리를 바꿔 해결한다. 후보 중 택일(7단계에서 확정):

- **`overflow=SHRINK`** — 글자 크기를 줄여 한 줄에 맞춘다. 카드 크기 불변, 가장 단순. (권장)
- **`overflow=RESIZE_HEIGHT` + `wrapText=true`** — 줄바꿈해 높이를 늘린다. 설명이 길면 카드 레이아웃이 흔들릴 수 있다.
- 라벨·카드 너비 확대 — 레이아웃 조정 폭이 크다.

순수 표시 속성 변경이라 발사체 로직·카드 드로우에는 영향이 없다.

## 5. 리스크와 폴백

**주 리스크 — 단일 Canvas 밑 2-카메라 토폴로지.** 이 프로젝트는 게임 월드와 UI가 한 Canvas에 섞여 있는 비정형 구조다. Cocos 공식 문서는 다중 카메라 UI를 보통 **Canvas를 여러 개** 두어 구성하라고 안내한다. 단일 Canvas에서 레이어∩visibility 기준으로 두 카메라가 각자 제 레이어만 렌더하는 방식은 2D에서 동작할 것으로 보이지만(렌더 대상은 Canvas 소속이 아니라 노드 레이어로 갈린다), **확정 검증은 7단계 인게임 테스트**에서 한다.

- **확인 포인트(7단계 체크리스트):** ① 게임 월드가 정상으로 보이는가(적·발사체·경험치·폭발 VFX 누락/이중 렌더 없음), ② 레벨업 때 카드 패널이 적·플레이어 위에 온전히 보이는가, ③ **카드 버튼 클릭이 정상 동작하는가**(레이어 이동 후 입력 히트테스트 확인), ④ HUD·GameOverPanel도 항상 위인가.
- **폴백(주 접근이 인게임에서 깨질 때):** UI 노드(HUD·GameOverPanel·CardSelectPanel)를 **별도 UI Canvas**로 옮겨, 게임 월드는 원래 Canvas(게임 카메라)·UI는 새 Canvas(UI 카메라)로 완전히 분리한다. 더 정공법이지만 재부모화와 `EnemySpawner`의 스폰 부모(`playerNode.parent`) 가정을 함께 봐야 해 범위가 커진다. 주 접근이 통과하면 폴백은 불필요하다.

**부수 — 카메라 직렬화 churn(F9).** UI 카메라 노드를 추가하면 `main.scene`에 카메라 관련 직렬화 diff가 생긴다. 장비별 화면 차이로 카메라가 재fit되는 기존 churn(F9)과 섞이지 않도록, 커밋 전에 `git diff *.scene`으로 의도한 변경만 남기고 무관한 `_lpos`·`_orthoHeight` 흔들림은 거른다.

## 6. 코드 변경 여부 → 테스트 스킵 판단

이 슬라이스의 변경은 **전부 Cocos 에디터/씬/프리팹 작업**이다 — 카메라 추가, `visibility`/`clearFlags`/`priority` 설정, 노드·프리팹 레이어 재배정, 라벨 넘침 속성. `game/assets/scripts`의 어떤 `.ts`도 바뀌지 않는다(레이어를 코드로 만지지 않으며, 프리팹 루트 레이어를 고치면 인스턴스가 물려받으므로 런타임 코드도 불필요).

따라서 검증할 **순수 로직 파일이 없으므로** 워크플로우의 테스트 스킵 조건에 해당한다. 계획 승인 후 qa-setup 단계에서 `pnpm wf skip-test "전부 Cocos 카메라/레이어/프리팹 에디터 설정 변경 — 순수 로직 .ts 변경 없음"`으로 사유를 기록하고 넘어간다. 대신 **QA 문서(`docs/qa/card-layer-fix-test.md`)의 수동 체크리스트와 에디터 레시피를 두껍게** 써서, §5의 확인 포인트와 §3·§4의 정확한 노드/카메라 설정값을 사용자가 에디터를 열지 않고도 알 수 있게 한다.

> 선택(채택 안 함, 기록만): 적·발사체 스폰 시 코드에서 `node.layer = Layers.Enum.DEFAULT`를 명시해 프리팹 레이어 드리프트를 방어하는 로버스트니스 옵션이 있다. 다만 백로그 H1의 결정은 에디터 기반이고, 프리팹 루트만 맞추면 충분하므로 이번엔 넣지 않는다. 추후 프리팹이 늘어 레이어 실수가 잦아지면 재검토.
