#### W1. 변경 집합과 적용 판정 — `.claude/lib/change-set.mjs`

- `collectChangeSet(root)`: `git merge-base origin/main HEAD`를 구하고, 추적 변경은 `git diff --raw -z --no-renames <mb>`(모드가 함께 나와 gitlink `160000`을 가려낼 수 있다 — `--name-status`는 모드를 내지 않는다. 출력은 status와 path 사이도 NUL이라 NUL로 갈라 짝으로 읽고 마지막 빈 토큰을 버린다), 미추적은 `git ls-files -o --exclude-standard -z`로 얻어 합친다. 항목은 `{status: 'A'|'M'|'D', path}`이고 경로는 git이 낸 저장소 상대 경로 그대로다(소문자화 금지). `.claude/workflow-state.json`은 뺀다. rename은 `--no-renames`로 D+A가 된다. 서브모듈(gitlink, mode `160000`)이 나타나면 `measurable: false`로 돌려준다.
- `measurable`이 거짓인 경우: `origin/main` 참조가 없다, git 저장소가 아니다, `realpath(root)`가 `realpath(git rev-parse --show-toplevel)`와 다르다, gitlink가 있다. 이때 모든 게이트가 적용된다(fail-closed). 「ROOT가 저장소 루트인가」는 `cwd: ROOT`로 띄운 `git rev-parse --show-prefix`가 빈 문자열인지로 잰다(실측 2026-09-17: 루트에서 빈 줄, `docs/`에서 `docs/`). realpath·normalize·대소문자 비교는 쓰지 않는다 — `--show-toplevel`이 `F:/…`, Node가 `F:\…`를 내는 문제(실측)는 비교 자체를 없애면 사라진다. 원인별 처방(「origin/main 없음 → `git fetch origin main`」, 「하위 폴더에서 실행 → 저장소 루트에서」, 「gitlink → 서브모듈은 지원하지 않음」)은 한 함수가 만들어 게이트를 계산하는 모든 명령이 같은 문장을 찍는다. 판정 전에 `fetch`하지 않는다. 로컬 `origin/main`이 낡으면 merge-base가 앞으로 가 변경 집합은 커지기만 하고 작아지지 않으므로 게이트가 덜 걸리는 쪽으로는 틀리지 않는다. 기준점은 `origin/main` 고정이라 1단계 위에 2단계를 미리 올리는 스택 브랜치에서는 게이트가 과하게 걸린다(D10대로 머지 뒤 열면 문제없다).
- 경로 정책은 이 파일의 상수다. `CSO_PATHS`(`.claude/**`, `tools/**`, `tests/helpers/**`, `tests/fixtures/**`, `.husky/**`, `vitest.config.*`, `package.json`, `pnpm-lock.yaml`, `.gitattributes`, `biome.json`, `tsconfig*.json`, `.gitignore`, `.vscode/**`, `**/*.{sh,ps1,cmd,bat}`(앞 셋은 통합 검사가 무엇을 보는지와 변경 집합 자체를 정한다), 그리고 생기면 `.github/**`·`.npmrc`·`pnpm-workspace.yaml`·`.gitmodules`·`.mcp.json`), `META_PATHS`(`game/assets/**`), `FULL_TYPECHECK_PATHS`(`game/**`, `pnpm-lock.yaml` — `package.json`은 넣지 않는다. 의존성 변경은 반드시 lockfile을 건드리고 `scripts` 편집은 타입에 무관하다. 이 슬라이스가 `verify:ci` 스크립트로 `package.json`을 고치므로 넣으면 §12의 「full-typecheck 해당 없음」이 자기 규칙으로 거짓이 된다). 각 상수 위 주석에 정책 문장(「개발 장비에서 실행되는 코드·자동화·의존성·공급망·git 실행 동작을 바꾸는 파일」)을 적어 목록만 고치지 않게 한다. 매칭은 경로 접두·글롭이고, 보호 루트의 대소문자 변형(`.Claude/`)도 보호 경로로 본다. 글롭은 세그먼트 경계를 지키고(`gameplay.md`는 `game/**`에, `toolsmith/x`는 `tools/**`에 걸리지 않는다) `package.json`·`pnpm-lock.yaml`은 루트 고정이다 — `game/package.json`(Cocos 프로젝트 파일, 실재)이 걸리면 모든 게임 슬라이스가 CSO에 걸린다.
- `applicableGates(changeSet)`: 게이트 `meta`·`fullTypecheck`·`cso`마다 `{applies, matches, rule}`을 돌려준다(`matches`는 변경 집합에서 걸린 경로, `rule`은 걸린 글롭). `status`·전이 차단 메시지가 「어느 파일 때문에 적용」「어느 경로가 없어 해당 없음」을 이 값으로 찍으므로 CLI가 매칭을 다시 하지 않는다. 해당 없음은 저장하지 않는다. `status`·`pass`·`approve-pr`·`start-verification`이 부를 때마다 계산한다.
- `.claude/lib/*.mjs`는 상태 파일을 읽거나 쓰지 않는다. 상태는 `workflow.mjs`만 쓴다.
- 재측정 도구 `tools/wf-measure/measure.ts`: 이 장비의 세션 기록(`~/.claude/projects/<slug>/*.jsonl`)에서 진행 기록 §3.1의 표(구간별 도구 호출·출력 토큰·활동 시간·재검증 횟수)를 다시 낸다. 리뷰 뒤 수정 작업과 게이트 의식을 갈라 센다. 다시 쓸 도구는 `tools/`에 커밋한다는 규칙을 따른다. 파일 머리에 사용법(`node --experimental-strip-types tools/wf-measure/measure.ts <slug> --since <date>`)과 지표 정의를 적는다: 회차 = phase 전이 명령 사이, 검증 회차당 기계 검사 명령 수, `invalidate` 뒤 `/cso` 재실행 수, `check-links` 단독 실행 수, 도구 슬라이스 hello world(`wf start`부터 `start-verification` 초록까지) AI 턴 수. 픽스처는 실제 세션 jsonl을 복사하지 않고 합성한다(경로·이메일·도구 출력이 든다). jsonl은 Claude Code 내부 형식이라 안정 보장이 없으므로 파서는 `type === 'assistant'` + `content[].type === 'tool_use'` + `name`·`input.command`만 보고 §12 지표를 그 필드로만 계산한다. 형식이 바뀌면 §12 지표는 세션 기록을 손으로 세는 것으로 대체한다. 기준선인 진행 기록 §3.1 표의 숫자는 `docs/temp/`(미추적)에만 있으므로 계획 승인 뒤 sessions 개요 문서에 옮겨 커밋한다 — 2단계 go/no-go가 이 숫자에 걸린다.
- 캡처하는 `spawnSync` 전부에 `maxBuffer: 64 * 1024 * 1024`를 명시한다 — 기본 1 MiB는 대형 아트 슬라이스의 `git diff`나 에러 수백 건의 tsc 출력에서 넘쳐 `ENOBUFS`·`status: null`이 된다. `r.error`·`status === null`은 자리마다 fail-closed로 접는다(변경 집합 → `measurable: false` 「git 출력 캡처 실패」, 러너 → status 1).
- 테스트(`WfSandbox`의 git 샌드박스): 추적 수정·미추적 신규·삭제·rename(D+A)·공백·한글 파일명·상태 파일 제외·`origin/main` 없음·상위 저장소 안의 폴더(`show-prefix`가 비어 있지 않음)·gitlink·`git` 캡처 실패(`r.error` 주입) → 각 판정. 글롭 경계: `gameplay.md`∉`game/**`, `toolsmith/x`∉`tools/**`, `game/package.json`∉루트 `package.json`.
