# 경험치 바 채움이 바 왼쪽 끝에서 시작하게 한다

- **작성:** 2026-10-14
- **브랜치:** feat/xp-bar-fill
- **정본:** 없음 — 버그 수정이라 명세가 바뀌지 않는다. 채움 위치를 왜 코드가 맞추는지는 `game/assets/scripts/ui/HudController.ts`의 XP 바 갱신 주석과 새 순수 함수의 JSDoc이 든다
- **이 슬라이스가 닫는 백로그 항목:** F142

---

## 1. 증상

화면 하단의 경험치 바에서 노란 채움이 바 왼쪽 끝이 아니라 바 안쪽에서 시작한다. 마법 이펙트 게이트 QA(`docs/qa/magic-effect-gate-test.md` §7)에서 사용자가 발견했다.

## 2. 원인

`main.scene`의 `XpBar` 노드는 폭 1280 · 앵커 가운데(0.5)이고, Widget이 붙어 있어 실행 중에 화면 폭만큼 늘어난다. 채움 노드 `Bar`는 앵커가 왼쪽(0)이고 씬에 저장된 위치는 x = -640이다.

Cocos 3.8.8 엔진의 `ProgressBar`(`cocos/ui/progress-bar.ts`)는 채움 노드의 x를 `_initBarSprite`에서만 `-바 폭 × 바 앵커 x`로 놓는다. 이 함수는 바 스프라이트를 연결할 때 한 번 불리고, 그때 바 폭은 1280이라 x는 -640이 된다. 매 프레임 진행도를 그리는 `_updateBarStatus`는 채움의 폭만 바꾸고 시작 위치는 다시 계산하지 않는다.

`HudController`는 매 프레임 `totalLength`를 늘어난 바 폭으로 맞추므로 채움의 **길이**는 바를 따라간다. 하지만 **시작점**은 -640에 남는다. 화면이 1280보다 넓으면 바의 실제 왼쪽 끝은 -640보다 더 왼쪽에 있으므로 채움이 안쪽에서 시작하고, 다 차면 그만큼 오른쪽 끝을 넘친다.

## 3. 고치는 방법

`HudController`가 `totalLength`를 맞추는 자리에서 채움 노드의 x도 `-바 폭 × 바 앵커 x`로 함께 맞춘다. 엔진이 처음에 쓰는 식과 같은 식이므로, 화면 폭이 1280일 때는 지금과 결과가 같다.

엔진의 `_updateBarStatus`는 채움 노드를 `바 폭 × (목표 앵커 − 채움 앵커)`만큼 옮긴다. reverse가 꺼져 있으면 목표 앵커와 채움 앵커가 둘 다 (0, 0.5)라 옮기는 양이 0이다. 그래서 코드가 넣는 x와 엔진이 서로 부딪히지 않고, `totalLength` · `progress`보다 먼저 넣든 나중에 넣든 결과가 같다. x만 바꾸고 y · z는 지금 값을 그대로 둔다. 폭이 0일 때 건너뛰는 지금 조건(`if (width)`) 안에 x도 함께 넣는다. reverse를 켜면 채움 앵커가 1이 되어 이 식이 맞지 않는다. 이 바는 reverse를 쓰지 않으므로, 순수 함수 JSDoc에 reverse가 꺼진 바에만 쓴다고 적는다.

Widget은 프레임의 update가 끝난 뒤에 폭을 다시 맞춘다. 그래서 첫 프레임과 창 크기를 바꾼 직후 한 프레임은 이전 폭으로 그려지고, 다음 프레임에 맞춰진다. 지금 `totalLength`도 같은 식으로 한 프레임 늦게 따라가므로 그대로 둔다.

`HudController`의 XP 바 갱신 주석은 지금 폭만 맞춘다고 설명한다. 시작 x도 맞춘다는 내용으로 함께 고친다.

이 계산을 순수 함수로 `logic/HudFormatLogic.ts`에 두고(`barRatio` 옆) 테스트한다. 씬 파일은 고치지 않는다. 채움 노드에 Widget을 붙이는 방법도 있지만, 그러면 엔진이 매 프레임 바꾸는 채움 폭과 Widget이 서로 다투게 된다.

HP 바는 폭 200으로 고정돼 늘어나지 않으므로 이 문제가 없고, 이번에 건드리지 않는다.

## 4. 확인

- 테스트 `tests/logic/XpBarFill.test.ts` — 바 폭 · 앵커별 시작 x(1280 · 0.5 → -640, 1600 · 0.5 → -800, 앵커 0 → 0, 앵커 1 → -폭)
- 사용자 인게임 확인 — 브라우저 창을 넓혀 1280보다 넓은 화면에서 채움이 바 왼쪽 끝에서 시작하고, 다 차도 오른쪽 끝을 넘지 않는다
