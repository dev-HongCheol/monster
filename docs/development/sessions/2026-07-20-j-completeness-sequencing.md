# v1 완성도(J축) 순서잡기 — 첫 방향 확정

- **작성일:** 2026-07-20
- **브랜치:** design/art-direction-plan
- **성격:** 의사결정 기록. circle-obstacle(#62) 머지 후 "다음 슬라이스"를 정하려고 `/office-hours`로 v1 완성도(J축)를 순서잡은 논의와 그 결정을 남긴다. 코드 구현 계획이 아니다.
- **관련 백로그:** J2·J3·J5·J7, F49(→v2), F57(신규), F50·F54·F55(#62 아카이브), F53(원 완료)

---

## 1. 왜 이 논의를 했나

맵/공간 스레드가 circle-obstacle(#62)까지 오면서 그 테마는 v1에서 사실상 닫혔다(아레나·소프트 해저드·건물 충돌·원 장애물 완료). 남은 v1의 주력 축은 **완성도(J)** — 맵·스토리·플로우·UI·메타인데, 대부분이 `office-hours 확정` 대기 상태라 순서와 의존성을 먼저 정해야 했다.

## 2. Phase 1 감사 — J축 실제 구현 현황 (코드 근거)

백로그가 "골격 존재 여부 미확인"이라고 적어 둔 것을 코드로 직접 확인했더니 그림이 바뀌었다.

- **J2 전체 게임 플로우는 골격이 아니라 거의 완성돼 있다.** `GameManager`에 루프가 통째로 배선돼 있다 — `gameDuration` 타이머가 0이 되면 `Victory` → `goToResult`, HP가 0이 되면 `GameOver` → `DeathSequence` → `goToResult`, 그리고 `restart()`(main 재로드)·`goToMenu()`. 결과 스냅샷(`_snapshotResult`)도 완비. 남은 것은 밸런스(타이머 값)와 폴리시(승리 비트 대칭 F28)뿐이다.
- **J3 메타는 대부분 비어 있다.** `MainMenuController`는 Play 버튼 하나가 전부이고(→ main 로드), 코드 전체에 `localStorage`가 0건이다. 세이브·도감·설정 전부 미구현.
- **승리와 사망이 비대칭이다.** 사망은 `DeathSequence`(오버레이 페이드 0.8초) 비트가 있는데, 승리는 `update()`에서 곧장 `goToResult()`로 직행한다. 이게 F28이 지적한 비대칭이다.

## 3. 의존성 정리

```
J3 세이브 인프라 ──→ J7 보상 포인트(누적) ──→ F37 리롤(구매)
J3 세이브 ──→ 이어서하기 분기 ──→ F57 위치 카드(이어서 흐름)
J6 사운드 ──→ J4 설정 화면(오디오 슬라이더)
J2 게임 플로우: 이미 배선됨 → 마감·폴리시만 (선행 없음)
```

핵심은 **세이브(J3)가 뿌리**라는 것이다. 이어서하기·보상 포인트 누적·로딩 도감이 전부 그 위에 선다.

## 4. 결정

### 결정 1 — 타이머 15분(900) 유지 (2026-07-20 사용자)

반복 플레이 장르라 런을 짧게 가져간다. `gameDuration`이 이미 900이라 코드 변경 없음. 밸런스 값이므로 인게임 테스트 후 재조절한다.

### 결정 2 — 첫 축은 "런 체감 완성", 기획으로 상세화

사용자가 고른 첫 축은 런의 시작과 끝을 "게임답게" 마감하는 것이다. 논의 중 기획의 실제 그림이 내(AI) 초기 프레이밍(전투 위 텍스트 오버레이)보다 컸다는 게 드러났다.

- **새 게임(처음부터):** 3나라 무녀 등이 등장하는 **인트로 씬**. 텍스트가 아니라 씬이다 → J5.
- **이어서하기:** (필요 시) **로딩 화면**. 다만 현재 게임은 로컬 JSON·소수 스프라이트라 기술적 로딩이 없다 → "등장 귀신·아이템 이미지/정보/프로그레스"는 로딩이 아니라 **도감 성격의 전환 화면**으로 취급한다(없는 로딩을 위한 프로그레스 바는 만들지 않는다) → J3.
- **위치 타이틀 카드:** 이어서하기 시 로딩 후·게임 시작 전, 화면 중앙에 "서울 - 한강"을 띄우고 1초 뒤 페이드아웃 → 게임 진행 → **F57(신규)**.
- **승리:** 결과 표시(현행) + **보상 포인트 증정**(미구현). 포인트는 `GameResult`에 필드로 추가하고 세이브로 누적한다("나중에") → J7.

### 결정 3 — 세이브 의존성이 런 체감을 가로막는다

위 상세화에서 이어서하기·로딩 도감·보상 포인트가 전부 세이브(J3)에 매달린다는 게 드러났다. 세이브 없이 지금 자족적으로 만들 수 있는 유일한 조각은 **새 게임 인트로 씬(무녀·3나라)** 하나다. 감사에서 나온 "J3 세이브가 뿌리"라는 결론이 여기서 되돌아온다.

### 결정 4 — F49 한강 대교 → 이월(v2) (2026-07-20 사용자)

반복 플레이 런 체감을 인트로·세이브 쪽으로 먼저 채우기로 하며 다리는 MVP1에서 뺐다.

### 결정 5 — 디자인(아트 디렉션) 우선 (2026-07-20 사용자)

코드 슬라이스로 바로 들어가는 대신, 캐릭터·마법·맵·적의 **시각 디자인을 먼저** 잡기로 했다. 충돌 검토 결과 안전하다.

- 캐릭터·마법·적 디자인은 전부 placeholder(마법=분류 색 틴트, 적=`tint`+`threatScale`, 플레이어=placeholder 스프라이트)를 갈아끼우는 것이라 로직과 충돌하지 않는다. 크기·충돌은 데이터(`collisionRadius` 등)라 최종 아트가 들어와도 코드는 불변이다.
- 콘텐츠 동결(마법·적 신규 2차)과도 정합한다 — 신규가 아니라 기존의 시각화이고, 로드맵 7-9주 아트 파이프라인에 해당한다.
- 한 가지 뉘앙스: 최종 맵 아트(F41)는 placeholder 건물·강 배치를 다시 authoring하게 된다. 코드를 깨는 건 아니지만, 맵 아트는 충돌 제약(볼록 박스 ≤300px·다리 난간 금지)을 알고 그려야 재작업이 준다.

## 5. 백로그 반영
