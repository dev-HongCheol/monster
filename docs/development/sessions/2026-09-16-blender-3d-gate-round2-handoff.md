## 2. 이번 세션이 닫은 것

### 2.1 시각 경계를 몸 경계에서 떼어 냈다 — [ADR 009](../../decisions/009-visual-bounds-exceed-body.md)

지팡이가 캔버스를 넘는 문제를 「무기를 줄인다」로 풀지 않고 **구조로** 풀었다. 246×493은 기준 몸의 소스 캔버스이지 캐릭터가 차지할 수 있는 시각 범위의 상한이 아니다. 무기 · 망토 · 날개 층은 자기 캔버스를 갖는다.

런타임 전 경로를 실제 코드로 확인했고, 시각 크기가 논리 크기로 새는 곳은 **발치 오프셋 하나**뿐이었다. 그것도 Player 자기 노드의 `UITransform`에서 오므로 시각 층을 자식으로 두면 닿지 않는다.

공통 배율은 스칼라 하나다 — `K = 96 / 493 = 0.1947262`. **층 캔버스는 기준과 가로 · 세로 홀짝을 맞춘다**(어긋나면 그 축으로 0.5px 밀린다. 실측으로 확인).

### 2.2 G1 측정 넷

코어 본 52개 일치, 얼굴 · 머리카락 지문 동일, 상의 판들의 맨살이 맨살 판의 부분집합(밖의 점 0개), 맨살 구멍 없음. 무기 자리는 손 위 208px · 아래 284px · 바깥 45px이다.

**VRoid는 옷을 별도 메시로 내보내지 않는다** — `Body` 하나에 머티리얼로만 갈려 있어 층을 가르려면 머티리얼로 면을 골라야 한다.

### 2.3 손 자세 확정

각도를 `pose_bone.rotation_quaternion`에 그대로 넣던 것이 틀렸다. `retarget_bake`는 **월드 공간에서 rest에 곱하는 델타**로 쓴다. `_common.apply_world_delta_pose`가 그 식을 든다. 손가락은 **로컬 회전 + 오일러 XYZ**로 방식이 달라 `apply_local_pose`가 따로 맡는다.

채택값(`retarget_render.py`에 들어감, 근거는 그 주석):

```
J_Bip_R_Hand    (-105, -58,   0)
J_Bip_R_Thumb1  (  25, +20,  30)
J_Bip_L_Thumb1  (  25, -20, -30)
```

`weapons.ts`의 후보 표가 정본이고 `grip`이 무기별 속성으로 들어갔다.

## 3. 다음 한 칸 — 툰 세팅

### 3.1 겨냥할 수치

사용자가 만든 귀신 표본 둘을 재서 목표를 뽑았다(`docs/temp/3d-gate/g2/처녀귀신.png` · `도깨비.png` — 커밋하지 않는다).

| | 처녀귀신 | 도깨비 |
|---|---|---|
| 윤곽선 굵기 | 5px = 긴 변의 **0.55%** | 8px = **0.57%** |
| 평균 채도 | 0.200 | 0.427 |
| 뭉갠 색 수 | 337 | 1092 |

**윤곽선 비율이 둘 다 0.55~0.57%로 맞아떨어진다.** 493px 캔버스 기준 **2.7~2.8px**이 외곽선 목표다.

**채도는 목표로 쓰지 않는다.** 두 표본이 두 배 넘게 벌어지는데 소재 차이다 — 정본 §4.1의 `tint`가 처녀귀신을 `#C9C9D2`, 도깨비를 `#5A3A8A`로 정해 놨다.

### 3.2 할 일 순서

1. **MToon 값** — 음영 2~3톤, 그림자 경계를 또렷하게
2. **외곽선** — 493px에서 2.7px 겨냥. 방식(인버티드 헐 · Line Art · 컴포지터)은 후보를 나란히 굽는다. **가림과 함께 고른다** — 방식에 따라 가림 뒤에 외곽선이 남거나 사라진다(G2 §3)
3. **비교 시트** — 3D 캐릭터 · 출하 2D 플레이어 · 귀신 둘을 **실제 표시 크기**로(도깨비 70단위, 처녀귀신 50단위, 플레이어 96단위)
4. **층 합성과 기준 컷의 픽셀 차이 기록**(G4 회귀 가드) — G2 §3

외곽선 방식 · 카메라 고도 · 화풍 통과는 **전부 사람 판정**이다(G2 §5).

## 4. 도구 쓰는 법

전부 `tools/blender/`에 있고 Blender는 `C:\Program Files\Blender Foundation\Blender 5.2\blender.exe`다.

```bash
# 층 하나 굽기 — layer: body · top · staff · shield
blender --background --python-exit-code 1 --python tools/blender/probe_layers.py -- \
  --base-vrm art-source/player/2026-09-16-player-3d/player_base.vrm \
  --layer staff --weapon-spec docs/temp/3d-gate/g2/staff_orb.json \
  --out docs/temp/3d-gate/g2/L_staff.png \
  --width 246 --height 493 --foot-row 489 --head-row 2 \
  --layer-width 420 --layer-height 493
```

- `--no-holdout 1` — 가림을 끈다. **층이 비어 나올 때 가려져서인지 애초에 없어서인지를 가르는 유일한 수단**이다
- `--yaw 180` — 모델을 돌린다(뒷모습)
- `--top-vrm <경로>` — 상의 층에 필요하다
- 무기 사양 JSON은 `docs/temp/3d-gate/g2/dump-weapons.ts`가 `weapons.ts`에서 뽑는다

| 도구 | 무엇 |
|---|---|
| `probe_layers.py` | 층 하나를 가림 전용 몸과 함께 굽는다 |
| `bake_layer.py` | 층 캔버스를 달리해 굽는다(ADR 009 실증에 씀) |
| `inspect_meshes.py` | 메시 · 머티리얼 · 정점 지문 덤프 |
| `measure_weapon_room.py` | 기준 자세의 손 위치와 몸 상자 |
| `docs/temp/3d-gate/g2/occlusion.ts` | 가림 판정 + 층 합성 + 게임 크기 축소 |
| `docs/temp/3d-gate/g2/measure_ghosts.ts` | 귀신 표본의 윤곽 · 채도 · 색 수 |

## 5. 일하는 방식 — 이번 세션에서 두 번 어겼다

**이미지가 산출물이면 AI가 판정하지 않는다. 경로를 주고 사용자 확인을 받은 뒤에 다음 단계로 간다.**

2026-09-16에 자세를 고친 렌더를 AI가 보고 「1라운드와 일치한다」고 스스로 통과시킨 뒤 세 판을 다시 굽고 측정까지 갔다. 사용자가 보니 오른손은 손바닥이 정면을 향했고 왼손 엄지는 뒤집힌 따봉이었다. 확인 안 했으면 틀린 손으로 전부 구웠다.

**재는 것은 코드로, 보는 것은 사람이.** 이번 세션의 버그 일곱 개 중 여섯 개를 숫자가 먼저 잡았다(`ortho_scale` 불일치 · 무기 world bbox · yaw 후 손 위치 · 알파 부분집합 …). 눈으로 본 것 하나는 틀렸다.

**위치 수정은 이 형식으로 주고받는다** — ① 어느 이미지 ② **화면 기준** 방향(「캐릭터 왼쪽」은 앞뒤에서 뒤집힌다) ③ 픽셀 또는 물체 기준 비율.

**굵기 · 크기 판정은 게임 크기 축소판으로 한다.** 탐침 렌더는 실제보다 8배 크게 보인다.
