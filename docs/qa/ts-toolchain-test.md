# QA — TS 툴체인 (타입 게이트 설치)

- **브랜치:** feat/ts-toolchain
- **계획:** [`../development/sessions/2026-07-13-ts-toolchain-plan.md`](../development/sessions/2026-07-13-ts-toolchain-plan.md)
- **백로그:** F27 · F30 (F24는 후속 슬라이스로 분리)
- **성격:** 툴체인 슬라이스. **게임 로직 무변경**이므로 인게임 회귀 위험이 낮고, 검증의 무게중심이 "게이트가 실제로 강제되는가"에 있다.

---

## 1. Impact Map

변경 파일별로 무엇을 확인해야 하는지다.

| 변경 파일 | 성격 | 확인 범위 |
|---|---|---|
| `game/tsconfig.json` | 컴파일러 설정 (`lib: ES2017`, `skipLibCheck`) | 타입 검사만 바뀐다. **출력물·런타임에 영향 없음.** `pnpm typecheck`가 게임 프로젝트에서 에러 0 |
| `tsconfig.tests.json` (신규) | Cocos 비의존 타입체크 프로젝트 | `tests/**` + `logic/**` + `data/**` 에러 0. **Cocos 없이도 돈다**(프레시 클론 검증) |
| `package.json` | `typescript`·`@types/node` devDep + `typecheck` 스크립트 | `pnpm install` 후 `pnpm typecheck` 동작 |
| `.claude/workflow.mjs` | `pass ts`가 실제로 타입체크 실행 | **일부러 타입 에러를 넣었을 때 `pass ts`가 실패하는가** (§4) |
| 싱글톤 선언 7곳 (`null as unknown as T`) | 임시 다리 | 런타임 무영향. 게임 정상 구동 + **재시작(씬 리로드)** |
| `I18nKeyGuard.ts` → `tests/helpers/` | 파일 이동 (게임 번들에서 제거) | 게임 코드가 이 파일을 참조하지 않으므로 씬·프리팹 참조가 깨질 수 없다. **Cocos 에디터가 에러 없이 열리는지**만 확인 |
| `tests/logic/MagicAddCard.test.ts` | 기존 타입 에러 수정 (`pattern` 누락) | 해당 테스트 통과 유지 |
| `.vscode/settings.json` | 편집기 TS 버전 정렬 | VS Code가 워크스페이스 TS(5.8.x)를 쓰는지 |
| `CLAUDE.md` | 9번 절차 교체 | 문서 |

**회귀 테스트 기준:** 게임 로직 파일(`systems/`·`components/`·`ui/`)의 **동작 코드는 한 줄도 바뀌지 않는다.** 바뀌는 것은 싱글톤 선언 7줄뿐이며, 이는 정적 초기화 시점에 `null`을 대입하는 것 외에 의미가 같다. 따라서 인게임 회귀는 "구동되는가 / 재시작되는가" 수준이면 충분하다.

## 2. 씬 / 프리팹 변경 사항 — **없음 (확정)**

이번 슬라이스는 씬(`.scene`)·프리팹(`.prefab`)을 **일절 건드리지 않는다.** 새로 만들 노드도, 옮길 노드도 없다.

## 3. 에디터 연결 체크리스트 — **없음 (확정)**

새 컴포넌트가 없으므로 연결할 `@property`가 없다. 7단계에서 에디터 세팅 작업이 발생하지 않는다.

> 단, `I18nKeyGuard.ts`가 `game/assets/`에서 빠지므로 **Cocos가 자산 하나를 잃는다.** 게임 코드가 이 파일을 import하지 않음을 확인했으므로(참조 0건 — 자기 테스트만 import) 씬·프리팹 참조가 깨질 여지가 없다. 에디터를 열었을 때 자산 누락 경고가 뜨지 않는지만 본다.

## 4. 자동 테스트로 검증 — **통과 (2026-07-13)**

> **근거:** 전체 스위트 **443/443** 통과(33개 파일). 피처 테스트는 없다(스킵 — §4 하단). `pnpm wf start-verification`의 GREEN 게이트를 통과해 `phase=verification` 진입.

- [x] `pnpm typecheck` — 게임 프로젝트 에러 **0** (`✓ 게임 코드 통과`)
- [x] `pnpm typecheck` — 테스트 프로젝트(`tsconfig.tests.json`) 에러 **0** (`✓ tests/logic/data 통과`). 이 프로젝트가 **처음으로** 테스트 코드를 타입 검사했고, 곧바로 `MagicAddCard.test.ts`의 진짜 타입 에러(TS2741 — `ISpellData.pattern` 누락)를 잡아 수정했다.
- [x] `pnpm test:run` — **443/443 통과** (순수 로직 무변경이므로 회귀 0)
- [x] `pnpm check` — lint·format 통과
- [x] **게이트 강제 검증 (핵심).** `WaveManager.ts` 끝에 의도적 타입 에러 `export const __gateProbe: number = "not a number";`를 넣고 `pnpm wf pass ts` 실행 → **TS2322를 잡아내고 종료코드 1로 실패**했으며, 결정적으로 **`ts_check_clean`이 `false`로 남았다**. 개편 전 코드였다면 검증 없이 `true`가 됐을 자리다. 확인 후 프로브를 완전히 제거했다(`grep -r __gateProbe game/` → 잔여 0).
- [x] **게이트 강제 검증 (재리뷰 후 추가).** 코드 리뷰가 찾은 구멍 — `pass ts` 실패가 **이전에 저장된 통과 플래그를 회수하지 않던 것** — 을 막았다. 이제 실패 시 `ts_check_clean = false` + `ts_check_scope = null`을 저장한 뒤 종료한다. 즉 "통과했다가 코드를 고쳐 타입이 깨져도 나머지 pass만 채우면 PR까지 가는" 경로가 닫혔다.
- [x] **종료코드 판정.** tsc는 타입 에러에도 종료코드 **2**를 낸다(1이 아니다 — 설정 에러도 2). `.claude/typecheck.mjs`가 `status !== 0`으로 판정하며, `=== 1` 비교를 쓰지 않는다(그랬다면 모든 타입 에러를 통과시켰을 것). 주석으로 근거를 남겼다.
- [x] **프레시 클론 시뮬레이션.** `game/temp/tsconfig.cocos.json`을 치운 상태에서 `pnpm typecheck` 실행 → TS5083 대신 **사람이 읽는 안내**가 떴고, 테스트 프로젝트는 정상 검사됐으며, 범위가 **`logic-only`** 로 보고됐다. `approve-pr`이 이 범위를 거부하는 가드를 `workflow.mjs`에 넣었다(코드 검증 — 실제 차단은 8단계에서 발현).

**단위 테스트 파일 없음 (의도적):** 신규 순수 로직이 없다. 변경은 컴파일러 설정·워크플로우 CLI·선언문·파일 이동뿐이다. `pnpm wf skip-test`로 사유를 기록했다. 회귀 방어는 위 게이트 강제 검증이 맡는다.

## 5. 수동 테스트 체크리스트 (7단계 — 사용자)

게임 로직이 안 바뀌었으므로 **가볍다.** 확인 목적은 "임시 다리(`null as unknown as T`)와 파일 이동이 런타임을 깨지 않았는가"다.

### 5-1. Cocos 에디터

- [x] Cocos Creator로 프로젝트를 연다. **자산 누락·컴파일 에러 경고가 없는지** 확인한다 (`I18nKeyGuard.ts`가 `game/assets/`에서 빠졌지만 참조하는 게임 코드가 없으므로 조용해야 한다).
- [x] 콘솔에 빨간 에러가 없다.

### 5-2. 인게임 한 바퀴

- [x] 게임을 시작한다 → 플레이어가 움직이고 마법이 발사된다.
- [x] 적을 처치해 XP를 먹고 **레벨업 카드가 뜬다** → 카드를 고르면 패널이 닫히고 게임이 재개된다.
- [x] ESC로 일시정지 → 재개된다.
- [x] 죽을 때까지 맞는다 → **HP가 0이 되면 실제로 죽고** 결과 화면으로 넘어간다.
- [x] 결과 화면에서 **RETRY(재시작)** → 씬이 리로드되고 게임이 정상적으로 다시 시작된다. **싱글톤이 실제로 null이 되는 유일한 순간이므로 이 항목이 가장 중요하다.**
- [x] 재시작 후에도 마법 발사·XP 획득·레벨업이 정상 동작한다.

### 5-3. 에디터 프리뷰 핫리로드

- [x] 프리뷰를 실행한 상태에서 스크립트를 하나 저장해 **핫리로드**를 유발한다 → 게임이 죽거나 싱글톤이 사라지지 않는지 본다. (`static instance: T = null as unknown as T`는 기존 `instance!:` 형태와 달리 모듈 평가 시점에 실제로 `null`을 대입하므로, 모듈이 재평가되면 살아 있는 인스턴스를 지울 이론적 여지가 있다. 실무상 Cocos가 씬을 리로드해 무해할 것으로 보지만 한 번 밟아 본다.)

### 5-4. 크로스머신 (선택 — 다른 장비가 있을 때)

- [x] 다른 머신에서 클론한 직후(= Cocos로 아직 안 연 상태) `pnpm typecheck`를 실행한다 → **TS5083 같은 날것의 에러가 아니라 사람이 읽는 안내**가 떠야 한다. 테스트 프로젝트는 정상적으로 검사된다.

---

## 6. 후속 슬라이스로 넘어가는 것 (여기서 검증하지 않음)

싱글톤 타입 정직화(`T | null`)와 호출부 73곳 가드는 **F24로 분리**됐다. 이번 QA는 그것을 다루지 않는다. 계획 §7에 넘긴 재료(지뢰 3곳·가드 규칙·클로저 내로잉·`DataManager` 콜백 버그)가 그 슬라이스의 QA 기준이 된다.
