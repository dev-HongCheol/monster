## Important

### I-1. `segmentCircleEntry`가 원이 선분 뒤에 있을 때 `-1`이 아닌 음수 t를 반환 — 수정됨

- **위치:** `game/assets/scripts/logic/ObstacleLogic.ts` `segmentCircleEntry`
- **진단:** "`c > 0`(밖에서 출발)이라 `t1 < 0`은 불가능하다"는 주석이 수학적으로 틀렸다. 선분이 원에서 **멀어지는** 방향(`b > 0`)이면 두 근이 모두 음수다. 구체 반례: `P=(300,0) Q=(400,0) C=(0,0) r=50` → `t1 = (−60000−10000)/20000 = −3.5`이고 `−3.5 ≤ 1`이라 함수가 `−1`이 아니라 `−3.5`를 반환한다. 형제 `segmentRectEntry`는 같은 경우 `−1`을 주므로, 헤더 주석이 "같은 역할"이라 부른 두 헬퍼가 실제로 어긋난다.
- **라이브 버그 아님:** 호출부 둘이 모두 방어한다 — 블로커 선택은 `t >= 0`으로 거르고, 목표 클램프 재판정은 `< 0`을 "안 막힘"으로 읽어 어느 쪽이든 결과가 같다(재판정에서는 `from`이 확장원 밖 + 경계 목표라 `b < 0`이 항상 성립해 음수 근 자체가 안 나온다). 그러나 이 헬퍼는 계획이 OBB·캡슐 슬라이스의 **재사용 지점**으로 지목한 seam이고, `t >= 0`을 안 거르는 미래 소비처가 "원이 뒤에 있는데 거의 즉시 진입"으로 오해할 함정이다.
- **수정:** `return t1 >= 0 && t1 <= 1 ? t1 : -1;`로 음수 근도 접고, 주석을 실제 불변식(첫 진입은 `[0,1]`, 멀어지는 선분은 음수 근 → 진입 없음)으로 다시 썼다. 두 호출부가 이미 음수를 걸러 기존 37개 테스트는 무변. 헬퍼가 비공개라 공개 API로는 이 경로를 직접 관측할 수 없어(두 소비처가 음수를 소거) 별도 단위 테스트는 두지 않는다 — 재사용 시점(OBB·캡슐)에 직접 소비하는 테스트가 붙는다.

### I-2. 계획이 약속한 접선점 극한 순환 국소 테스트 누락 — 수정됨

- **위치:** `tests/logic/CircleObstacle.test.ts`
- **진단:** 계획 §6이 "접선점에 정확히 선 적 vs 0.01px 지난 적 — 방향 뒤집힘 없음(C-1 원 판)"을 명시했는데 원 스위트는 도달 스윕(느린 통합 신호)으로만 덮었다. 사각형 스위트에는 같은 국소 테스트(`BuildingCollision.test.ts` "코너에 정확히 선 적과 0.01px 지난 적")가 있어 불연속을 빠르고 국소적으로 못박는다. 또 "같은 편·사이에 아무것도 없음 → `desiredDir` 반환"의 원 대응 테스트도 없었다(사각형엔 있음).
- **수정:** 두 국소 테스트를 추가했다 — ① 정면 대칭선 0.01px 통과 시 방향 비반전(dot > 0), ② 목표가 확장원 안이어도 같은 편 바로 뒤 적은 우회하지 않고 `desiredDir` 그대로 반환(재판정 조기 반환 경로 직접 단언). 원 피처 35→37, 전체 585→587 GREEN. 계획 §6 이탈이 이로써 닫혔고, QA 문서 §2에도 두 항목을 추가했다.

## Minor

### M-1. 비유한 노드에서 F50 스킵 전에 다른 경고가 먼저 뜬다 — 백로그 이월

- **위치:** `game/assets/scripts/systems/MapManager.ts` `_indexObstacles`
- **진단:** 비정사각(`isCircle && width !== height`)·scale·angle 경고가 F50 유한성 가드/`continue`보다 먼저 실행된다. `NaN` 크기 노드는 "비정사각"(NaN ≠ height)과 F50 스킵 경고를 둘 다 뱉는다. 씬 파일 수동 손상으로만 도달하는 순수 코스메틱.
- **처리:** 유한성 가드를 크기 계산 직후·경고들 앞으로 올리면 단일 신호가 되나, 계산 블록 재배치 리스크 대비 이득이 낮아(에디터로 도달 불가) 이번엔 수정하지 않는다. → `backlog-implement.md`에 이월.

### M-2. F55 하한 검사가 원에도 height를 본다 (주석 불일치) — 주석 수정됨

- **위치:** `game/assets/scripts/systems/MapManager.ts` F55 경고
- **진단:** `tr.width < MIN || tr.height < MIN`이 원에도 두 축을 보는데, 원의 지름은 width뿐이라 주석 "원은 지름 = width 기준"과 어긋난다. 비정사각 원(예: 240×100)은 이미 비정사각 경고를 받으므로 무해한 중복 경고다.
- **수정:** 코드는 두 축 바운딩 박스 검사로 두고(보수적·정사각 원이면 곧 지름), 주석을 그 사실에 맞게 고쳤다. 비정사각 원은 위에서 이미 경고된다는 점도 덧붙였다.
