# player-4dir — 테스트 체크리스트

- **브랜치:** feat/player-4dir
- **정본:** [`../development/sessions/2026-07-24-player-4dir-plan.md`](../development/sessions/2026-07-24-player-4dir-plan.md), [`../design/art-direction.md`](../design/art-direction.md) §3.3(온스크린 크기)·§9(작업 순서 2번), [`../decisions/006-collision-hitbox.md`](../decisions/006-collision-hitbox.md) (ADR 006)
- **범위:** 플레이어 마법사가 **이동하는 방향을 바라본다.** 앞·뒤·좌·우 네 장의 정지 스프라이트를 만들고, 이동 입력으로 방향을 판정해 방향이 바뀔 때만 그림을 갈아끼운다. 함께 그림을 세로로 크게(90~96px) 키우고 피해 히트박스를 새 실루엣에 맞춰 재튜닝한다.
- **범위 밖:** 이동 충돌 원(`collisionRadius=25`)과 그 중심 위치, 발치 오프셋, y-정렬, 스켈레탈 리깅, 이동·시전 애니메이션. 근거는 계획 §8.

## 씬 변경 사항 (잠정 — 구현 후 확정)

`main.scene`을 읽어 확인한 현재 상태다(2026-07-25). **새 노드를 만들지 않는다.**

```
Canvas (레이어 DEFAULT 0x40000000)
 ↳ Player                       ← 자식 없음. 아래 네 컴포넌트가 이 노드에 직접 붙어 있다
     · cc.UITransform           Content Size 50×64, Anchor (0.5, 0.5)
     · cc.Sprite                흰색 255, Size Mode CUSTOM, Trimmed, 브릿지 스프라이트가 물려 있음
     · PlayerController         현재 @property 없음 → 이 슬라이스가 프레임 슬롯을 추가
     · SpellCaster              무변경
 ↳ BulletParent
```

> **계획 §9 감사표의 `Player>Sprite` 표기는 부정확했다.** `Sprite`는 `Player`의 자식 노드가 아니라 `Player` 노드 자신에 붙은 컴포넌트다. 그래서 코드가 `@property`로 받지 않고 `getComponent(Sprite)`로 집는다(같은 노드의 Sprite를 이렇게 집는 것은 `EnemyController.onLoad`의 기존 방식과 같다). 연결을 잊어서 방향 전환이 조용히 죽는 실패 모드가 하나 줄어든다.

바뀌는 값은 둘이다.

| 대상 | 현재 | 바꿀 값 | 왜 |
|------|------|---------|-----|
| `Player > UITransform` Content Size | 50×64 | **(잠정) 70×90 또는 75×96** — 렌더 결과로 확정 | 세로 90~96px 결정(계획 §6). 가로는 소스 종횡비(브릿지 788×1012 = 0.779)를 곱해 계산했다: 90×0.779≈70, 96×0.779≈75 |
| `player.json` `hurtboxHalfWidth`/`hurtboxHalfHeight` | 18 / 30 | **(잠정) 25 / 42**(70×90 기준), **27 / 45**(75×96 기준) | 현 값은 50×64 실루엣에 맞춘 것이라 그대로 두면 몸통보다 작은 박스가 된다. 현 비율(폭의 0.36배·높이의 0.47배)을 새 크기에 적용한 값이며, **실제 그림의 몸통 코어를 보고 확정**한다 |

**바꾸지 않는 것:** Anchor (0.5, 0.5) — 네 프레임이 같은 피벗을 공유하는 근거다. `Sprite`의 Size Mode **CUSTOM** — TRIMMED나 RAW로 바꾸면 노드가 소스 픽셀(788×1012)로 리사이즈돼 플레이어가 화면을 덮는다. 노드 Scale (1, 1, 1) — 스케일에 크기를 실으면 리깅 때 같은 노드의 스켈레탈 디스플레이로 이월돼 숨은 재작업이 된다.

## 에셋 제작 — 네 방향 생성과 정합 (잠정 — 렌더 후 확정)

생성 드라이버는 레포 밖(`F:\ai\gen_mage_bridge.py`)을 방향별 프롬프트로 확장한다. 스타일 LoRA `f58_anime_style`(트리거 `f58anime`, 강도 0.8)을 그대로 얹고, 배경 제거는 rembg를 재사용한다.

1. **네 방향을 같은 캔버스·같은 시드 계열로 뽑는다.** 정면(front), 후면(back), 좌향(left), 우향(right). 좌·우를 미러링으로 만들지 않는다 — 미러링은 노드나 스프라이트의 `scale.x`를 뒤집어야 하고, 그 스케일이 리깅 때 이월된다.
2. **몸통을 캔버스 가로 중심에 맞춘다.** 현 브릿지는 지팡이·불꽃이 왼쪽으로 쏠려 몸통이 중심에서 벗어나 있다. 네 장 모두 몸통 중심을 캔버스 중심에 맞춘다.
3. **정합 검수 — 이게 단일 스프라이트엔 없던 이 슬라이스 고유 리스크다.** 아래 셋이 어긋나면 방향이 바뀔 때 캐릭터가 위치·크기로 튀어 걷는 내내 덜컹거린다.
   - 네 PNG의 **캔버스 크기가 동일**해야 한다.
   - 불투명 픽셀의 **가로 중심**이 캔버스 가로 중심에서 ±2% 안(788px 캔버스면 ±16px).
   - 불투명 픽셀의 **최하단(발 밑선)**이 네 장에서 ±1% 안(1012px 캔버스면 ±10px). 발 높이가 어긋나면 방향을 바꿀 때 캐릭터가 아래위로 튄다.
4. **지팡이·불꽃이 캔버스 밖으로 잘리지 않게** 뽑는다. 잘리면 그 방향만 실루엣이 달라 보인다.
5. 파일명은 `player_mage_front.png` · `_back.png` · `_left.png` · `_right.png`로 `game/assets/art/player/`에 둔다(브릿지 `player_mage_bridge.png`는 남겨 둔다 — 되돌릴 근거).

## 에디터 연결 체크리스트 (잠정 — 구현 후 확정)

`@property` 이름은 구현 시점에 확정되며, 아래는 계획 기준 예정 이름이다.

| # | 할 일 | 상태 |
|---|-------|------|
| 1 | 네 PNG를 `game/assets/art/player/`로 드래그 임포트 → 각 파일 아래 `spriteFrame` 서브에셋이 생기는지 확인(Type은 기본 `sprite-frame`) | ❌ |
| 2 | `main.scene` 열고 Hierarchy에서 `Canvas > Player` 선택 | ❌ |
| 3 | `UITransform` Content Size를 **(잠정) 70×90 또는 75×96**으로 설정. Anchor가 (0.5, 0.5)인지 확인 | ❌ |
| 4 | `Sprite`의 Size Mode가 **CUSTOM**인지 확인(바꾸지 않는다) | ❌ |
| 5 | `PlayerController` 인스펙터의 **(가칭) Frame Front / Frame Back / Frame Left / Frame Right** 슬롯에 각 방향 `spriteFrame`을 드래그 | ❌ |
| 6 | `Sprite`의 SpriteFrame에 **front** 프레임을 물려 둔다(에디터 미리보기용 — 런타임 초기 표시는 코드가 `start()`에서 정한다) | ❌ |
| 7 | `Player` 노드 Scale이 (1, 1, 1)인지 확인 | ❌ |
| 8 | `player.json`의 `hurtboxHalfWidth`/`hurtboxHalfHeight`가 새 실루엣의 몸통 코어에 맞는지 확인(지팡이·불꽃 오버행은 박스 밖 장식으로 둔다) | ❌ |

> **`Sprite` 컴포넌트 자체를 연결하는 슬롯은 없다** — 코드가 같은 노드에서 `getComponent(Sprite)`로 집는다(위 씬 섹션 참고).

## 자동 테스트로 검증

- [ ] `facingFromMoveDir` — 네 축 입력(오른쪽→right·왼쪽→left·위→back·아래→front), **입력 0이면 직전 방향 유지**(네 방향 각각), 정규화 대각선 네 조합이 모두 가로, 정규화 전 정수 대각선도 같은 규칙, 가로 우세→좌우·세로 우세→상하, **입력이 있을 때 직전 방향이 결과를 끌어당기지 않음**. → `tests/logic/Player4dir.test.ts`

## 수동 테스트 체크리스트 (7단계 인게임)

**방향 전환**

- [ ] 위·아래·좌·우로 걸을 때 각 방향에 맞는 그림이 뜬다(위로 걸으면 뒷모습, 아래로 걸으면 정면).
- [ ] 걷다 멈추면 **마지막으로 보던 방향을 유지**한다(정면으로 되돌아가지 않는다).
- [ ] 방향이 바뀔 때 캐릭터가 **위치·크기로 튀지 않는다** — 특히 발 높이가 그대로인지 본다(네 프레임 정합).
- [ ] 대각선으로 걸으면 좌우 그림으로 읽힌다(상하로 흔들리지 않는다).
- [ ] **벽에 밀고 있는 동안**에도 그 방향을 계속 바라본다(못 움직여도 방향은 유지).
- [ ] 일시정지·레벨업 카드 선택 중에는 방향이 얼어붙는다(소프트 일시정지와 일치).

**커진 그림 — 크기와 판정**

- [ ] 마법사가 브릿지보다 뚜렷하게 크고, 세로로 서 있는 비율이 자연스럽다.
- [ ] 지팡이·불꽃이 잘리지 않고 다 보인다.
- [ ] 적이 **머리·발 높이**로 접촉해도 피해가 들어온다(피해 박스 재튜닝 확인).
- [ ] 적이 **좌우로 스쳐 지날** 때 억울한 피격이 없다.
- [ ] 적 발사체가 같은 기준으로 명중·회피된다.
- [ ] **벽·건물 미끄러짐과 아레나 클램프가 그대로다**(이동 원 무변경). 커진 발·머리가 벽에 겹치는 정도가 견딜 만한지 눈으로 판단한다 — 거슬리면 그것이 **발치 오프셋**을 다음 슬라이스로 올릴 근거다(계획 §8, ADR 006).

**무변경 회귀**

- [ ] 이동 속도·한강 물속 감속이 그대로다.
- [ ] 경험치 픽업 반경·흡수가 그대로다.
- [ ] 마법 발사와 조준이 그대로다(이 슬라이스는 조준에 손대지 않는다 — `_facing`은 그림 선택에만 쓰인다).
- [ ] 카메라 추적이 그대로다(플레이어가 화면 중앙, 아레나 벽에서 멈춤).
