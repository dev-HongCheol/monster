# input-focus-reset — 테스트 체크리스트

- **브랜치:** feat/input-focus-reset
- **정본:** [`../development/sessions/2026-08-01-input-focus-reset-plan.md`](../development/sessions/2026-08-01-input-focus-reset-plan.md), 배포 환경은 [`../development/spec/ops-build.md`](../development/spec/ops-build.md) §4
- **범위:** 창이나 캔버스가 **포커스를 잃으면 눌린 것으로 기록된 이동키를 전부 해제**한다(백로그 **F65**). 그 과정에서 눌린 키 상태와 이동 벡터 계산을 순수 모듈 `logic/MoveInputLogic.ts`로 꺼낸다. 함께 `hitbox-viewer.html`의 biome 에러 4건을 닫는다(**F63**).
- **범위 밖:** 다른 입력 소비처의 포커스 정책(`PauseController`는 `KEY_DOWN` 엣지만 들어 눌린 상태를 갖지 않는다), 키 리바인딩·게임패드, `hitbox-viewer.html`의 정보 수준 지적 29건.

> **이 버그는 배포해야 보이는 것이 아니다.** 웹으로 도는 모든 환경에서 발생하며 **Cocos 에디터 프리뷰도 포함**한다(프리뷰가 Chromium이라 같은 `pal/input/web`을 쓴다). 실제로 F65는 `feat/player-4dir` 7단계 인게임 테스트에서 발견됐다. **따라서 아래 수동 항목은 전부 에디터 프리뷰에서 확인할 수 있고, itch에 올릴 필요가 없다.**

## Impact Map

| 변경 파일 | 확인 범위 (회귀 기준) |
|-----------|----------------------|
| `logic/MoveInputLogic.ts` (신규 순수) | `releaseAllMoveKeys`(해제)·`moveInputToVector`(벡터 계산) 자동 테스트 |
| `components/PlayerController.ts` | 눌린 키 상태를 위 모듈로 위임 + 포커스 유실 신호 세 개 구독·해제. **이동 자체가 바뀌면 안 된다** — 속도, 대각선 정규화, 8방향 입력, 물속 감속, 장애물 충돌, 아레나 클램프, 바라보는 방향 전환이 모두 이전과 같아야 한다 |
| `hitbox-viewer.html` | 레포 루트 디버그 뷰어. 게임 런타임과 무관하지만 **뷰어가 여전히 열리고 동작하는지** 확인 |
| **무변경(회귀 확인)** | 일시정지(ESC), 마법 자동 발사·조준, 적 이동·공격, XP 픽업, 카메라 추적, HUD |

## 씬/프리팹 변경 사항 — **없음 (확정)**

**7단계에 에디터 조립 작업이 없다.** 이 슬라이스는 노드를 추가하지 않고, `PlayerController`의 `@property` 집합도 바꾸지 않는다(`frameFront`·`frameBack`·`frameLeft`·`frameRight` 네 개 그대로). 상태를 담는 필드가 불리언 4개에서 모듈 객체 하나로 바뀔 뿐인데 그 필드는 인스펙터에 노출되지 않는다.

포커스 신호는 씬이 아니라 코드가 런타임에 구독한다 — `window`와 `game.canvas`는 브라우저가 주는 것이고 `Game.EVENT_HIDE`는 엔진 이벤트다. 에디터에서 연결할 대상이 아니다.

## 에디터 연결 체크리스트 — **해당 없음 (확정)**

새 `@property`가 없으므로 연결할 것이 없다. 기존 네 프레임 슬롯이 이미 연결돼 있어야 하며(`feat/player-4dir`에서 완료), 아래 수동 테스트에서 방향 전환이 정상인지로 함께 확인된다.

## 수동 테스트 체크리스트

### A. 이동 회귀 — 먼저 확인 (상태 관리를 갈아끼웠으므로)

- [x] WASD 네 방향이 각각 정상 이동한다
- [x] 방향키(↑↓←→) 네 방향도 각각 정상 이동한다 (`KeyCode` → 축 매핑이 여기서 검증된다)
- [x] 대각선 8방향이 모두 나오고, **대각선이 직선보다 빨라 보이지 않는다**
- [x] 마주 보는 키를 함께 누르면(W+S) 그 축으로 움직이지 않는다
- [x] 키를 떼면 즉시 멈춘다 (미끄러짐 없음)
- [x] 이동 방향에 따라 캐릭터가 바라보는 그림이 바뀐다 (4방향 스프라이트 회귀)
- [x] 한강 물속에서 느려지고, 건물에 막히고, 아레나 밖으로 못 나간다 (이동 제약 회귀)

### B. 포커스 유실 — 이 슬라이스의 본론

> **두 경로를 각각 확인해야 한다.** 서로 다른 신호가 잡으므로, 하나만 보면 나머지 배선이 빠져도 통과한다.

- [x] **B-1 창 포커스 유실.** 이동키(예: W)를 **누른 채** 다른 앱 창으로 전환(Cmd+Tab) → 그 상태에서 키를 뗀다 → 게임으로 돌아온다 → **캐릭터가 혼자 걷고 있지 않다**
- [x] **B-2 창 포커스 유실 후 반대 방향.** B-1 직후 S(아래)를 누른다 → **즉시 아래로 움직인다** (고쳐지기 전에는 제자리에 섰다)
- [x] **B-3 캔버스만 포커스 유실.** W를 **누른 채** 게임 화면 **바깥의 다른 요소**를 클릭한다(프리뷰 창의 툴바·주소창 등 게임 캔버스가 아닌 곳) → 키를 뗀다 → 게임 화면을 다시 클릭한다 → **캐릭터가 혼자 걷고 있지 않고, 반대 방향 키가 먹는다**
- [x] **B-4 탭 전환.** W를 누른 채 다른 탭으로 이동 → 키를 뗀다 → 돌아온다 → 캐릭터가 걷고 있지 않다
- [x] **B-5 정상 조작이 망가지지 않았다.** 게임 화면에 포커스를 둔 채 평소처럼 이동한다 → 키가 임의로 풀리거나 끊기지 않는다 (해제가 과하게 불리면 이동이 툭툭 끊긴다)
- [x] **B-6 키를 계속 누른 채 돌아오면 멈춰 있다 — 회귀가 아니라 의도된 동작.** W를 누른 채 잠깐 포커스를 잃었다가(다른 창 클릭) **키에서 손을 떼지 않고** 돌아온다 → **캐릭터가 멈춰 있고, 그 키를 한 번 떼었다 다시 누르면 움직인다.** 브라우저는 이미 눌려 있는 키의 `keydown`을 다시 보내지 않으므로 해제한 기록을 되살릴 방법이 없다. 고치기 전에는 이 경우 계속 걸었으니 **이 지점만 이전과 동작이 다르다** — 대안은 고착을 그대로 두는 것뿐이라 이쪽을 택했다(계획 §9, `releaseAllMoveKeys` JSDoc)

### C. 리스너 정리

- [x] 게임 재시작(일시정지 메뉴 → 재시작)을 **세 번 반복**한 뒤에도 이동이 정상이다
- [x] 재시작 반복 후 B-1을 다시 해도 여전히 정상 해제된다 (리스너가 중복 등록되거나 죽은 컴포넌트에 남지 않았다)
- [x] 메뉴 → 게임 → 메뉴를 오가도 콘솔에 새 에러·경고가 없다
