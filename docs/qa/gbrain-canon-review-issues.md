## Important 1 — 「종료 코드가 0이다」가 사실이 아니다 · **수정됨**

세 곳이 잠금 실패의 종료 코드를 0이라고 적었다 — `spec/ops-gbrain.md` §6.2, 계획 §1-1, `backlog-implement-archive.md`의 F77 항목.

**리뷰어가 직접 돌려 반박했고 실측으로 확인했다. 실제 종료 코드는 1이다.**

```
$ bun src/cli.ts sources status >/dev/null 2>&1; echo $?
1
```

원인은 내 최초 측정이 틀린 것이다. 그때 `bun src/cli.ts sources status 2>&1 | head -20; echo "EXIT=$?"`로 쟀는데, 파이프라인에서 `$?`는 마지막 명령인 `head`의 종료 코드라 항상 0이 나온다. 잠금 실패는 `pglite-lock.ts`가 던지는 예외가 CLI의 단일 종료 지점까지 그대로 올라가 1로 끝난다.

**이 정정이 인과를 바꾼다.** 실패는 조용하지 않았다 — 종료 코드로 보면 시끄러웠다. 19일이 보이지 않은 진짜 이유는 **아무도 그 코드를 읽지 않았다**는 것이다. 절차가 사람 손으로 도는 단계였고, 잠금 메시지가 "그냥 MCP 도구를 쓰라"는 권유로 읽혀 실패가 아니라 안내처럼 보였으며, 갱신이 안 돼도 다음 단계가 아무것도 막지 않았다.

세 곳을 이 서술로 고쳤다. 계획 문서는 이 슬라이스가 지금 쓰는 중이라 고치는 것이 규칙에 맞고, 아카이브 줄은 영구히 남으므로 틀린 사실을 실을 수 없다.

## Important 2 — §6.2가 프로세스를 **어떻게** 종료하는지 안 적었다 · **수정됨**

절차가 PID를 **찾는** 법은 공들여 적었는데(잠금 메시지가 알려 준다) **끝내는** 명령이 없었다. 실행 가능한 절차를 표방하는 문서에서 이건 정확히 이 슬라이스가 닫으려던 종류의 구멍이다.

리뷰어가 짚은 대로 이건 이 문서에서 유일하게 OS에 의존하는 단계이기도 하다. 확인해 보니 **이 레포가 이미 §5.2·§5.6에서 다루는 함정과 같은 계열**이었다.

```
$ taskkill /F /PID 999999      # Git Bash
오류: 잘못된 인수/옵션 - 'F:/'.

$ taskkill //F //PID 999999    # Git Bash
오류: 프로세스 "999999"을(를) 찾을 수 없습니다.   ← 플래그가 제대로 넘어갔다
```

MSYS가 `/F`를 경로로 해석해 `F:/`로 바꿔 넘긴다. §5.2(하위 디렉터리 소스 거부)·§5.6(`SYMLINK_NOT_ALLOWED`)과 같은 POSIX 경로 가정 문제다.

셸별 명령을 §6.2에 넣고 그 이유를 함께 적었다. `gbrain serve`에 중단 서브커맨드가 없다는 것도 확인해 명시했다.

## 리뷰어가 실물로 확인해 준 것

고친 것 못지않게 **틀리지 않았다고 독립적으로 확인된 것**도 기록해 둔다. 다음 슬라이스가 같은 것을 다시 재지 않게 하려는 것이다.

- 레포 전체에서 `§6.2`·`§8`을 부르는 외부 참조 여덟이 전부 새 경로에서 그대로 풀린다. 구 §2·§7을 번호로 부르는 곳은 0건이라 비운 결정이 안전하다.
- 정본이 `sessions/`·`decisions/`로 나가는 링크가 0건이다(`DocLinks.test.ts:270`의 `CANON_SCOPE`가 덮는 범위).
- §5.8이 인용한 `~/gbrain/src/core/sync.ts:343`의 `SYNC_SKIP_FILES` 배열이 바이트 단위로 일치하고, 증분과 전체가 같은 상수를 탄다는 주장도 맞다(`sync.ts:367`·`import.ts:587`).
- §6.2가 인용한 잠금 메시지가 원문과 같다.
- MCP `sync_brain`에 `source`·`strategy` 인자가 없다는 것이 도구 스키마로 확인된다 — 우회 금지 근거가 사실이다.
- 테스트 파일 두 곳은 **주석만** 바뀌었고 단언과 로직이 바이트 단위로 같다.
- 자동 게이트 전부 초록(45파일 797/797 · 타입체크 `full` · `check-links`·`check-docs`·`check-meta`).
