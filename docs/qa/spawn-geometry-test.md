# QA 체크리스트 — 스폰 기하: 적을 화면 밖에서 내보낸다 (feat/spawn-geometry)

- **브랜치:** feat/spawn-geometry
- **계획 문서:** [`../development/sessions/2026-07-14-spawn-geometry-plan.md`](../development/sessions/2026-07-14-spawn-geometry-plan.md)
- **부모 문서:** [`../development/sessions/2026-07-14-map-space-roadmap.md`](../development/sessions/2026-07-14-map-space-roadmap.md)
- **대상:** 플레이어 기준 반경 350 원형 링 스폰을 버리고, **카메라 뷰 사각형 바깥 + 아레나 안**에서 해석적으로 뽑는다. 거리 기반 적 재활용과 `maxEnemies`의 의미 교정(살아 있는 적 → 교전 중인 적)을 함께 넣는다. 백로그 **F35**(벽 근처 스폰 몰림)를 닫는다.
- **성격:** 회귀 수정. `feat/map-arena`(PR #55)가 카메라 팔로우를 넣으면서 반경 350이 언제나 화면 안이 됐고, 그때부터 모든 적이 플레이어가 보고 있는 화면 한복판에서 튀어나온다.

## 2. 자동 테스트로 검증 (`tests/logic/SpawnGeometry.test.ts`)

> **통과 근거:** 피처 테스트 40/40 + 전체 스위트 483/483 (34 파일) GREEN — 코드 리뷰 3회차 반영 후. 리뷰 이슈: [`spawn-geometry-review-issues.md`](spawn-geometry-review-issues.md).

- [x] **파생 거리 유도** — `engagementRadius`는 스폰 사각형 모서리까지의 거리(`hypot(viewHalfW+margin, viewHalfH+margin)` ≈ 871px), `maxSpawnDistance`는 카메라 클램프까지 감안한 최대 거리(`hypot(2·viewHalfW+margin, 2·viewHalfH+margin)` ≈ 1605px).
- [x] **순서 불변식(안전 계약)** — 모든 종횡비(16:9·세로 창·21:9·뷰가 아레나보다 넓은 경우)와 여유값에서 `engagementRadius < maxSpawnDistance`. 이 순서가 깨지면 구석 캠핑 수정이 조용히 무효가 된다.
- [x] **여유(margin) 하한** — 0·음수·NaN이면 `MIN_SPAWN_MARGIN`으로 올린다. 하한은 적 최대 충돌 반경(40) 이상이라 적 몸통 절반이 화면 안에서 태어나지 않는다.
- [x] **`clampRecycleDistance`** — 요청값이 최대 스폰 거리보다 작으면 그 위로 올린다(스폰하자마자 회수되는 루프 방지).
- [x] **유효 둘레 클리핑** — 플레이어가 중앙이면 네 변 전부(둘레 4800), 우상단 구석이면 좌·하 두 변만 남는다(795 + 1355 = 2150). 아레나가 뷰보다 작으면 0(폴백 경로), 아레나 데이터가 없으면 뷰 사각 둘레 전체.
- [x] **사후조건 속성 테스트** — 플레이어를 아레나 전역(중앙·변·구석·클램프 경계)으로, `roll`을 0~1로 훑으며 모든 결과가 ① 뷰 밖 ② 아레나 안(적 반경 포함) ③ 최대 스폰 거리 이내를 만족한다.
- [x] **중앙 무손상 보장** — 플레이어가 열린 곳이면 모든 스폰점이 교전 반경 안이다. 즉 `maxEnemies`를 교전 중인 적으로 세도 기존 웨이브 밸런스가 그대로다.
- [x] **구석 케이스(F35)** — 우상단 구석에 붙으면 좌·하에서만 나오고 우·상에서는 절대 나오지 않는다. 벽면에 눌린 클램프 몰림이 사라진다.
- [x] **구석 relief의 출처** — 구석 스폰점의 **대부분**이 교전 반경 밖이고 평균 스폰 거리가 열린 곳의 1.5배를 넘는다. 그래서 상한을 먹지 않고, 그래서 스포너가 멈추지 않는다. (전부는 아니다 — 스폰 사각 아래변의 가장 가까운 끝은 플레이어 바로 아래 795px이라 교전 반경 871px 안이다. 그 적은 실제로 코앞이니 교전 중으로 세는 게 정직하다.)
- [x] **카메라 기준 회귀 가드** — 플레이어가 벽에 붙었을 때 스폰 사각형의 중심이 플레이어가 아니라 카메라다(플레이어 기준으로 되돌리는 리팩터를 막는다).
- [x] **비정방 아레나·종횡비 변주** — 3200×1800 아레나와 세로 창에서도 사후조건이 성립한다(축 스왑 회귀).
- [x] **퇴화 입력** — 아레나 데이터 없음, 아레나가 뷰보다 작음(가장 먼 안쪽 점으로 폴백 — 중심으로 돌아가지 않는다), `roll` −1·0·1·2·NaN, 뷰 절반 0·음수·NaN·무한대, 반경 0·40·아레나 절반 초과.
- [x] **결정성** — 같은 입력은 같은 출력.
- [x] **`canSpawn` 진리표** — 교전 상한·이동 상한 각각의 경계값, 그리고 "도착하지 않은 적은 압박 상한을 먹지 않는다"(구석 캠핑이 스폰을 멈추지 못한다).
- [x] **`classifyByDistance` 경계값** — 교전 반경 경계는 교전에 포함, 재활용 거리 경계는 아직 회수 안 함, 그리고 **거리가 비유한값이면 회수**(NaN 좌표의 유령 적이 이동 중 상한을 영구 점유하지 못하게 한다).
- [x] **카메라·플레이어 좌표 NaN·무한대 정규화** — 스폰 좌표로 NaN이 새어 나가지 않는다.
- [x] **폴백의 최대 거리 보장(전 폴백 영역)** — 폴백이 실제로 발생하는 아레나·플레이어 구성을 전부 훑으며 사후조건 ③(최대 스폰 거리 이내)을 단언한다. 스폰 직후 회수되는 무한 churn을 구조적으로 배제한다.

Cocos 배선(`EnemySpawner`·`CameraController`·`EnemyController.recycle`)은 프레임워크 의존이라 아래 수동 항목으로 검증한다.

## 3. 씬 변경 사항 (`main.scene`) — (확정)

신규 노드는 없다. 기존 `EnemySpawner` 노드에 `@property` 연결 하나를 추가하고, 나머지는 인스펙터 수치다.

| 노드 | 변경 | 값 |
|------|------|-----|
| `EnemySpawner` (기존 매니저 노드) | `Camera Controller` 프로퍼티에 게임 `Camera` 노드 연결 | `Camera`의 `CameraController` 컴포넌트 |
| `EnemySpawner` (기존 매니저 노드) | `Max Inbound` 기본값 확인 (신규) | 25 |
| `EnemySpawner` (기존 매니저 노드) | `Spawn Margin` 기본값 확인 (신규) | 100 |
| `EnemySpawner` (기존 매니저 노드) | `Recycle Distance` 기본값 확인 (신규) | 2200 |

> `Max Enemies`(20)는 이름은 그대로지만 **의미가 바뀌었다** — 이제 "살아 있는 적"이 아니라 "교전 반경(약 871px) 안에 있는 적"의 상한이다. 값은 건드리지 않는다.

## 4. 에디터 조립 레시피 — (확정)

> 신규 에셋·노드를 만들지 않으므로 조립 순서는 짧다. 프로퍼티 연결 하나가 전부다.

**목표 계층 (변경 없음 — 참고용):**

```
main (Scene)
 ↳ Camera            (CameraController — 이미 부착돼 있다)
 ↳ Canvas
    ↳ Player
    ↳ … (기존 게임 오브젝트)
 ↳ EnemySpawner      (기존 매니저 노드 — 여기에 프로퍼티 하나 연결)
 ↳ GameManager · DataManager · MapManager · …
 ↳ UICanvas
```

**만드는 순서:**

1. **`EnemySpawner` 노드 선택** — 기존 매니저 노드 계층에 이미 있다. 새로 만들지 않는다.
2. **`Camera Controller` 프로퍼티 연결** — 인스펙터의 `Enemy Spawner` 컴포넌트에서 `Camera Controller` 슬롯에 씬의 게임 **`Camera` 노드**를 드래그해 놓는다. (Cocos가 그 노드에서 `CameraController` 컴포넌트를 찾아 붙인다. HUD용 `UICamera`가 아니라 **게임 `Camera`** 다 — 잘못 연결하면 뷰 크기가 어긋나 적이 화면 안에서 스폰된다.)
3. **수치 확인** — 같은 컴포넌트의 `Spawn Margin`(100), `Recycle Distance`(2200), `Max Inbound`(25)가 기본값대로인지 확인한다. 인게임 체감으로 조정할 수 있는 밸런스 수치이며, 조정했다면 아래 6절에 기록한다.
4. **씬 저장.**

| 컴포넌트 | `@property` (인스펙터 표시) | 연결 노드·값 | 상태 |

## 6. 수동 테스트 체크리스트 (인게임)

핵심은 세 가지다. 적이 **화면 밖에서 걸어 들어오는가**, 벽·구석에서 **벽 쪽에서 솟지 않는가**, 그리고 구석에 죽쳐도 **적이 계속 몰려오는가**.

- [ ] **화면 밖 스폰 (핵심 회귀 수정)** — 게임을 시작해 가만히 서 있으면, 적이 화면 안에서 갑자기 나타나지 않고 화면 가장자리 **밖에서** 걸어 들어온다. 스폰 순간이 눈에 보이지 않는다.
- [ ] **적 몸통이 화면에서 태어나지 않는다** — 큰 적(도깨비·이무기·두억시니 — 충돌 반경 38~40)도 화면 가장자리에 몸 절반이 걸친 채 나타나지 않는다.
- [ ] **벽 근처 스폰 (F35)** — 벽에 붙어 서 있으면 벽 쪽(등 뒤)에서 적이 솟지 않는다. 열린 방향에서만 온다.
- [ ] **구석 스폰 방향** — 아레나 모서리로 가서 서 있으면 적이 **맵 안쪽 두 방향에서만** 온다. 벽 너머·모서리 쪽에서는 나타나지 않는다.
- [ ] **구석 캠핑이 통하지 않는다 (악용 차단)** — 구석에 20~30초 죽치고 있어도 적이 끊기지 않고 계속 몰려온다. 화면이 비어 가며 숨통이 트이는 일이 없다. (계획 §5.2 — `maxEnemies`가 도착하지 않은 적을 세던 것을 고쳤다.)
- [ ] **카이팅 중 스폰이 끊기지 않는다** — 아레나를 크게 돌며 도망쳐도 신규 적이 계속 나온다. 뒤에 늘어선 느린 적들이 상한을 채워 화면이 비는 일이 없다.
- [ ] **재활용은 사망이 아니다** — 멀리 떨어져 회수된 적이 **XP를 떨구지 않고** 킬 수에도 잡히지 않는다. 결과 화면의 킬 수가 실제로 죽인 수와 맞는다. 사망 연출(붉은 점멸 등)도 나오지 않는다.
- [ ] **적이 사라졌다 나타나는 것이 눈에 띄지 않는다** — 재활용 거리(2200)가 충분히 멀어, 화면 근처에서 적이 갑자기 사라지는 장면이 보이지 않는다.
- [ ] **스폰 속도·웨이브 스케일링 회귀** — 웨이브가 오를수록 적이 더 자주·더 많이 나온다(기존 동작). 열린 곳에서의 체감 밀도가 이번 변경 전과 비슷하다.
- [ ] **적 종류 분포 회귀** — 웨이브별 스폰 테이블대로 여러 종류가 섞여 나온다(`SpawnDirectorLogic` 회귀 없음).
- [ ] **원거리 적 회귀** — 구미호·이무기·물귀신이 정상적으로 발사체를 쏜다(적 발사체 풀 연결이 깨지지 않았다).
- [ ] **맵 데이터 누락 방어** — `seoul.json`의 `size`를 임시로 `[0,0]`으로 바꿔도 적이 플레이어 몸 안에서 스폰되지 않고 화면 밖에서 나온다(콘솔 경고는 뜬다). 확인 후 원복한다.
- [ ] **일시정지·레벨업 회귀** — ESC 일시정지와 레벨업 카드 선택 중에는 스폰·재활용이 멈춘다(`GameState.Playing`이 아닐 때).
- [ ] **밸런스 체감 기록** — `Spawn Margin`(100)·`Recycle Distance`(2200)·`Max Inbound`(25)를 조정했다면 최종 수치와 이유를 여기 적는다.
