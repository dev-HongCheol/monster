## 2. 씬/프리팹 변경 사항

씬 파일과 프리팹 파일은 바뀌지 않는다. 실험실이 켜지면 코드가 아래 노드를 만든다. 부모와 형제 순서는 `main.scene`을 읽어 정했다(2026-10-13).

```
Canvas
├── Camera · RegionOverlay · Obstacles · Player(SpellCaster) · … · BulletParent
├── VfxLayer            ← LabVfxSink가 BulletParent 바로 다음 형제로 붙인다(확정)
│   ├── Add             ← 가산 방출기 · 가산 스프라이트
│   └── Alpha           ← 알파 방출기 · 알파 스프라이트
├── EnemySpawner · ExperienceManager
├── VfxCompare          ← 비교판만. VfxLab이 Canvas 끝에 붙이는 격자(확정)
├── (적 · 적 탄 — 스포너가 Canvas 끝에 차례로 붙인다)
└── StatusLayer         ← StatusVfxOverlay가 Canvas의 마지막 자식으로 유지한다. 표시 노드는 이 아래에 바로 붙는다(확정)
```

- **레이어:** 새 노드는 모두 부모(Canvas)의 레이어 `DEFAULT`를 따른다. 에디터로 만든 노드가 아니라서 백로그 F47(레이어가 `UI_2D`로 새는 문제)에 걸리지 않는다.
- **상태 표시만 따로 두는 이유(확정):** 적은 스포너가 Canvas 맨 끝에 붙인다. 그래서 `VfxLayer`에 둔 노드는 적보다 먼저 그려져 적 그림에 가린다. 폭발 · 노바 · 오브는 지금 프리팹도 `BulletParent` 아래라 적 밑에 그려지므로 이 순서를 지킨다. 그러나 적 위에 붙는 상태 표시는 가리면 판정할 수 없다. 그래서 `StatusLayer`를 Canvas의 마지막 자식으로 둔다. 채우기 구간에 새 적이 Canvas 끝에 붙어도 `StatusVfxOverlay`가 매 프레임 `StatusLayer`를 맨 뒤로 다시 옮기므로 이 순서가 유지된다. 비교판의 더미 적도 같은 층 순서를 쓴다.
- **가산 머티리얼(확정):** 만들지 않는다. 방출기 · 정지 스프라이트 모두 코드로 가산이 걸렸다(§5.2 다).

## 5. 수동 테스트 체크리스트

웹 빌드는 AI가 만들고 로컬 서버를 띄운다. 빌드 폴더는 `game/build/web-lab2`이고, 서버는 `tools/web/serve_nocache.py`다(응답마다 `Cache-Control: no-store`를 붙인다. 기본 `http.server`로 띄우면 Chrome이 옛 js를 캐시해 새 빌드가 안 보인다). 주소는 `http://localhost:8080/`이다. 숫자를 재는 회차는 사용자의 Chrome에서 돌린다.

### 5.1 연기 시험 — 가장 먼저

- [x] AI가 Windows 명령줄로 웹 빌드를 만든다. 안 되면 사용자가 에디터의 빌드 패널(`Project → Build` → 플랫폼 `Web Mobile` → `Debug` 끔 → `Build`)로 만들고 폴더 위치를 알린다. 결과: 명령줄 빌드가 된다(`CocosCreator.exe --build`, 끝 코드 36이 성공).
- [x] `http://localhost:8080/`(파라미터 없음)에서 지금 게임이 그대로 돈다. 적이 나오고, 마법이 자동으로 나가고, 폭발 · 노바 · 오브가 지금 모양 그대로 뜨고, 플레이어가 피해를 받는다. 결과: 사용자 확인(2026-10-13).
- [x] `?lab=compare&method=ga`에서 터짐 후보가 격자로 뜨고, 맨 아래에 키 안내 줄이 보인다. 결과: 사용자 확인(2026-10-14). 키 안내 줄은 맨 아래가 아니라 왼쪽 위 HUD에 있다.

### 5.2 구현 첫 시간 확인 — AI가 재고 여기 적는다

| 순서 | 확인 | 결과 |
|---|---|---|
| 가 | 이펙트 없이 200마리 끔 블록: 채우는 데 걸린 시간 · 끔 블록 건너뜀 비율(5% 이하여야 판정이 유효) | 사용자 PC · 2560×1271 창(판정 크기가 아니라 비교 기록) · 켬 블록은 지금 프리팹 이펙트: 끔 블록 건너뜀 0%, 무효 블록 0. 바쁜 시간 차이 +0.03ms · 1% low 차이 +0.09ms — 지금 이펙트의 비용은 거의 없다. 채우는 시간은 결과 파일에 기록하지 않는다. 결과 파일 `magic-effect-gate-results/gate-2560x1271-max-all-20261013t134603.json`. 둘째 회차는 2차 측정 이펙트(파티클 방출기)로 쟀다. 개발자 도구의 기기 흉내(Pixel 10, devicePixelRatio 2)로 열어 캔버스가 3840×2160px이었고(판정 크기의 네 배 픽셀이라 비교 기록) 적은 200만 쟀다. 끔 블록 건너뜀 0%, 무효 블록 0, 판정 통과 — 바쁜 시간 차이 +0.29ms · 1% low 차이 +0.56ms · 건너뜀 차이 0. 켬 블록의 드로우콜은 평균 66 · 최대 101(끔 25), 방출기 최대 48 · 알갱이 최대 643. 결과 파일 `magic-effect-gate-results/gate-3840x2160-max-all-20261014t015138.json`. 셋째 회차는 같은 이펙트를 `?lab=measure&load=max`로 63 · 200 · 400 모두 쟀다. 기기 흉내 devicePixelRatio 1, 캔버스 1920×1024px. 비교판이 아직 없어 레시피 파일의 기본 후보로 돌렸으므로 §5.4 판정 스윕을 대신하지 않는다. 무효 블록 0, 끔 블록 건너뜀 0%, 적 수 셋 모두 기준 안 — 바쁜 시간 차이 63: +0.41ms · 200: +0.31ms · 400: +0.38ms, 1% low 차이 +0.89 · +0.67 · +0.59ms, 건너뜀 차이 0. 켬 블록의 드로우콜 평균 66 · 최대 101, 방출기 최대 48 · 알갱이 최대 642로 적 수와 상관없이 거의 같다 — 이펙트 수는 마법 발사 수를 따르는데, 측정 모드는 정해진 마법 묶음을 쓰고 `load=max`는 그 마법들을 최대 강화로 고정해 발사가 쿨다운대로만 나가기 때문이다. 결과 파일 `magic-effect-gate-results/gate-1920x1024-max-all-20261014t022626.json` |

### 5.3 비교판 — 방식마다(사용자)

각 URL을 열고 다음을 확인한 뒤 답 넷(계획 §8)을 이 표에 적는다. 셋째 단계는 계획 §7.2의 값이다. 아래 체크리스트는 사용자가 2026-10-13~14 여섯 방식을 판정하며 확인했다(`1`~`8` · `0` · `R` · `P`는 마지막에 따로 확인).

결론: 가 · 나 · 다 · 라 통과(라 1번은 정해진 대로 보류), 마는 표현만 통과, 바는 「없음」 — 적 위 상태 색 층으로 가며 백로그 F140으로 넘겼다. 분류색 세 가지는 모든 방식에서 어색하다는 지적이 나와 백로그 F141로 다시 정한다.

- [x] 키 안내 줄과 방식 코드 대응표가 보인다(왼쪽 위 HUD).
- [x] 판정 원(가 · 다만), 밝은 배경 조각, 겹침 1× · 4× · 셋째 단계, 「현재」 칸(가 · 다 · 나의 오브)이 보인다. 다는 겹침 대신 강화 단계 셋(반경 120 · 180 · 240)이고, 판정 원과 「현재」 노바도 열마다 함께 커진다. 마는 거쳐 가는 적 수 셋(3 · 5 · 8)이고, 칸마다 더미 적이 놓이고 번개가 왼쪽 끝 시전 자리부터 적을 차례로 거쳐 간다.
- [x] `Tab`으로 칸을 고르고 `1`~`8`로 조절하면 그 칸만 10%씩 바뀌고, `0`으로 되돌아간다.
