# QA 체크리스트 — 맵 사이즈 2배 (feat/map-size-2x)

- **브랜치:** feat/map-size-2x
- **계획 문서:** [`../development/sessions/2026-07-18-map-size-2x-plan.md`](../development/sessions/2026-07-18-map-size-2x-plan.md)
- **대상:** 서울 아레나를 각 변 ×2(2400×2400 → **4800×4800**, 면적 4배)로 넓힌다. 맵 크기를 하드코딩한 코드가 없어(배경·아레나·카메라 클램프·스폰이 전부 `map.size`에서 유도됨) 실제 변경은 데이터 두 곳(`seoul.json`의 `size`와 한강 폴리곤 14정점 ×2)과 주석 한 곳(`ObstacleLogic.ts`의 `MAX_SUBSTEPS` 근거 수치)뿐이다. 넓어진 맵에 맞춰 기존 장애물 박스 8개를 7단계 에디터에서 재배치한다(중앙 클러스터로 두지 않고 넓게 흩뿌린다). 실제 도로·랜드마크 등 콘텐츠 배치는 이 슬라이스가 아니라 후속이다 — 여기서는 **리사이즈만** 한다.

## 1. Impact Map (변경 파일별 확인 범위)

| 파일 | 변경 | 회귀 확인 범위 |
|------|------|----------------|
| `resources/data/maps/seoul.json` (수정·데이터) | `size` `[2400,2400]` → `[4800,4800]`; 한강 `regions[0].poly` 14정점 전부 ×2. `playerSpeedMul`·`enemySpeedMul`은 불변 | 맵 로드 성공, 아레나·배경·카메라 클램프가 4800 기준으로 유도됨, 한강이 넓어진 맵을 계속 가로지름 |
| `logic/ObstacleLogic.ts` (수정·주석만) | `MAX_SUBSTEPS`(33행) 근거 주석의 아레나 수치 "2400px" → "4800px"로 갱신하고 4800 대각선 기준 재검증 수치 반영. **로직·상수값 불변** | 서브스텝 분할 로직 무변경 — 자동 테스트로 회귀 없음 확인 |
| `scenes/main.scene` (수정·사용자 배치) | 기존 `Obstacles` 루트의 박스 8개를 넓어진 맵 전역으로 **재배치**(신규 노드·컴포넌트·`@property` 없음) | 재배치 후 충돌·우회가 새 좌표에서 정상, MapManager 경계·간격 경고 없음 |

> **신규 코드·노드·`@property` 없음.** `MapManager`·`RegionLogic`·`ObstacleLogic`의 순수 로직은 전부 불변이고, 장애물 좌표는 코드가 노드 바운드에서 로드 시 1회 유도하므로 박스를 옮기면 충돌이 따라온다(building-collision §2.2 계약 그대로).

## 2. 자동 테스트 — 스킵 (`pnpm wf skip-test`)

> **회귀 확인 근거:** 신규 피처 테스트는 없다(스킵). 데이터·주석 변경이 기존 테스트를 깨지 않는지 `pnpm wf start-verification`이 전체 스위트를 돌려 확인했다 — **550/550 (36 파일) GREEN**(`HanRiverHazard` 15/15·`BuildingCollision` 52/52 포함). 통과 커밋 `24cb8ea`(feat — seoul.json + ObstacleLogic.ts 주석).

**신규 순수 로직 파일이 없다.** 이 슬라이스의 변경은 데이터(JSON)와 주석뿐이고 새로 작성하는 로직이 한 줄도 없다. 기존 `tests/logic/HanRiverHazard.test.ts`는 합성 픽스처(SQUARE·NOTCHED·DIAMOND)로 `pointInPolygon`·`playerSpeedMulAt`을 검증하므로 `seoul.json` 폴리곤이 ×2로 스케일돼도 그대로 통과한다(seoul.json에 의존하지 않는다). `ObstacleLogic`의 서브스텝 분할 로직도 상수·코드가 불변이라 `BuildingCollision.test.ts`가 계속 통과한다.

따라서 새로 실패시킬(RED) 테스트가 없어 `pnpm wf skip-test "맵 크기 2배는 데이터(seoul.json size·폴리곤)와 주석만 변경 — 신규 순수 로직 파일 없음. 기존 로직·상수 불변으로 HanRiverHazard·BuildingCollision 테스트가 회귀 없이 통과. 폴리곤 스케일·크기 반영은 7단계 인게임 수동으로 검증(§6)."`로 사유를 기록한다.

> **전체 스위트 GREEN 확인(6단계):** 신규 테스트는 없지만 데이터·주석 변경이 기존 테스트를 깨지 않는지 `pnpm wf start-verification`이 전체 스위트를 돌려 확인한다. 통과 근거(M/M + 커밋 SHA)는 이 절 머리에 기재한다.

## 3. 데이터 변경 (`seoul.json`) — (확정)

### 3.1 `size` — 4800×4800

`"size": [2400, 2400]` → `"size": [4800, 4800]`. `MapManager._applyMap`이 이 값에서 아레나(`{width, height}`)·배경 크기·물 렌더 UITransform 기준을 전부 유도하므로, 이 한 줄이 아레나 경계·카메라 클램프·배경 스프라이트 크기를 동시에 4800으로 넓힌다(코드 무변경).

### 3.2 한강 폴리곤 ×2 — `regions[0].poly` 14정점

정점을 전부 ×2로 스케일한다. 정점이 새 벽(±2400 = 새 halfW)에 정확히 앉으므로 `MapManager`의 경계 경고가 뜨지 않고, 스케일 후 최대 |y|는 1200으로 새 halfH(2400) 안이다. 강 폭·형태의 비율은 그대로라 넓어진 맵을 계속 대각선으로 가로지른다.

| 현재 | ×2 |
|------|-----|
| [-1200, 370] | [-2400, 740] |
| [-700, 250] | [-1400, 500] |
| [-200, 20] | [-400, 40] |
| [0, -30] | [0, -60] |
| [300, 70] | [600, 140] |
| [700, 250] | [1400, 500] |
| [1200, 600] | [2400, 1200] |
| [1200, 160] | [2400, 320] |
| [700, -190] | [1400, -380] |
| [300, -370] | [600, -740] |
| [0, -470] | [0, -940] |
| [-200, -420] | [-400, -840] |
| [-700, -190] | [-1400, -380] |
| [-1200, -70] | [-2400, -140] |

`playerSpeedMul`(0.5)·`enemySpeedMul`(1.0)은 감속 세기라 맵 크기와 무관 — 그대로 둔다.

## 4. 씬 변경 사항 (`main.scene`) — 장애물 재배치 (확정)

**신규 노드 없음.** building-collision이 만든 `Obstacles` 루트(게임 `Canvas` 자식, RegionOverlay 다음·Player 앞, DEFAULT 레이어)와 그 아래 박스 8개(`Box_N1`~`Box_N4`, `Box_S1`~`Box_S4`)를 **그대로 두고 위치만** 넓어진 맵에 맞춰 옮긴다. 루트·박스의 Layer·Anchor·Color·Content Size·`@property` 연결은 손대지 않는다.

| 노드 | 변경 | 값 |
|------|------|-----|
| `Obstacles` (기존 루트) | 변경 없음 | Position (0, 0) 유지 — 자식 좌표가 아레나 좌표와 일치하는 기준점 |
| `Box_N1`~`Box_S4` (기존 ×8) | **Position만** 재배치 | 아래 §5 재배치표(시작값). Content Size·Layer·Anchor 불변 |

## 5. 에디터 재배치 레시피 — (확정 · 씬에 적용됨)

> **적용 상태(2026-07-19):** 아래 ×2 좌표는 사용자 요청으로 `main.scene`에 **직접 반영돼 커밋됐다**(8개 박스 `_lpos` 수정, 신규 노드·`.meta` 없음). 따라서 7단계에서 수동 재배치는 필요 없고, **인게임 동작 확인 + 필요 시 Cocos에서 미세 튜닝**만 하면 된다. 손 편집은 Cocos 시각 검증을 건너뛰므로, `PR 승인` 전에 Cocos로 한 번 열어 넓어진 배경·한강 대비 박스 위치를 눈으로 확인하길 권한다(§7 육안 항목).

> 아래는 적용된 값과 그 산출 근거 기록이다. Cocos에서 조정하려면 Hierarchy에서 `Obstacles ↳ Box_*`를 선택해 Inspector의 **Position만** 바꾼다. Content Size·Layer(DEFAULT)·Anchor(0.5,0.5)·Scale(1,1)은 building-collision 세팅 그대로 유지한다(§4 계약). 좌표는 손 타이핑이 아니라 에디터에서 옮겨도 되며, 충돌 색인은 `MapManager`가 노드 바운드에서 맵 로드 1회에 다시 유도한다.

**시작값 산출 근거 — 기존 위치 ×2.** 넓어진 맵의 물 밴드·벽도 함께 ×2로 커졌지만 박스 절대 크기(240×160 등)는 그대로다. 기존 위치를 ×2로 옮기면 기하가 균일하게 2배가 되어 박스와 물가·벽 사이 여유가 **줄지 않고 늘어난다**(같은 절대 크기 박스가 2배 넓어진 공간에 놓이므로). 그래서 이 시작값은 building-collision에서 검증된 상대 배치를 그대로 물려받으면서 넓은 맵에 흩뿌려진 형태가 된다. 아래 표의 값은 전부 새 물 밴드(§3.2 폴리곤) 바깥·새 벽(±2400)에서 여유를 두고 앉는다.

| 노드 | 기존 Position | **새 Position (×2)** | Content Size(불변) | 비고 |
|------|--------------|----------------------|--------------------|------|
| `Box_N1` | (-800, 700) | **(-1600, 1400)** | 240 × 160 | 강북 서측 |
| `Box_N2` | (-250, 500) | **(-500, 1000)** | 300 × 140 | 강북 중앙 |
| `Box_N3` | (350, 880) | **(700, 1760)** | 200 × 200 | 강북 동측 상단 |
| `Box_N4` | (850, 680) | **(1700, 1360)** | 280 × 120 | 강북 동측 — 우측 물 경계가 위로 올라오므로(새 밴드 y≈710 @x=1700) 더 내리지 말 것 |
| `Box_S1` | (-850, -600) | **(-1700, -1200)** | 260 × 160 | 강남 서측 |
| `Box_S2` | (-200, -800) | **(-400, -1600)** | 300 × 150 | 강남 중앙 |
| `Box_S3` | (400, -750) | **(800, -1500)** | 220 × 220 | 강남 동측 |
| `Box_S4` | (860, -500) | **(1720, -1000)** | 240 × 140 | 강남 동측 — 우측 벽(2400)과 560px 간격 유지 |

> **넓어진 외곽으로 더 흩뿌리기(선택, 7단계 체감).** ×2 시작값은 박스가 ±1840 안쪽에 모여 있어 외곽 링(±1900~2300)이 비어 있다. 맵을 채워 나가는 후속 콘텐츠 슬라이스가 이 공간을 쓰지만, 이 슬라이스에서 카이팅 룸 체감상 더 벌리고 싶으면 박스를 외곽으로 밀어도 된다. 단 하드 제약(한 변 ≤ 300px, 상호·벽 통행 간격 ≥ 200px, 물 밴드·벽에서 떨어뜨림)을 지킨다 — 어기면 콘솔 경고가 뜬다(코드가 색인 시 검증). 재배치가 물 폴리곤을 침범하지 않는지는 §6 육안 항목으로 확인한다.

## 6. 에디터 연결 체크리스트 (`@property`) — (확정)

| 컴포넌트 | `@property` | 연결 노드 | 상태 |
|----------|-------------|-----------|------|
| — | — | — | 신규·변경 연결 없음 |

> 이 슬라이스는 새 `@property` 연결을 추가하지 않는다. `MapManager.obstaclesRoot`는 building-collision에서 이미 `Canvas ↳ Obstacles`에 연결돼 있고, `MapManager.backdropSprite`는 여전히 미연결(map-arena에서 미연결로 남음 — 배경 스프라이트는 F41에서 붙는다)이다. 배경·물·아레나 크기는 전부 `seoul.json`의 `size`에서 유도되므로 크기 변경에 추가 배선이 필요 없다.

## 7. 수동 테스트 체크리스트 (인게임)

- [] **아레나 경계·카메라 클램프 확대** — 맵 끝까지 이동하면 카메라가 새 벽(±2400)에서 멈춘다. 4800×4800 전역을 팬해 돌아다닐 수 있고, 이전 2400 크기의 절반 지점에서 벽에 막히지 않는다.
- [x] **배경 스프라이트 확대** — 배경이 4800×4800으로 덮인다. placeholder 배경은 2배로 늘어나 흐릿할 수 있는데, 이는 최종 아트(F41)가 해결할 사안이라 이 슬라이스에서는 허용한다(맵 밖 빈 공간·검은 테두리가 보이면 배경이 크기를 안 따라온 것 → `MapManager._sizeBackdrop`·`backdropSprite` 배선 확인).
- [x] **한강 횡단 유지** — 반투명 파랑 강이 넓어진 맵을 계속 대각선으로 가로지르고, 양쪽 강안이 새 벽(±2400)에 닿는다. 강이 맵 가운데로 뜨거나 한쪽 벽에 안 닿으면 폴리곤 스케일이 `size`와 안 맞은 것(둘은 같은 원점 중심 공간 — §3.2).
- [x] **물속 감속 정상** — 넓어진 강에 들어가면 플레이어가 느려지고(0.5×) 나오면 즉시 원속도로 복귀한다. 강이 커진 만큼 건너는 데 걸리는 거리·시간이 늘어난다 — 비대칭 감속(플레이어만)이 체감상 과한지 관찰(§계획 5, 과하면 후속 수치 튜닝).
- [x] **재배치 장애물 충돌·우회** — 옮긴 박스 8개에서 플레이어가 표면에서 멈추고(파고들기 없음) 벽면을 따라 미끄러지며, 적 4종(추격·지그재그·유격·돌진)이 박스를 통과하지 않고 돌아 나와 플레이어에게 온다. 새 좌표에서도 building-collision의 충돌·우회 동작이 그대로 유지된다.
- [x] **시각=충돌 일치** — 막히는 위치가 눈에 보이는 박스 표면과 일치한다. 옮긴 박스가 허공에서 막히거나 그림을 통과하면 재배치 중 Layer가 틀어진 것(DEFAULT 확인).
- [x] **박스가 물 위에 없음(육안)** — 재배치한 박스가 넓어진 한강(반투명 파랑) 위에 걸치지 않는다. §5 ×2 시작값은 물 밖에 앉지만, 외곽으로 옮겼다면 물가 침범을 눈으로 확인한다.
- [x] **MapManager 콘솔 경고 없음** — 맵 로드 시 경계 밖·통행 간격 200px 미만·한 변 300px 초과·물 구역 정점 아레나 밖 경고가 뜨지 않는다(배치가 하드 제약 안). 경고가 뜨면 해당 박스를 제약 안으로 되돌린다.
- [x] **스폰 정상(카메라 상대)** — 적이 여전히 카메라 뷰 밖에서 스폰돼 화면 안으로 걸어 들어온다. 맵이 4배 넓어졌어도 스폰은 카메라 상대라 플레이어 주변 적 밀도는 그대로다(넓은 맵에서 지속 카이팅이 더 쉬운지 체감 관찰 — F48과 같은 축).
- [x] **일시정지/레벨업 회귀** — 넓어진 맵 어디서든 ESC 일시정지·레벨업 카드가 정상 동작하고, 재개 시 이동·충돌·물 감속이 올바르게 이어진다.
