# QA 체크리스트 — 건물 충돌 최소판 (feat/building-collision)

- **브랜치:** feat/building-collision
- **계획 문서:** [`../development/sessions/2026-07-16-building-collision-plan.md`](../development/sessions/2026-07-16-building-collision-plan.md)
- **대상:** 에디터에 배치한 낮은 장애물 박스(볼록 축정렬 사각형, 한 변 ≤ 300px)가 플레이어와 적의 **이동만** 막는다 — 발사체·근접 부채꼴은 통과한다(D2: 막으면 적 12종 중 6종이 무력화된다). 이동 결과가 장애물과 겹치면 최소 침투 축으로 밀어내고 막힌 축만 소거해 벽면을 따라 미끄러진다(collide-and-slide). 충돌 사각형 좌표는 손으로 적지 않고 씬 노드의 위치·UITransform 크기에서 로드 시 1회 유도한다 — 에디터에서 노드를 옮기면 충돌이 따라오므로 시각과 충돌이 어긋날 수 없다(§2.2).

## 2. 자동 테스트로 검증 (`tests/logic/BuildingCollision.test.ts`)

> **통과 근거:** 피처 테스트 15/15 + 전체 스위트 513/513 (36 파일) GREEN. 통과 커밋 `06881b6`(코드리뷰 반영 포함).

- [x] 장애물 없음(빈 배열) → to 그대로 (기존 이동 회귀 없음).
- [x] 정면 진입 → 표면에서 radius만큼 떨어져 멈춤.
- [x] 비스듬 진입 → 막힌 축만 소거, 진행 축 이동은 보존(미끄러짐).
- [x] 코너 진입 → 최근접점 방향(대각) 밀어내기로 끼임 없이 모서리 통과(축 스냅이면 코너 거리 검증이 깨진다).
- [x] from이 장애물 내부(스폰 겹침) → 최근접 면 밖으로 밀어냄.
- [x] 고속 이동(step ≫ radius) → 얇은 장애물 관통(터널링) 없음.
- [x] 붙지 않은 장애물 2개 사이 통행 폭(200px) 통과.
- [x] 재해소 무변화 — 해소된 위치를 같은 인자로 다시 해소하면 그대로(어기면 벽에 붙은 매 프레임 위치가 튀는 진동).
- [x] to NaN → 원위치 / from NaN → to 그대로 / radius 0 이하 → to 그대로(유령 충돌·무한 분할 없음).
- [x] 입력(from·to·obstacles) 무변형(F36 할당 위생 계약).
- [x] 겹치게 배치된 장애물 2개(제약 위반 데이터) → 2패스로 비침투 위치 도달 (코드리뷰 M-5).
- [x] 내부 겹침 + 이동(to ≠ from) → 최근접 면 탈출 우선 (코드리뷰 M-5).
- [x] 병리적 입력(거대 이동 × 극소 radius) → 서브스텝 상한(64)으로 즉시 완주 (코드리뷰 M-5).

MapManager의 씬 색인·검증(미연결 경고·비활성 노드 스킵·UITransform 없음/크기 0 스킵·scale ≠ (1,1) 경고·angle ≠ 0 경고·루트 scale/angle 경고·한 변 300px 초과 경고·아레나 경계 밖 경고·통행 간격 200px 미만 경고)과 이동 배선 5곳은 cc 프레임워크 의존이라 아래 수동 항목으로 검증한다.

## 3. 씬 변경 사항 (`main.scene`) — (확정)

**실제 씬 구조(2026-07-17 main.scene 파싱으로 확인):** 게임 `Canvas`(DEFAULT, lpos 640×360)의 자식 순서는 `Camera → RegionOverlay → Player → DataManager → I18n → WaveManager → DeckManager → GameManager → BulletParent → EnemySpawner → ExperienceManager`이고 전부 DEFAULT 레이어다. `MapManager`는 `Canvas`의 형제(루트 자식) 노드다.

2D는 뒤 형제일수록 위에 그려지므로, 장애물이 물(RegionOverlay) 위·플레이어 아래에 깔리려면 `Obstacles` 루트를 **`RegionOverlay`와 `Player` 사이**에 둔다. 런타임 적·발사체는 나중에 붙는 자식이라 자연히 장애물 위에 그려진다.

| 노드 | 변경 | 값 |
|------|------|-----|
| `Obstacles` (신규 루트) | 게임 `Canvas` 자식, **RegionOverlay 다음·Player 앞** 형제 순서, Layer=**DEFAULT** | Position **(0, 0)** — 자식 좌표가 아레나 좌표와 일치하는 기준점 |
| `Box_*` (신규 ×8) | `Obstacles`의 자식 Sprite 박스 | 아래 §4 배치표(시작값) |

## 4. 에디터 조립 레시피 — (확정)

> 사용자가 문서만 보고 세팅할 수 있게 순서·수치를 준다. 배치 수치는 시작값이며, 하드 제약(한 변 ≤ 300px, 통행 간격 최소 200px, 물 구역·아레나 벽에서 떨어뜨림 — 계획 §2.1) 안에서 7단계 체감으로 배경에 맞춰 조정한다. 제약을 어기면 콘솔 경고가 뜬다(코드가 색인 시 검증).

**목표 계층 (main.scene 관련 부분):**

```
main (Scene)
 ↳ Canvas              (게임, DEFAULT, lpos 640×360)
    ↳ Camera           (기존)
    ↳ RegionOverlay    (기존 — 물 폴리곤 렌더)
    ↳ Obstacles        (신규 루트 — RegionOverlay 다음, Player 앞)
       ↳ Box_N1 … Box_S4   (신규 ×8 — 단색 박스 Sprite, 시각이자 충돌 출처)
    ↳ Player           (기존, DEFAULT)
    ↳ … 매니저들 · BulletParent (기존)
 ↳ MapManager          (기존 — Canvas 형제. obstaclesRoot 연결 대상)
```

**만드는 순서:**

1. **`Obstacles` 루트 생성** — 게임 `Canvas` 우클릭 → `Create → Empty Node`, 이름 `Obstacles`. Inspector에서 Layer **`DEFAULT`**, Position **(0, 0, 0)** 확인. (루트가 원점이어야 자식의 로컬 좌표가 곧 아레나 좌표가 된다.)
2. **형제 순서 조정** — Hierarchy에서 `Obstacles`를 `RegionOverlay` **바로 다음**(= `Player` 앞)으로 드래그. 뒤 형제일수록 위에 그려지므로 박스가 물 위·플레이어/적 아래에 깔린다.
3. **첫 박스 생성** — `Obstacles` 우클릭 → `Create → 2D Object → Sprite`, 이름 `Box_N1`. **⚠ F47 주의: 이 메뉴는 Layer를 `UI_2D`로 붙인다 — 만들자마자 Layer를 `DEFAULT`로 교정한다.** UI_2D로 새면 고정 UICamera가 다른 배율로 그려서, 충돌은 노드의 실제 좌표에서 걸리는데 그림은 엉뚱한 곳에 떠 — 플레이어가 아무것도 없는 허공에 막힌다.
4. **박스 시각 세팅** — SpriteFrame은 생성 기본값(`default_sprite`) 유지, Sprite `Color`를 무채색 회색 **(110, 110, 110, 255)** 으로(시작값 — 배경·물과 구분되는 시인성 체감으로 조정).
5. **크기·위치 세팅** — `UITransform` Content Size를 아래 표의 크기로, Anchor **(0.5, 0.5)**, Position 표대로. Content Size를 Inspector에서 바꾸면 Sprite Size Mode가 자동으로 CUSTOM이 된다(Cocos 3.8 매뉴얼). **Scale은 (1, 1) 고정 — 크기는 Content Size로만 조절한다.** 색인이 contentSize만 읽으므로 Scale로 키우면 그림은 커지는데 충돌은 원래 크기라 "보이는 벽의 절반만 단단한" 어긋남이 생긴다(코드가 경고를 띄운다).
6. **나머지 박스 복제** — `Box_N1`을 Ctrl+D로 복제해 이름·Position·Content Size를 표대로 조정한다(복제본은 Layer·Color·Anchor를 그대로 물려받는다).
7. **`@property` 연결** — `MapManager` 노드 선택 → Inspector의 `obstaclesRoot`에 `Obstacles` 노드를 드래그 연결(§5 표).

**박스 배치표 (시작값 — 물 밴드(한강)와 아레나 벽(±1200)을 피하고 상호 간격 ≥ 200px):**

| 노드 | Position | Content Size | 비고 |
|------|----------|--------------|------|
| `Box_N1` | (-800, 700) | 240 × 160 | 강북 서측 |
| `Box_N2` | (-250, 500) | 300 × 140 | 강북 중앙 |
| `Box_N3` | (350, 880) | 200 × 200 | 강북 동측 상단 |
| `Box_N4` | (850, 680) | 280 × 120 | 강북 동측 — 물 경계가 우측으로 갈수록 올라오므로(y≈453 @x=990) 더 내리지 말 것 |
| `Box_S1` | (-850, -600) | 260 × 160 | 강남 서측 |
| `Box_S2` | (-200, -800) | 300 × 150 | 강남 중앙 |
| `Box_S3` | (400, -750) | 220 × 220 | 강남 동측 |
| `Box_S4` | (860, -500) | 240 × 140 | 강남 동측 — 우측 벽과 220px 간격 유지 |

> 대교 예정지(F49)는 아직 미정이다 — 박스가 전부 물가에서 100px 이상 떨어져 있어 강 횡단 축(다리 후보 자리)을 막지 않는다. F49 착수 시 다리 진입부와 겹치는 박스만 에디터에서 옮기면 된다(코드 무변경).

## 5. 에디터 연결 체크리스트 (`@property`) — (확정)

| 컴포넌트 | `@property` | 연결 노드 | 상태 |
|----------|-------------|-----------|------|
| `MapManager` (MapManager 노드) | `obstaclesRoot: Node` | `Canvas ↳ Obstacles` | ❌ |

> 연결은 이 1개뿐이다. 장애물 데이터는 `MapManager`가 `Obstacles`의 자식들에서 로드 시 1회 유도해 싱글톤(`MapManager.instance.obstacles`)으로 노출하고, `PlayerController`·`EnemyController`가 그 값을 읽는다(추가 `@property` 연결 없음). 미연결이면 콘솔 경고 1회 + 장애물 없이 정상 동작한다(장애물은 게임 성립의 필수 요소가 아니라 loud-fail로 끄지 않는다 — 계획 §4.2).

## 6. 수동 테스트 체크리스트 (인게임)

- [ ] **정면 막힘** — 박스로 걸어가면 표면에서 멈춘다(파고들기·밀려 튕김·떨림 없음).
- [ ] **미끄러짐** — 박스 면에 비스듬히 밀면 벽면을 따라 자연스럽게 미끄러진다(정지하지 않음).
- [ ] **코너 통과** — 모서리를 스치며 돌 때 끼임·진동 없이 부드럽게 돌아 나간다.
- [ ] **시각=충돌 일치 (F47 회귀 방지)** — 막히는 위치가 눈에 보이는 박스 표면과 일치한다. 허공에서 막히거나 그림을 통과하면 박스 Layer가 `UI_2D`로 샌 것 → `DEFAULT`로 교정.
- [ ] **적 4종 이동** — 추격(처녀귀신 등)·지그재그(어둑시니)·유격(구미호)·돌진(불가사리)이 박스를 통과하지 않고 벽을 타고 미끄러진다.
- [ ] **돌진 텔레그래프 체감(§9 관찰)** — 불가사리 돌진 경로에 박스가 끼면 벽을 타거나 벽 앞에서 멈춘다. 텔레그래프와 실동선이 어긋나 보이면 돌진 동선 상 박스 밀도를 낮춘다(배치 조정, 코드 무변경).
- [ ] **접촉 적 정체 체감(§5 위험)** — 접촉 피해형 적이 박스 뒤에 정체돼 압박이 눈에 띄게 빠지면 배치 밀도를 낮춘다.
- [ ] **발사체 통과 (D2)** — 플레이어 발사체·적 발사체가 박스를 그대로 통과한다. 근접 휘두르기 부채꼴도 박스 너머로 명중한다(의도 — 시야 차단 없음).
- [ ] **XP 오브 통과** — 박스 너머·안쪽에 떨어진 오브가 자석 범위에서 정상 획득된다(픽업은 장애물 무시).
- [ ] **화면 밖 스폰 밀어내기** — 장애물 위 스폰이 순간이동으로 보이지 않는다(화면 밖에서 해소되므로 관찰상 이상 없음이 정상).
- [ ] **물 구역 겹침 육안 확인** — 박스가 한강(반투명 파랑) 위에 없다(계획 §7 판단 4 — 코드 검사 없음, 눈으로 확인).
- [ ] **데이터 방어 — `obstaclesRoot` 미연결(임시 조작)** — 연결을 비우면 콘솔 경고 1회 + 장애물 없이 정상 동작한다(조용한 무막힘이 아니라 소리를 낸다. 확인 후 원복).
- [ ] **데이터 방어 — Scale 조작(임시 조작)** — 박스 하나의 Scale을 (2, 2)로 키우면 콘솔 경고가 뜨고, 충돌은 원래 Content Size 크기로 걸린다(확인 후 원복).
- [ ] **데이터 방어 — 300px 초과(임시 조작)** — 박스 하나의 Content Size를 400×400으로 키우면 콘솔 경고가 뜨되 충돌은 유지된다(확인 후 원복).
- [ ] **데이터 방어 — 통행 간격 위반(임시 조작)** — 박스 하나를 다른 박스에서 100px 간격까지 끌어다 붙이면 두 노드 이름이 든 간격 경고가 뜬다(좁은 복도는 D4 위반이자 해소 1패스 전제 붕괴 신호. 확인 후 원복).
- [ ] **박스 비활성화 = 충돌도 꺼짐(임시 조작)** — 박스 하나의 active를 끄면 그림과 충돌이 함께 사라진다(그림 없는 자리에서 막히는 투명 벽 없음 — 코드리뷰 I-1. 확인 후 원복).
- [ ] **데이터 방어 — 회전 조작(임시 조작)** — 박스 하나의 angle을 45°로 돌리면 콘솔 경고가 뜨고, 충돌은 축정렬 그대로다(확인 후 원복).
- [ ] **일시정지/레벨업 회귀** — 박스 옆에서 ESC 일시정지·레벨업 카드가 정상 동작하고, 재개 시 이동·충돌이 올바르게 이어진다.
