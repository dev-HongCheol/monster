# QA: UI 폰트 실행 탐침 (ui-font-probe)

> - **브랜치:** feat/ui-font-probe
> - **계획:** [2026-11-01-ui-font-probe-plan.md](../development/sessions/2026-11-01-ui-font-probe-plan.md)
> - **요약:** 본문 폰트 후보 둘(Pretendard · Noto Sans KR)을 Cocos의 실제 Label로 그린 판정 화면(`?lab=font`)에서 사용자가 이름을 모른 채 고른다. 같은 화면에서 결과 화면의 글자 단계와 줄 높이, 최소 글자를 정한다. 측정 모드(`?lab=measure&off=ui`)는 HUD 노드 전체를 켠 블록과 끈 블록의 바쁜 시간 차이(UI 몫)와 폰트 첫 표시를 잰다. 실험실은 URL 파라미터로만 켜지고, 이펙트 실험실과 같이 레시피 파일 `vfx-lab.json`이 없는 빌드에서는 꺼진다.

## 2. 씬/프리팹 변경 사항

씬 파일과 프리팹 파일은 바뀌지 않는다. `?lab=font`이고 오류가 없으면 `SpellCaster`가 `Player` 노드에 `FontProbe` 컴포넌트를 붙이고, `FontProbe`가 아래 노드를 코드로 만든다. 부모와 형제 순서는 `main.scene`을 읽어 정했다(2026-11-04).

```
UICanvas                 [UI_2D] (640,360) — 화면 고정 UI. UICamera가 그린다
├── UICamera
├── HUD                  ← lab=font에서는 hudControl로 끈다(웨이브 · 타이머 · 레벨 · HP · XP · 마법 슬롯)
├── FontProbe            ← (확정) HUD 바로 다음 형제, 1280×720. 일시정지 화면(PauseRoot)이 이 위에 그려진다
│   ├── Columns          ← (확정) 줄 노드(Row_1-가 … Row_6 · Row_4-en, 둘째 화면 Row_b-*)가 열마다 하나씩
│   │                       왼쪽 열 줄의 왼쪽 끝 x −608 · 오른쪽 열 x +16 · 폭 592. 패널 줄은 줄 노드에 #161d2e 패널
│   │                       띠보다 먼저 만든다 — 형제 차례가 뒤일수록 위에 그려지므로 띠가 언제나 줄 위에 보인다
│   ├── TopBand          ← (확정) 위 띠. 왼쪽 유효 · 무효, 오른쪽 숫자판, 둘째 줄에 열 이름표. 엔진 기본 글꼴
│   ├── BottomBand       ← (확정) 아래 띠. 키 안내 한 줄과 알림 한 줄. 엔진 기본 글꼴
│   ├── BandLabel        ← (확정) 「폰트 불러오는 중 n/6」 표시. 준비되면 꺼진다
│   └── Questions        ← (확정) K로 저장한 뒤 채팅으로 답할 질문. 아무 키나 누르면 닫힌다
├── CardSelectPanel
├── DeathOverlay
└── PauseRoot
```

- **레이어(확정):** 새 노드는 모두 `UI_2D`로 둔다(`FontProbe._node`). 코드로 만든 노드의 기본 레이어는 `UICamera`가 그리지 않는 쪽이라, 부모를 따르지 않으면 화면에 나오지 않는다.
- **열 좌표(확정):** 1280에서 바깥 여백 32 × 2와 열 사이 32를 빼고 둘로 나눠 열 폭 592px다. 열 중심은 UICanvas 기준 x = ±312다. 폰트가 하나면 열 하나를 x = 0에 둔다. 줄은 위 띠 아래(y = 328)부터 줄 사이 8px로 쌓고, 두 열의 같은 줄은 두 열 가운데 높은 쪽에 맞춘다 — 두 열의 패널이 크기 · 자리가 같아야 대비가 같다.
- **HUD를 끄는 이유:** 위쪽 웨이브 · 타이머 · 레벨 라벨이 위 띠 · 열과 겹치고, 판정 화면은 HUD 숫자를 2번 줄에서 따로 그린다.

## 3. 에디터 연결 체크리스트

새 `@property`가 없다. 판정 화면 · 측정 모드는 이미 연결된 프로퍼티를 읽기만 하고, HUD 손잡이는 `HudController`가 코드로 맡긴다.

| 컴포넌트(노드) | 프로퍼티 · 연결 | 쓰는 곳 | 상태 |
|---|---|---|---|
| `SpellCaster`(Player) | `startingSpellIds` | font · measure에서 `MEASURE_SPELL_IDS`로 바꿔 쏜다. 인스펙터 값은 고치지 않는다 | ✅ 기존 연결 |
| `HudController`(UICanvas/HUD) | 라벨 넷(웨이브 · 타이머 · 레벨 · HP) | 측정 모드가 폰트를 입히고 문자열을 쓴다 | ✅ 기존 연결 |
| `resources/fonts/*.ttf` | Cocos가 TTF를 `TTFFont` 자산으로 가져온다 | 사용자가 에디터를 열면 `.meta`가 생긴다(AI는 만들지 않는다) | ✅ (확정) 후보 빌드 · 최종 빌드 모두 Cocos가 가져와 `.meta`를 만들었고, 판정 화면 · 측정 모드가 그 폰트로 그렸다 |

## 5. 수동 테스트 체크리스트

웹 빌드는 사용자가 만들고(명령줄 빌드가 되면 AI가 만든다), AI가 로컬 서버를 띄운다. 서버는 `tools/web/serve_nocache.py`다(응답마다 `Cache-Control: no-store`). 서버는 빌드 폴더 하나만 내보내므로, AI가 `tools/ui/embed-1280x720.html` 파일을 빌드 폴더 맨 위(`index.html` 옆)에 복사한 뒤 `http://127.0.0.1:8080/embed-1280x720.html?lab=font`로 연다. 틀 페이지의 쿼리는 그대로 빌드에 넘어간다. 숫자를 재고 눈으로 판정하는 회차는 사용자의 Chrome에서 한다.

### 5.1 구현 첫날 확인 — AI가 확인하고 여기 적는다

| 순서 | 확인 | 결과 |
|---|---|---|
| 가 | Pretendard의 `tnum`이 단일 치환인가. 아니면 멈추고 「타이머 숫자만 다른 폰트를 쓸지」를 사용자와 다시 정한다 | 단일 치환이다(GSUB lookup 53, 형식 1 — 굵기 셋 모두). 기본 숫자는 비례 폭이라(400 굵기 「1」 898 · 「0」 1220) 굽기가 필요하다. Noto Sans KR은 `tnum` 기능이 없고 기본 숫자가 이미 같은 폭(521)이다(2026-11-04) |
| 나 | 두 후보 원본의 힌팅 표(`fpgm` · `prep` · `cvt ` · `gasp`) 유무와, 맞추려고 `--no-hinting`을 썼는가 | 상태가 다르다 — Pretendard는 넷 다 없고, Noto Sans KR은 `prep` · `gasp`가 있다. 그래서 둘 다 힌팅을 빼고 `gasp`도 뺐다. `gasp`가 남으면 Windows가 작은 크기에서 두 후보를 다른 방식으로 그려, 판정이 폰트가 아니라 그리기 설정을 비교하게 된다(2026-11-04) |
| 다 | 서브셋 스크립트 자체 검사 일곱 통과(후보 실행은 「검사 통과」만 적는다 — 크기와 예약 이름 목록은 원본 폰트를 드러낸다) | 검사 통과 — 후보 파일 6개. OTS 검사(8)와 겹친 윤곽 플래그 검사도 통과했다(2026-11-04) |
| 라 | `opentype-sanitizer` 설치 여부를 사용자에게 물었는가와 답 | 물었고 사용자가 설치를 골랐다. 9.2.0을 설치해 자체 검사 8로 돌린다(2026-11-04) |
| 마 | 엔진이 넣은 `@font-face`가 `document.fonts`에 나타나는가, 그 `family` 값의 따옴표 모양 | 나타난다. `family` 값은 따옴표 없이 `<파일 이름>_LABEL`이고, 후보 빌드의 여섯 파일이 모두 `loaded`였다. 그래서 `fontFaceStatus`를 그대로 쓴다(2026-11-04, 헤드리스 Chrome 151 · 후보 빌드) |
| 바 | Cocos 3.8 Label 외곽선 폭의 뜻(매뉴얼)과, HTML 판정판의 2px 외곽선에 맞춘 값 | 매뉴얼에는 폭의 뜻이 없어 엔진 3.8.8 소스로 확인했다. 캔버스 선 두께를 `outlineWidth × 2`로 긋고 그 위에 채우기를 덮으므로(`assembler/label/text-processing.ts:536-543` · `:664`) 글자 바깥에 `outlineWidth`px가 보인다. CSS 2px 외곽선은 바깥에 약 1px가 보이므로 「1단계」는 `outlineWidth = 1`, 「후보 폭」은 2다. 그림자는 엔진이 y를 뒤집어 넘기므로(`:674`) CSS `0 1px 2px`는 `shadowOffset (0, −1)` · `shadowBlur 2`다(2026-11-04) |

### 5.2 연기 시험 — 후보 빌드에서 가장 먼저

- [x] 파라미터 없는 주소에서 지금 게임이 그대로 돈다. 적이 나오고, 마법이 나가고, HUD 숫자가 바뀌고, 플레이어가 피해를 받는다. 결과: 최종 빌드에서 AI가 적이 나오고 타이머가 흐르는 것을 헤드리스 Chrome으로 봤고, 사용자가 적에게 맞아 HP가 줄어드는 것을 확인했다(2026-11-04).

외곽선 관찰에는 1층 HTML 판정판과 그리는 방식이 다르다는 점을 함께 본다. Chrome의 `-webkit-text-stroke`는 채우기 위에 외곽선을 그려 글자 안쪽을 덮지만, Cocos는 외곽선을 먼저 그리고 채우기를 위에 그려 글자를 깎지 않는다(엔진 `assembler/label/text-processing.ts:536-543`). 그래서 같은 두께로 맞춰도 1층의 HTML 판정이 더 보수적이었다.

문장 속 고정 폭 숫자를 받아들일 수 없다고 판정하면, 숫자 전용 파일을 hp · timer 라벨에만 쓰는 경로로 바꾼다. 그때 아래 줄을 더해 확인한다.

- 해당 없음 — 사용자가 문장 속 고정 폭 숫자를 받아들여 숫자 전용 파일을 만들지 않았다. (그 경로일 때만) hp · timer 라벨만 숫자 전용 파일이고 wave · level 라벨은 본문 폰트인가 — 판정 화면 2번 줄과 측정 모드 화면에서 눈으로 본다. 연결을 잘못하면 wave · level의 영문 글자가 대체 글꼴로 섞여 그려진다.
