## 2. 자동 테스트로 검증 (테스트 스킵 — 사유 기록)

**테스트 파일을 만들지 않는다.** 이번 슬라이스는 새 순수 로직을 만들지 않는다. 변경은 싱글톤 선언, cc 의존 컴포넌트의 참조 캐시, `DataManager`·`I18n`의 수명주기, 워크플로우 CLI뿐이고 이 파일들은 전부 Cocos 런타임에 묶여 있어 vitest로 돌릴 수 없다.

> **통과 근거 (2026-07-14, 구현 완료 시점):** 전체 스위트 **443/443** 통과(33개 파일), `pnpm typecheck` **에러 0**(변경 전 65건 → 전부 해소), `pnpm check` 통과. 타입 에러 65건이 곧 이 슬라이스가 채운 가드 자리의 실측치다.

- [x] `pnpm test:run` — **기존 전체 스위트가 그대로 초록**이어야 한다. (`logic/`을 건드리지 않으므로 하나라도 빨간불이면 의도치 않은 회귀다.) → **443/443 통과**
- [x] `pnpm typecheck` — 에러 0. **이것이 "가드가 빠진 곳이 없다"의 근거다.** → **0건**
- [x] `pnpm check` — lint·format 통과.

> **타입체크의 한계를 알고 쓴다.** TypeScript의 내로잉은 중간에 함수 호출이 끼어도 유지되므로, 게이트가 보장하는 것은 **"흐름당 가드 하나"** 지 "모든 참조마다 가드"가 아니다. 그리고 가드의 **의미**(상태 전이를 반쪽 실행하지 않는가)는 전혀 증명하지 못한다. 그래서 아래 3절이 이 슬라이스의 진짜 그물이다.

## 3. 수동 테스트 체크리스트 (7단계)

### 3-1. 콜드 부팅 — "조용한 죽음" 5종

게임을 새로 시작하고 **처음 60초** 안에 다음이 전부 일어나는지 확인한다. 하나라도 안 일어나면 그건 이 슬라이스가 만든 회귀다. **어느 것도 콘솔에 에러를 남기지 않는다** — 눈으로 봐야 한다.

- [ ] **플레이어가 움직인다** (WASD/방향키). → 안 움직이면 `PlayerController`의 데이터 준비 래치가 안 켜진 것
- [ ] **마법이 자동 발사된다** (시작 마법이 적 방향으로 나간다). → 안 나가면 `SpellCaster._dataReady`가 안 켜진 것
- [ ] **적이 스폰된다** (웨이브 1이 실제로 돈다). → 안 나오면 `WaveManager.startWave()`가 안 불린 것
- [ ] **HUD의 웨이브 번호·타이머가 정상 표시되고 타이머가 줄어든다.**
- [ ] **적을 죽이면 XP 오브가 떨어지고, 주우면 XP 바가 찬다.** → 안 차면 `ExperienceManager._logic`이 null인 것
- [ ] **XP가 충분히 쌓이면 레벨업 카드 패널이 뜬다.** → 안 뜨면 `setOnLevelUp` 콜백이 안 걸린 것
- [ ] 콘솔에 `[XxxManager] … 없음` 형태의 loud-fail 에러가 **하나도 없다**. (있다면 씬 배선 문제이므로 그 컴포넌트가 스스로 비활성화된 상태다.)

### 3-2. 상태 전이 4종 — 반쪽 실행 여부

- [ ] **레벨업 → 카드 선택 → 재개:** 카드를 고르면 패널이 닫히고 **게임이 다시 흐른다**(적이 다시 움직인다). 카드 효과(피해·쿨다운·패시브)도 실제로 적용된다.
- [ ] **레벨업 카드를 여러 번** 연속으로 받아도 매번 정상 재개된다(2~3회 반복).
- [ ] **사망 → 결과 화면:** HP가 0이 되면 죽음 연출이 흐른 뒤 result 씬으로 넘어간다. **HP 0인 채로 게임이 멈춰 있으면 안 된다.**
- [ ] **결과 화면 통계**가 정상이다 — 생존 시간, 레벨, 도달 웨이브, 킬 목록, 보유 마법·강화, 패시브. (매니저 캐시가 잘못되면 여기가 0·빈 목록으로 조용히 샌다.)
- [ ] **승리(타이머 0:00) → 결과 화면.** 기본 `gameDuration`이 900초라 그대로는 15분이 걸린다. **Cocos 에디터에서 `GameManager` 노드의 `gameDuration`을 30초 정도로 임시 변경**해 확인하고, 확인 후 **900으로 되돌린다.** 타이머가 0:00에서 멈춘 채 게임이 계속 돌면 승리 전이가 깨진 것이다(이번 슬라이스가 가장 놓치기 쉬운 자리다).

### 3-3. 풀링 재사용 — 이전 생의 값이 남는가

- [ ] 적을 **10마리 이상 연속으로 죽인 뒤**에도 새로 스폰된 적이 **정상 체력·정상 크기·정상 종류**로 나온다. (재초기화가 반쪽이면 이전 적의 데이터를 물고 나온다.)
- [ ] 발사체가 적을 맞히고 사라진 뒤, 다음 발사체도 **정상적으로 사라진다.** 화면에 안 없어지고 남아 계속 피해를 주는 발사체가 없다.
- [ ] 적 발사체(이무기 등 원거리 적)도 같은 확인.

### 3-4. 수명주기 — 재시작·씬 이동

- [ ] **로딩 중 재시작:** 게임 시작 직후(1초 이내) ESC → 재시작을 **연타**한다. 콘솔에 에러가 없고 게임이 정상 부팅된다. (이게 `DataManager` 콜백 누수 수정의 검증이다.)
- [ ] **결과 화면에서 재시도 → 정상 플레이**가 다시 된다(2회 반복).
- [ ] **결과 화면 → 메뉴 → 다시 시작**도 정상.
- [ ] 씬을 오갈 때 콘솔에 `Cannot read properties of null` 류 에러가 없다.
- [ ] **일시정지(ESC)** 중 적·발사체가 멈추고, 해제하면 다시 흐른다.

### 3-5. 번역 라벨

- [ ] 메뉴·HUD·카드·결과 화면의 한국어 라벨이 전부 정상 표시된다(키가 그대로 노출되지 않는다).

## 4. F44 게이트 자체 검증 (인게임 무관, AI가 수행)

`approve-pr`이 타입체크를 **실제로** 돌리는지 확인한다. 이 커맨드는 `phase: "user-verification"`에서만 동작하므로, **7단계 진입 직후(Draft PR 생성 전)** 실패 경로만 밟아 확인한다(성공 경로를 밟으면 `pr-ready`로 전이해 버린다).

> **수행됨 (2026-07-14, `user-verification` 진입 직후).** `tests/logic/PauseMenu.test.ts`에 `const __gateDrill: number = "not a number";`를 심고 `pnpm wf approve-pr`을 실행했다.

- [x] 타입 에러를 하나 심고(스크립트 편집이 잠긴 phase이므로 `tests/` 쪽 파일에 심는다) `pnpm wf approve-pr`이 **차단**되는지 확인한다. → **차단됨.** `TS2322`를 그대로 출력하고 종료코드 1, `phase`는 `user-verification`에 그대로 남았다(전이 없음).
- [x] 차단 시 상태 파일의 `ts_check_clean`이 `false`, `ts_check_scope`가 `null`로 **덮어써지는지** 확인한다(기록이 낡은 값을 계속 말하지 않아야 한다). → **덮어써짐** (`ts_check_clean: false`, `ts_check_scope: null`).
- [x] 심은 에러를 되돌리고 타입체크가 다시 깨끗한지 확인한다. → **통과 (범위: full).**

> **드릴이 실패하면(= 게이트가 안 막으면):** `approve-pr`이 `pr-ready`로 전이해 버리고, 거기서 `user-verification`으로 되돌리는 wf 커맨드가 없다(`rework`는 `user-verification`에서만, `invalidate`는 `verification`에서만 된다). 복구는 `git restore .claude/workflow-state.json`이다.
>
> **드릴 후 상태 파일이 `ts_check_clean: false`로 남는 것은 정상이다** — `approve-pr`은 그 플래그를 읽지 않고 매번 다시 계산하므로 다음 승인에서 자동으로 복구된다.

## 5. 알려진 비-이슈

- 콘솔에 `[XxxManager] … 없음 — 컴포넌트를 비활성화합니다` 에러가 뜨면 그건 **이 슬라이스가 의도한 loud-fail**이다. 버그가 아니라 **씬 배선이 실제로 잘못됐다는 신고**이므로, 해당 매니저 노드가 씬에 있는지 확인한다.
