# ADR 008: AI 이미지 생성은 유료 서비스에서 한다

- **날짜:** 2026-08-06 확정 (ADR 작성 2026-08-08)
- **상태:** 결정됨
- **관련 설계:** [`../design/spec/art-direction.md`](../design/spec/art-direction.md) §8(파이프라인 정본), [`../design/spec/art-generation-playbook.md`](../design/spec/art-generation-playbook.md) §1.1~§1.2(엔드포인트·가격·Sandbox 사용법), [`../development/sessions/2026-08-04-paid-art-pipeline-plan.md`](../development/sessions/2026-08-04-paid-art-pipeline-plan.md)(검토와 시험 설계), [`../development/sessions/2026-08-06-player-front-cut-generation.md`](../development/sessions/2026-08-06-player-front-cut-generation.md) §7(4방향 판정 통과)
- **입력:** 아트 결정 재조사(2026-08-04) D3·D4·D9 → 로컬 실패 실측 → 유료 전환 검토와 시험 절차 → fal.ai Sandbox 실측(2026-08-06·08-07) — 사용자 결정

[ADR 001](001-cocos-version.md)이 게임을 만드는 엔진을 정했다면, 이 ADR은 **그 게임에 들어갈 그림을 어디서 만드는가**를 정한다.

## 컨텍스트

원래 방향은 비용을 아끼는 것이었다. 로컬에 생성 환경(ComfyUI + SDXL 1.0 base + 자체 스타일 LoRA `f58_anime_style`)을 세우고 여러 컨셉을 뽑아 고른 뒤 그것을 기준으로 진행한다는 구상이었고, 화풍 확정(2026-07-21)까지는 실제로 그렇게 굴러갔다.

플레이어 4방향에서 막혔다. **두 번의 실측이 같은 곳을 가리킨다.**

F62 실측(2026-07-25)에서 뒷모습은 스타일 LoRA 강도를 0.8에서 0.3까지 내려야 겨우 나왔고 완전한 측면은 강도 0.0에서도 나오지 않았다. 그런데 강도를 내리면 인물 동일성이 무너진다. 즉 **시점과 일관성이 한 노브에서 서로를 잡아먹는다.** 4방향 v3 실측에서 같은 증상이 재확인됐다 — back은 모자챙만 기울고 얼굴이 정면으로 보였으며, front는 긴 로브, left는 바지와 굽 부츠, right는 갑옷 장식이라 같은 인물의 네 방향이 아니라 비슷한 컨셉의 네 캐릭터였다.

**이 둘은 프롬프트로 고칠 수 있는 종류가 아니다.** back에 얼굴이 나오는 것은 모델이 그 시점 개념 자체를 모르는 것이고, 방향마다 의상이 바뀌는 것은 시드를 고정해도 남는다.

기존 그림을 편집으로 되살리는 길도 막혔다. 실패한 이유가 도구가 아니라 원본에 있었기 때문이다 — 브릿지와 v3 모두 **하반신이 로브에 덮여 다리가 아예 생성된 적이 없고** 몸통은 망토에 가려져 있다. 없는 것을 고칠 수는 없으므로 이건 고칠 대상이 아니라 새로 만들 대상이었다.

원인을 되짚으면 로컬 구성이 이 요구사항에 대해 거의 최악이었다. 셋이 겹쳤다.

- **베이스가 범용 모델이다.** SDXL 1.0 base에는 시점 어휘가 없다. Danbooru 태그를 네이티브로 먹는 애니 특화 계열은 `from_behind`·`from_side`가 학습 데이터에 명시적으로 붙어 있어 사정이 다르다.
- **ControlNet이 없다.** 방향별 골격을 직접 주는 표준 수단인데 설치되지 않은 채였다.
- **지시형 편집 도구가 없다.** "불꽃 빼고 팔 벌려" 같은 편집은 SDXL 인페인팅으로 어렵다. 비교적 최근에 생긴 능력이다.

그리고 이 병목은 아트 하나에 그치지 않았다. **리깅도 잡몹 로스터도 전부 플레이어 최종 아트에 매달려 있어서**, 4방향이 막힌 동안 아트 계열 작업 전체가 서 있었다.

## 결정

**AI 이미지 생성은 fal.ai를 경유한 유료 서비스에서 한다. 로컬 생성 스택은 폐기한다.**

- **채택 모델:** `openai/gpt-image-2/edit`. 정면 한 장을 레퍼런스로 넣는 다중 이미지 편집으로 시점과 인물 동일성을 한 번에 통과시킨다.
- **폐기 대상:** ComfyUI · SDXL 1.0 base · 스타일 LoRA `f58_anime_style`.
- **생성만 옮긴다.** 배경 제거·정렬 같은 후처리는 이 결정의 대상이 아니며 기존 도구에 남는다.

**판정 근거는 사전에 설계해 둔 게이트다.** 검토 문서 §8의 2단계 두 항목 — `back에 얼굴이 보이지 않는다`와 `네 장의 의상·머리·지팡이가 동일하다` — 이 v3가 실패한 바로 그 두 지점이고, 통과하면 전환을 확정한다고 미리 못 박아 두었다. 2026-08-06 정면 컷에서 세 모델이 통과했고 2026-08-07 4방향에서 후처리까지 끝났다.

## 왜 이렇게 정하는가

**첫째, 실패가 튜닝의 문제가 아니라 구성의 문제였다.** 프롬프트·시드·강도를 더 돌려도 위 세 원인 중 어느 것도 사라지지 않는다. 같은 구성으로 재시도하는 것은 이미 두 번 실패한 경로를 세 번째로 밟는 것이다.

**둘째, 라이선스가 함께 풀린다.** 로드맵 v2가 Steam 유료 판매와 스킨 판매를 예고하므로 상업 이용 가부는 실제 제약이다. FLUX.1 [dev]는 **자체 호스팅 시 비상업 연구 라이선스**인 반면 fal.ai 같은 API 파트너를 경유하면 출력의 상업 이용이 허용된다. 로컬에 두는 쪽이 오히려 판매를 막을 수 있었다.

**셋째, 비용 구조가 이 프로젝트에 맞는다.** fal.ai는 구독 없이 출력당 과금이고 이 프로젝트의 채택 에셋은 100장 안쪽이다. 실험을 넉넉히 300장 잡아도 $10~25로, Spine Essential 한 장($69)보다 싸다. 구독제였다면 반대 결론이 났을 것이다.

**넷째, 되돌아갈 조건이 시간이 지나도 변하지 않으므로 지금 판단할 수 있다.** 아래 「이 결정이 새로 만드는 제약」의 씨앗 문제 때문에 로컬 복귀는 확정된 인물을 버리는 것에서 시작한다. 모델 성능은 나중에 다시 재 볼 수 있지만 이 조건은 그대로라, "더 지켜보자"가 답을 바꾸지 않는다.

## 이 결정이 새로 만드는 제약

- **유료 출력을 로컬 모델의 학습 씨앗으로 쓸 수 없다.** FLUX 라이선스가 출력물을 경쟁 모델의 학습·파인튜닝·증류에 쓰는 것을 금지한다. 원래 구상했던 "유료로 초안을 뽑고 그것을 기준으로 로컬 양산"이 정확히 여기 걸린다. 그래서 로컬 복귀는 재학습이 아니라 **씨앗 재수집**부터다.
- **채택 모델의 상업 이용 조건이 아직 미확인이다**(백로그 F68). 검토 당시 가려 놓은 라이선스 표에는 FLUX·Gemini·Midjourney가 있고 OpenAI가 없다 — 그때는 후보가 아니었고 채택은 이틀 뒤 Sandbox 비교에서 정해졌다. **가려 놓은 것과 실제로 쓴 것이 어긋난 상태**이므로, 에셋이 불어나기 전에 닫는다. 어겼을 때의 손실이 다른 항목과 다르다 — 매팅 방식은 잘못 골라도 같은 원본으로 다시 돌리면 되지만, 라이선스가 걸리면 원본까지 못 쓰게 되어 생성부터 다시 해야 한다.

## 결과 · 후속

- **감사가 남긴 두 작업이 불필요해졌다.** D3(베이스 체크포인트 품질 비교)는 로컬 베이스를 안 쓰므로 문제 자체가 사라졌고, D4(스타일 LoRA 재학습)는 얹을 자리가 없어진 데다 위 씨앗 제약 때문에 **해서는 안 되는 일**이 될 수도 있었다. F62(시점 통제 수단 확보)도 세 수단이 전부 로컬 전제였으므로 닫혔다.
- **남는 것도 있다.** D2(파츠 컷 실측)와 D11(`ParticleSystem2D` 검증)은 생성과 무관한 축이라 그대로다.
- **로컬 환경 철거는 별도 항목이다**(백로그 F70). 약 21GB를 회수하는데 `rembg`가 지울 대상인 ComfyUI venv 안에 살고 있어 순서를 지켜야 한다. 절차는 검토 문서 §12가 든다.
- **셋업 문서는 지우지 않는다.** `comfyui-setup.md`·`kohya-setup.md`는 환경이 사라져도 남긴다 — 폴백으로 돌아올 때 그대로 다시 세우기 위해서다.
- **정본 위치.** 파이프라인 방향은 `art-direction.md` §8, 엔드포인트·가격·판정 절차는 `art-generation-playbook.md`가 든다. 이 ADR은 "왜 옮겼는가"만 든다.

## NOT in scope

- **배경 제거를 어디서 하는가** — 로컬 색 키잉을 유지할지 fal.ai 매팅으로 옮길지는 미확정이다(백로그 F59 ②). 생성만 옮기는 이 결정과 독립이다.
- **파츠 분리와 리깅 도구** — Spine 채택은 [ADR 006](006-collision-hitbox.md) 계열의 아트 결정이 아니라 별도 판단이고(재조사 D5), 구매 시점은 파츠 분리된 에셋이 한 벌 나온 뒤다(백로그 F59 ①).
- **잡몹 12종이 서로 구분되는 실루엣을 갖는 문제** — 도구가 아니라 디자인 문제라 전환으로 풀리지 않는다. 오히려 생성이 빨라지면 더 중요해진다(백로그 F60 3단계).
- **무엇이 좋은 그림인가의 판단** — 여전히 사람 몫이다.
