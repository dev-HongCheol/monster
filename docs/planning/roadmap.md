## 1. 프로젝트 목표 (Goal)

**학습 + 출시 경험.** 사할을 걸거나 큰 자본 투자 없이, "부끄럽지 않은 작은 상업 게임을 출시하고 리뷰·구매를 받아본다"는 개인 학습 목표.

**성공 기준 (Definition of Success):**
- v1: itch.io 무료 출시까지 도달 + 5명 이상의 외부 플레이 기록
- v2: Steam 유료 출시까지 도달 + 평균 70% 이상 리뷰 점수 + 100카피 이상 판매
- 학습 측면: Cocos Creator 풀 사이클, AI 그래픽 파이프라인, Steam 출시 워크플로우 체득

## 2. 게임 컨셉 (One-Liner)

**"판타지 영웅이 한국 신화 세계에서 귀신과 싸우는 정통 덱 호드 서바이벌"**.

### 시나리오 (plan.md 원안 단순화)

```
한국 무당 + 일본 무녀 + 중국 스님의 합동 소환 의식
    ↓ 차원 균열
판타지 세계의 영웅들이 한국으로 강림
    ↓
한국 귀신/요괴들과의 전쟁 시작
    ↓
세계를 구원하면 다시 자기 세계로 귀환
```

캐릭터 해금 = 추가로 소환된 영웅들.

**장르 클러스터:** Vampire Survivors / Brotato / Hell Maiden / Magic Survival
**시점:** 탑다운 2D
**그래픽:** 픽셀 아트 (AI 생성, 방식 1주차 데모 후 확정)
**플랫폼:** v1 = itch.io 웹, v2 = Steam PC. 모바일 비목표.

## 9. 코드 설계 원칙

**day 1부터 챙겨야 할 것:**

| 원칙 | 이유 |
|------|------|
| **데이터 주도 설계** | 마법/적/캐릭터/카드를 JSON으로 정의. 새 콘텐츠 추가 = 데이터 한 줄 |
| **단일 컨트롤러 + 데이터 분리** | `EnemyController`, `MagicController`, `CharacterController` 각 1개가 모든 데이터를 읽음 |
| **객체 풀링** | 마법 슬롯 6개가 동시 발사 + 적 다수 + 투사체 다수. 풀링 필수 |
| **이벤트 기반 시스템** | "레벨업" 이벤트 → 카드 뽑기 UI 트리거. 시스템 간 결합 최소 |
| **싱글톤 정리** | GameManager 정적 인스턴스 destroy 시 null 정리 (learnings.jsonl 참조) |

### 핵심 데이터 스키마 예시

**캐릭터:**
```json
{
  "id": "wizard",
  "name": "마법사",
  "sprite": "characters/wizard.png",
  "stats": { "hp_max": 100, "speed": 100, "damage_mult": 1.0, "pickup_range": 80 },
  "starting_magic": "fireball",
  "unlocked": true
}
```

**마법:**
```json
{
  "id": "fireball",
  "name": "파이어볼",
  "pattern": "linear",
  "projectile_count": 1,
  "damage": 30,
  "speed": 400,
  "cooldown": 1.0,
  "range": 300,
  "explosion_radius": 50,
  "homing": 0,
  "sprite": "magic/fireball.png"
}
```

**카드:**
```json
{
  "id": "card_damage_boost",
  "type": "enhancement",
  "label": "대미지 +20%",
  "effect": { "damage_mult": 0.20 },
  "requires_magic_selection": true
}
```

## 12. 알려진 위험 (Known Risks)

| 위험 | 확률 | 영향 | 완화책 |
|------|------|------|--------|
