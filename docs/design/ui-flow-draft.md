# v1 UI 플로우 + 화면 와이어프레임 초안

- **작성일:** 2026-07-02
- **성격:** DRAFT — `ui-completeness-plan.md`의 요소 리스트를 실제 화면과 화면 간 이동으로 배치한 초안. 레이아웃·문구·화면 구성은 확정 아님(에디터 세팅 전 지도 역할).
- **관계:** 「무엇을 만들지」(요소·우선순위)는 [ui-completeness-plan.md](./ui-completeness-plan.md), 「어떻게 연결·배치되나」(플로우·와이어프레임)는 이 문서. 「어떻게 보이나」(폰트·색·모션)는 후속 `/design-consultation`.
- **채택 기본값(사용자 확인 대기):** 메타 진행 = 최소(클리어 수 + 도감 해금), 아이콘 = placeholder(단색 사각형)로 구조 먼저. 일시정지 메뉴 신설.
- **확정(2026-07-02 사용자 결정):** 게임오버는 `result.scene` **한 갈래로 통일**하고 `main.scene`의 사경로(gameOverPanel)를 제거한다(§4).

> 와이어프레임의 `[Lv0]`~`[Lv3]`·`[9-slice]`·`[text]` 표시는 `ui-completeness-plan.md §3`의 구현 복잡도 레벨(이미지 필요 여부)을 가리킨다. `[Lv0]`=흰 텍스처 틴트(이미지 불필요), `[Lv2]`=디자인 이미지 필요(지금은 placeholder), `[9-slice]`=한 장 재사용, `[text]`=Label.

## 1. 현재 플로우 (as-is, 코드 기준)

게임 상태(`GameState`)는 `Playing` · `Victory` · `LevelUp` · `GameOver` 네 가지다.

```
[menu.scene] ──PLAY──► [main.scene / Playing]
                             │
   ┌─────────────────────────┼──────────────────────────┐
   │ (레벨업 이벤트)          │ (HP 0)         (타이머 0)  │
   ▼                         ▼                ▼          │
[LevelUp 오버레이]        state=GameOver   state=Victory  │
 카드 3장 → 픽              │                │           │
   │ resumeFromLevelUp()     └──goToResult()──┘           │
   └──► Playing 재개                 │                    │
                                     ▼                    │
                            [result.scene]                │
                          승/패 + 도달 웨이브             │
                          ├─RETRY─► [main.scene]──────────┘
                          └─MENU──► [menu.scene]
```

- **메인 메뉴:** 타이틀 + PLAY 버튼 하나. 도감·설정 없음.
- **인게임 HUD:** HP·웨이브·타이머·레벨·XP 모두 텍스트 라벨.
- **레벨업:** `main.scene` 안 오버레이(씬 전환 아님). 카드 3장 픽 → 재개.
- **일시정지(수동):** 없음.
- **게임오버/승리:** 둘 다 `goToResult()`로 `result.scene`으로 전환. 결과 화면은 도달 웨이브 숫자만.
- **⚠️ 이중 구조:** `main.scene`에 `gameOverPanel`(RESTART/MENU 버튼)과 `gameover.*` i18n 키가 남아 있으나, 사망 시 `_applyDamage`가 곧장 `goToResult()`를 호출해 씬을 바꾸므로 **이 오버레이는 실제로 뜨지 않는다(사경로).** §4에서 정리한다.

## 2. 목표 플로우 (to-be, v1 완성)

신규(일시정지·설정·도감)를 넣고 게임오버 경로를 한 갈래로 정리한 플로우다. 신규·변경은 ✨로 표시.

```
                    ┌──────────────[menu.scene]──────────────┐
                    │   [PLAY]      [도감]✨      [설정]✨      │
                    └────┬────────────┬────────────┬──────────┘
                         │            │            │
                       PLAY         도감✨        설정✨
                         │            ▼            ▼
                         │    [collection]✨  [settings]✨
                         │      └──뒤로──┐    └──뒤로──┐
                         │              ▼            ▼
                         │           [menu.scene]로 복귀
                         ▼
              ┌──[main.scene / Playing]──┐
              │                          │
   ┌──────────┼───────────┬──────────────┼───────────┐
 (레벨업)    (ESC)✨      (HP 0)       (타이머 0)      │
   ▼          ▼            ▼              ▼            │
[LevelUp]  [Pause]✨   GameOver        Victory         │
 카드3장    ├─계속       └──goToResult()──┘            │
  +스킵✨   ├─설정✨          │                        │
   │        ├─재시작         ▼                        │
   ▼        └─메뉴     [result.scene]                  │
 Playing              승/패 + 런 통계✨(시간·레벨·킬·마법)│
  재개                ├─RETRY─► [main.scene]────────────┘
                      └─MENU──► [menu.scene]
```

핵심 변경:
1. **메인 메뉴 확장** — 도감·설정 진입 추가.
2. **일시정지 메뉴 신설** — `ESC`로 `Playing` → `Paused`(신규 상태). 계속하기·설정·재시작·메뉴. 레벨업과 같은 오버레이 방식(씬 전환 없음).
3. **설정·도감 화면 신설** — 별도 씬 또는 메뉴 위 오버레이(§5에서 결정). 뒤로 = 직전 화면 복귀.
4. **게임오버 경로 일원화** — `result.scene` 하나로. `main.scene`의 `gameOverPanel`·`gameover.*`는 정리(§4).
5. **결과 화면 통계 확장** — 도달 웨이브 외 생존 시간·레벨·처치 수·획득 마법.

## 4. 게임오버 경로 일원화 (확정 2026-07-02)

현재 `main.scene`의 `gameOverPanel`(+ `gameover.title/restart/menu` i18n)과 `result.scene`이 둘 다 "게임오버 UI"인데, 코드 사망 경로가 `goToResult()`로 곧장 씬을 바꿔 **오버레이는 안 뜬다(사경로).** **결정:** `result.scene` 한 갈래로 통일하고 `main.scene`의 사경로를 제거한다(결과 통계·재시작 흐름상 별도 씬이 깔끔).

정리 작업(별도 소규모 슬라이스 또는 결과 화면 슬라이스에 포함):

- `HudController`의 `gameOverPanel`·`restartButton`·`menuButton` `@property`와 배선(`onLoad`의 버튼 콜백, `_onRestart`/`_onMenu`, `_handleStateChange`의 `GameOver` 분기 패널 표시)을 제거한다.
- `main.scene`에서 `gameOverPanel` 노드 계층을 제거한다(에디터 작업 = 사용자, 7단계).
- i18n 카탈로그의 `gameover.title`/`gameover.restart`/`gameover.menu` 키를 `en.json`·`ko.json`에서 제거한다. **i18n 키 정합 가드(백로그 C1)가 이 키의 코드/씬 참조 잔재를 잡으니, 참조를 모두 지운 뒤 키를 지운다.**
- 사망 경로 동작(`_applyDamage` → `goToResult()`)은 그대로 둔다 — 이미 result 씬으로 가고 있어 로직 변경 없음. 제거는 순수하게 죽은 UI 정리다.

## 5. 열린 결정 (슬라이스 착수 전 확정)

- **설정·도감을 별도 씬 vs 메뉴 위 오버레이** — 별도 씬은 격리가 깔끔하나 씬 3개 추가, 오버레이는 `menu.scene` 안에서 토글해 가볍다. 인게임 일시정지에서도 설정을 여니 **설정은 재사용 가능한 오버레이(프리팹)로** 두는 편이 인게임/메뉴 양쪽에서 재사용된다.
- **런 통계 수집** — 처치 수·DPS 등을 `GameManager`/`GameResult`가 집계해야 한다(현재 도달 웨이브만). 통계 항목 확정 필요.
- **메타 진행 모델** — 최소(클리어 수 + 도감 해금) 기본값. 상점형으로 바꾸면 골드 HUD·상점 화면·결과 보상이 추가된다.
