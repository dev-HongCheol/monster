# Design: 새 게임 인트로 씬 — 위기·소환·응답 3장

Generated by /office-hours on 2026-08-25
Branch: feat/intro-scene

Status: DRAFT (rev 3 — 적대적 리뷰 2회 반영)

> **rev 3 개정 사유:** rev 2가 **고칠 파일을 잘못 지목했다** — i18n 스캐너(`KEY_RE`·`extractLiteralsFromSource`·`scanUsedLiterals`)는 `tests/helpers/I18nKeyGuard.ts`가 아니라 `tests/logic/I18nKeyGuard.test.ts`에 있다(helpers는 `usedLiterals`를 **입력으로 받는** 판정만 든다). 함께: 배경 색을 `logic/`에 두려던 것이 `ui/Theme.ts`의 「색의 단일 출처」 선언을 침범했고, 언어 전환 검증 명령이 실제로는 `ReferenceError`였으며, 빈 배열 불변식이 스스로 모순이었다. `@property` 계약과 `check-qa` 요구사항도 이제 들어왔다.
>
> **rev 2 개정 사유:** 초안이 **통과하지 못할 게이트를 하나 못 봤다.** 페이지 텍스트 키를 `intro.json`에만 두는 구조는 `tests/logic/I18nKeyGuard.test.ts`의 영구 CI 게이트에서 전부 `orphan`으로 잡혀 `wf start-verification`의 GREEN 게이트를 못 넘는다(확인: `sceneKeyPrefixes`가 `['menu.','result.','gameover.']` 하드코딩, expected = `.ts` 리터럴 스캔 ∪ 4개 도메인 패밀리). 그 하나를 풀면서 `intro.json` 자체가 사라졌고, 딸려 있던 로드 실패 경로·`.meta` 타이밍 문제도 함께 닫혔다. 함께: 인용한 `code-i18n.md` §8.1과 스스로 어긋난 곳, 로드맵 편집 지시가 무관한 정본까지 지울 문구였던 것, 저장 변경 함수와 「스킵이 본 것으로 치는가」가 비어 있던 것을 고쳤다.

## Problem Statement

지금 메뉴에서 PLAY를 누르면 아무 맥락 없이 서울 아레나 한복판에서 게임이 시작된다. 플레이어가 누구인지, 왜 귀신과 싸우는지가 게임 안 어디에도 없다. 백로그 J5가 그 자리를 「새 게임 인트로 씬」으로 잡아 뒀지만 실제 재료는 로드맵 §2의 네 줄이 전부이고, 스토리를 담은 문서는 없다. 그래서 이 슬라이스는 **스토리 정본을 세우는 일과 인트로 씬을 만드는 일을 함께** 한다.

인트로가 이 시점에 오는 이유도 분명하다 — 2026-07-20 감사에서 이어서하기·도감·보상 포인트가 전부 세이브(J3)에 매달린다는 게 드러났고, J5만이 그 밖에서 자족적으로 설 수 있는 조각으로 남았다.

## What Makes This Cool

**인트로가 다음 1초를 설명한다.** 세 비트를 「위기 → 소환 → 응답」으로 놓으면 첫 화면이 귀신에 덮인 서울이고, 인트로가 끝나자마자 플레이어가 서는 곳이 바로 그 서울이다. 설정을 설명하는 인트로가 아니라 **다음 화면을 준비시키는 인트로**가 된다.

그리고 이건 이 게임이 자기 이야기를 처음으로 꺼내는 자리다. 지금까지 만든 것은 전부 시스템(마법·적·맵·UI)이었고 「판타지 영웅이 한국 신화 세계에서 싸운다」는 컨셉은 로드맵 안에만 있었다. 인트로 3장이 그 컨셉을 처음으로 화면에 올린다.

## Constraints

- **경쟁자는 다른 인트로가 아니라 스킵 버튼이다.** 호드 서바이벌은 PLAY를 누르면 곧장 싸움이 시작되는 장르고 반복 플레이가 전제라, 두 번째부터는 무조건 스킵된다. 길이가 곧 위험이다.
- **씬 파일과 `.meta`는 AI가 만들지 않는다.** Cocos 에디터가 낳는 산출물이므로 `intro.scene`은 7단계에서 사용자가 조립한다. AI 산출물은 컨트롤러 `.ts`·순수 로직·i18n 키까지다.
- **인트로용 그림은 0장이고, 아트 파이프라인은 PR #91(feat/staff-layer)이 점유 중이다.** placeholder로 시작한다. `art-direction.md` §9 작업 순서에도 인트로 인물 자리가 없다.
- **컷셈은 v1 제외**(`roadmap.md:188` — 「시나리오 컷씬 (인트로 텍스트만)」). 애니메이션 시퀀스가 아니라 정지 화면 + 텍스트다.
- **코드 전체에 `localStorage` 0건.** 이 슬라이스가 첫 저장을 들인다(D3).
- **`I18n.setLanguage`는 `LocalizedLabel`만 갱신한다**(`systems/I18n.ts` `_refreshAll` → `_registry` 순회). 컨트롤러 `t()` 라벨은 스스로 등록하지 않으면 언어 전환에 반응하지 않는다.
- **마법·적은 동결.** v1 축은 완성도(맵·스토리·플로우·UI·메타)이며 이 슬라이스는 그중 스토리다.

## Premises

1. **스토리 정본을 신설한다** — `docs/planning/story.md`. 로드맵 §2 네 줄은 인트로를 쓰기에 모자라고, 세션 문서에만 적으면 시점 기록이 몇 달 뒤 명세로 오독된다. `docs/planning/`은 `docs-references.md` §1이 정본 층으로 들고 있고 `enemy-system.md`·`magic-system-mage.md`가 이미 그 층에 서 있다.
   **단, `wf canon`으로는 만들 수 없다** — `.claude/workflow.mjs`의 허용 접두사가 `code|game|docs|ops`(dev spec/)과 `art|ui`(design spec/)뿐이다. 손으로 쓴 뒤 `wf canon-done docs/planning/story.md`로 선언한다. `docs/planning/`에는 색인 README가 없으므로 등재는 **CLAUDE.md Knowledge Base 표에 한 행 추가**로 대신한다.
2. **로드맵은 §2의 「시나리오」 하위 블록만 고친다.** §2에는 장르 클러스터·시점·**그래픽 문단**(유료 생성 서비스·채택 모델·Spine·아트 정본 3개 링크)·플랫폼이 함께 들어 있고 그 그래픽 문단은 다른 어디에도 없는 정본이다. 「§2를 요약으로 줄인다」는 그것까지 지우는 문구였다 — 손대는 것은 시나리오 코드블록과 그 아래 한 줄뿐이고 나머지는 건드리지 않는다.
3. **용어와 인물 수를 확정한다** — 백로그 J5의 「3나라 무녀」는 로드맵의 「한국 무당 + 일본 무녀 + 중국 스님」과 다르다. 셋을 뭉뚱그려 "무녀"라 부르지 않는다. 표기 규칙은 `story.md`가 든다.
4. **씬은 사용자가 만든다** — QA 문서가 `qa-setup.md` §「에디터 조립 레시피」 기준(씬 좌표계 Position·Size, 노드 계층 순서 명시)으로 레시피를 실어야 한다. Draft PR에는 신규 `.meta` 0개, PR 승인 시점에 일괄 커밋.
5. **`intro.scene`은 씬 단위로 코드 구동으로 정한다** — `code-i18n.md` §8.1은 「먼저 씬을 보고, 그다음 문자열을 본다」이고 `main.scene`에 그 씬 단위 결정의 선례가 있다. 인트로는 라벨 넷 중 셋(페이지 텍스트)이 코드가 키를 고르는 것이라, 문자열 축만 보면 스킵 버튼 하나만 `LocalizedLabel`이 되어 한 화면이 두 방식으로 갈린다. **스킵 버튼을 포함해 전부 컨트롤러 `t()`**로 두고, 근거와 함께 §8.1·§8.3에 기록한다. 이 결정이 없으면 F79(pause 패널 잔재)와 같은 겹침이 새 씬에서 재발한다.
6. **저장은 J3이 흡수할 수 있는 최소 형태로** — 단일 네임스페이스 키 + 버전 필드, 파싱·판정·변경이 전부 순수 함수, 저장 실패는 게임을 막지 않는다. **모르는/더 높은 version은 기본값으로 읽되 쓰지 않는다**(J3이 version을 올린 뒤 이 코드가 남아 있으면 구 세이브를 덮어 지우는 것을 막는다).

## Approaches Considered

### Approach A: 별도 `intro.scene` (채택)
새 씬 하나 + `IntroController` + 순수 `IntroLogic`·`SaveLogic` + `SaveStore`.
Effort: human ~2일 / CC ~40분 (+ **사용자 씬 조립 40~60분, 왕복 1회 가정**) · Risk: Low

### Approach B: `menu.scene` 풀스크린 오버레이 (기각)
조립은 가장 쉽지만 「텍스트 오버레이가 아니라 씬이다」라는 2026-07-20 결정(`sessions/2026-07-20-j-completeness-sequencing.md:43`)을 뒤집는다.

### Approach C: `intro.scene` + 페이지 시퀀스 일반화 (기각)
재사용처가 아직 가설이다 — F57은 1장짜리 카드라 시퀀스가 아니고(`backlog.md:96`), F28(승리 비트)은 페이지 형태가 아닐 수 있다. `IntroLogic`이 페이지 배열을 받는 형태라 필요할 때 승격하는 비용이 거의 0이므로 지금 하지 않는다.

### 기각된 저장 방식: 세션 한정 플래그 (인메모리 / `sessionStorage`)
영속 저장을 안 건드려 J3 선점이 0이지만, **탭을 새로 열면 다시 보인다.** v1 배포처가 itch.io 웹이라 그건 「최초 1회」가 아니다. D3에서 사용자가 영속을 택했다.

## Recommended Approach

**Approach A**, 아래 결정을 얹어서.

| # | 결정 | 왜 |
|---|------|-----|
| D1 | 서사는 **위기 → 소환 → 응답** | 인트로 다음 화면(서울 아레나)을 설명하는 비트가 이것뿐이다. 무당·무녀·스님 셋을 한 장에 몰아넣을 수 있어 최종 아트가 인물 컷 하나로 끝난다 |
| D2 | **3장 × 한 줄**, 총 3문장 | 스킵을 누를 동기가 생기기 전에 끝난다. 세 비트가 각자 그림을 가져 placeholder 상태에서도 리듬이 보인다 |
| D3 | **최초 1회만** (`sys.localStorage`) | 반복 루프에 마찰이 0이다. 대가로 이 프로젝트 첫 저장 키를 인트로가 정하므로 형태를 J3이 흡수 가능하게 둔다(전제 6) |
| D4 | 스토리 정본은 **`docs/planning/story.md`** | 인트로는 스토리의 첫 소비처일 뿐이다. 적 이름·도감·보스가 같은 원천을 쓸 것을 전제하면 문서 하나 늘리는 값이 나온다 |
| D5 | **별도 `intro.scene`** | J5의 명시 결정 유지 |

### D1이 확정하는 것 — 순서가 아니라 인과다

로드맵은 `의식 → 균열 → 영웅들 강림 → 귀신과 전쟁`이다. 인트로는 `귀신이 이미 서울을 삼킴 → 그 대응으로 의식 → 마법사가 응답`이다. **인과가 반대다**(의식이 귀신을 부른 게 아니라, 귀신이 의식을 부른다). 그리고 **복수「영웅들」이 단수「마법사」가 된다** — v1이 마법사 단일 고정이기 때문이다. 로드맵 §2 시나리오 바로 아래 줄 「캐릭터 해금 = 추가로 소환된 영웅들」은 **그대로 살린다**: 의식은 한 번이지만 응답은 계속 오는 것으로 두면 해금 캐릭터의 자리가 남는다. 이 셋을 `story.md`가 문장으로 못 박는다.

### `intro.json`을 두지 않는다

초안은 페이지를 `resources/data/intro.json`에 뒀다. 그러면 세 가지가 한꺼번에 깨진다.

1. **i18n 정합 가드가 RED가 된다.** expected 집합은 `.ts` 리터럴 스캔과 4개 도메인 패밀리로만 조립되므로, JSON에만 있는 `intro.page.*`는 전부 `orphan`이다. 이건 CI가 아니라 `start-verification`의 GREEN 게이트다.
2. **로드 실패가 첫 화면을 죽인다.** `DataManager._loadAll`은 7개 파일 고정 목록이고 실패 시 `_isReady`가 영영 안 켜진다(파일 주석이 "게임은 켜지지만 정지 상태"라고 스스로 적어 뒀다).
3. **`.meta` 타이밍이 얽힌다.** 새 JSON은 사용자가 에디터를 열어야 임포트되므로 그전엔 로드가 실패한다.

그래서 **페이지 배열은 `IntroLogic.ts`의 `const INTRO_PAGES`로 둔다.** 3장짜리를 늘리는 일은 배열 한 줄 추가이고, 편집 주체가 사람+AI라 JSON일 이유가 없다. 남는 것은 가드가 `textKey:` 리터럴을 못 잡는다는 점뿐인데, 스캐너는 이미 같은 성격의 `nameKey:`·`descKey:`를 잡고 있으므로 **`textKey:`를 그 옆에 한 줄 추가**한다(패밀리 예외나 `sceneKeyPrefixes: ['intro.']` 추가는 오타를 영영 못 잡게 되므로 안 쓴다).

### 순수 로직 — 경계값까지

```ts
// IntroLogic.ts
export interface IntroPage { readonly backgroundTint: string; readonly textKey: string; }
export const INTRO_PAGES: readonly IntroPage[];            // 길이 3
export interface IntroState { readonly pageIndex: number; readonly finished: boolean; }

startIntro(pageCount)            // 3 → {0,false}   0 → {0,true}  (빈 배열은 즉시 종료)
advanceIntro(state, pageCount)   // {0,false},3 → {1,false}
                                 // {2,false},3 → {2,true}   ← 마지막에서 인덱스 유지, finished만 켠다
                                 // finished 상태로 또 부르면 그대로 반환 (멱등)
skipIntro(state)                 // {pageIndex 유지, finished:true}
```

`finished`일 때도 `pageIndex`가 유효 범위 안이라 컨트롤러의 `pages[pageIndex]`가 절대 out-of-range가 되지 않는다.

```ts
// SaveLogic.ts
export interface SaveData { readonly version: number; readonly introSeen: boolean; }
export const SAVE_VERSION = 1;

parseSave(raw: string | null): SaveData   // null·깨진 JSON·낯선 형태 → 기본값
canWriteSave(data: SaveData): boolean     // data.version > SAVE_VERSION 이면 false (미래 세이브를 덮지 않는다)
shouldPlayIntro(data: SaveData): boolean  // !data.introSeen
markIntroSeen(data: SaveData): SaveData   // 변경도 순수 함수 — 버전 상수가 cc 파일로 새지 않게
serializeSave(data: SaveData): string
```

키는 `monster.save`, 값은 `{"version":1,"introSeen":true}`. 읽기 실패(사생활 모드·저장 차단)는 「기본값 = 인트로 재생」으로 흡수하고, 쓰기 실패는 무시한다 — 인트로가 한 번 더 나올 뿐 게임은 진행된다.

**스킵도 본 것으로 친다.** 스킵한 사람이 다음에 또 보게 되면 스킵의 의미가 없다. 즉 마지막 페이지 도달과 스킵 **양쪽 모두** `markIntroSeen` → 저장 → `loadScene('main')`이다.

### 컨트롤러가 반드시 하는 것 두 가지

- **`I18n.instance?.onReady(render)`** — 인트로는 100% 텍스트에 10초짜리라 카탈로그가 늦으면 플레이어가 생키(`intro.page.crisis`)를 본다. 결과 화면과 달리 인트로에는 재렌더를 부를 다른 트리거가 없다(`ResultController.ts:51`이 같은 패턴).
- **`ILocalizable` 구현 + `register`/`unregister`** — `setLanguage`가 `_registry`만 순회하므로, 등록하지 않으면 언어 전환이 인트로 텍스트에 반영되지 않는다.

### 넘김과 배경

- **넘김은 수동만** — 클릭/터치 + `Space`·`Enter`. 자동 넘김은 두지 않는다(자동을 두면 페이지별 지속시간이 데이터에 들어가야 하고, 읽는 속도가 사람마다 달라 어차피 수동 넘김이 필요하다). D2의 "10초"는 **읽는 데 걸리는 시간 추정치이지 타이머 값이 아니다.**
- **배경 placeholder는 흰 텍스처 단색 틴트 3색** — `ui-completeness-plan.md`의 `[Lv0]` 관례 그대로라 이미지 에셋이 필요 없다. 색은 위기=어두운 남색, 소환=자주, 응답=금색으로 두어 장면 전환이 보이게 한다.

## Success Criteria

- 첫 PLAY에서 인트로 3장이 뜨고, 마지막 페이지 뒤 `main` 씬으로 넘어간다.
- 메뉴로 돌아와 다시 PLAY하면 인트로 없이 곧장 `main`으로 간다.
- 스킵이 어느 페이지에서나 즉시 `main`으로 보내고, **그 뒤로 인트로가 다시 뜨지 않는다.**
- 저장이 막힌 환경(사생활 모드)에서도 게임이 시작된다 — 인트로가 매번 나올 뿐.
- 씬에 `I18n` 노드가 붙은 상태에서 콘솔 `I18n.instance.setLanguage('en')`을 치면 3문장과 스킵 라벨이 즉시 영어로 바뀐다(= `ILocalizable` 등록이 살아 있다는 증거).
- `IntroLogic`·`SaveLogic`이 씬 없이 vitest로 검증된다 — 경계값(마지막 페이지·빈 배열·멱등·미래 version 비기록) 포함.
