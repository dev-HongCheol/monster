- **작성일:** 2026-09-28
- **성격:** 초안 폴더의 참고 자료다. 정본도 결정 기록도 아니다. 2D 생성 경로의 문서(플레이북 · 세션 · QA · ADR 008)를 지우면서, 적 로스터 · UI · 배경을 2D로 뽑을 때 다시 쓸 부분만 여기 모았다. 각 슬라이스가 계획과 새 정본을 쓸 때 입력으로 읽고, 정본으로 옮겨 간 내용은 여기서 지운다.

## 1. 지난 결정의 요지

**AI 이미지 생성은 유료 · 웹 서비스에서 한다(2026-08-06, 지운 ADR 008).** 처음에는 비용을 아끼려고 로컬 스택(ComfyUI + SDXL 1.0 base + 자체 스타일 LoRA)을 세웠고 화풍 확정(2026-07-21)까지는 그렇게 굴러갔다. 플레이어 4방향에서 막혔다 — 뒷모습은 LoRA 강도를 0.3까지 내려야 겨우 나오고 완전한 측면은 0.0에서도 안 나오는데, 강도를 내리면 인물 동일성이 무너진다. **시점과 일관성이 한 노브에서 서로를 잡아먹었다.** 원인은 튜닝이 아니라 구성이었다 — 범용 베이스에는 시점 어휘가 없고(애니 특화 계열은 `from_behind` 같은 태그를 학습 데이터에 달고 있다), ControlNet이 없었고, "불꽃 빼고 팔 벌려" 같은 지시형 편집 도구가 없었다. 유료 서비스는 정면 한 장을 레퍼런스로 넣는 다중 이미지 편집으로 그 둘을 한 번에 통과시켰다.

이유 넷이 시간이 지나도 그대로다. ① 실패가 구성의 문제라 같은 구성으로 재시도하는 것은 세 번째 실패다. ② 라이선스 — 로컬에 두는 쪽이 오히려 상업 이용을 막을 수 있었다(자체 호스팅 시 비상업 조건이 붙는 모델이 있다). ③ 채택 에셋이 100장 안쪽이라 출력당 과금이 구독보다 싸다. ④ **되돌아갈 조건이 변하지 않는다** — 서비스 출력을 로컬 모델의 학습 씨앗으로 쓰는 것은 약관이 막으므로(fal 약관 §14 · OpenAI 약관의 경쟁 모델 개발 금지), 로컬 복귀는 재학습이 아니라 **씨앗 재수집**부터다. 모델 성능은 나중에 다시 재 볼 수 있지만 이 조건은 그대로라 "더 지켜보자"가 답을 바꾸지 않는다.

**fal.ai에서 ChatGPT 웹으로(2026-09-15).** 추가 결제를 피하려고 사용자가 ChatGPT 웹에서 직접 만든다. fal에서 쓰던 채택 모델도 결국 OpenAI의 `gpt-image` 계열이라 화풍은 이어진다. 웹 화면을 자동화로 돌리지 않고, VRoid 프리셋 텍스처를 입력으로 넣지 않는다 — 조건은 `ops-licensing.md` §2.3.

**손그림 · 미감을 최소로(2026-07-21).** 사람 몫을 "그린다"가 아니라 "고르고 맞춘다"까지로 내린다. 세 레버는 art-direction §8 머리에 있다.

## 2. 두 트랙

플레이어(스킨이 붙는 주체)는 3D 마스터에서 층별로 굽고, 잡몹 12종 · 이펙트 · 맵은 2D 생성 스프라이트다. 표와 이유는 `art-asset-spec.md` §0, `art-direction.md` §3.1. 이 문서는 두 번째 트랙만 다룬다.

## 3. 인물 고정 문장

캐릭터의 화풍 · 머리색 · 눈색 · 피부 · 옷차림을 한 문단으로 못 박고 **컷마다 글자 그대로 복사**한다. 단어 하나를 바꾸면 인물이 갈린다 — "red hair"를 한 컷에서 "crimson hair"로 쓰면 모델은 같은 뜻으로 읽지 않는다. 동의어 교체 · 어순 변경 · 수식어 추가를 전부 금지한다.

2D 플레이어 시절의 확정 문장(2026-08-06)이다. 지금 플레이어는 이 문장을 쓰지 않지만, **형태의 본보기**로 남긴다 — 축이 화풍 → 머리 → 눈 → 피부 → 옷(부위별 색) → 소품 순이다.

```
young woman fire mage, long scarlet hair, amber eyes, fair and pale skin,
short tunic with short sleeves in bright cream orange, pants in dark brown,
ankle boots in medium leather brown, fingerless gloves in dark brick red,
plain wooden staff without ornament
```

빈칸을 채울 때의 제약:

- **색은 그 캐릭터의 주조색 범위 안에서 고른다.** 플레이어는 불 원소(따뜻한 적 · 갈 · 주황)였다. 적은 `enemies.json`의 `tint`가 주조색이다(art-direction §4.1).
- **상의 · 하의 · 신발은 서로 명도가 달라야 한다.** 같은 명도로 채우면 표시 크기에서 한 덩어리로 뭉친다.
- **적 로스터와 색이 겹치는지 확인한다.** 플레이어 주조색과 구미호 `#FF8C2A`(주황) · 야차 `#C0392B`(적)가 같은 계열이고, 창백한 피부는 달걀귀신 `#F7D6AE` · 장산범 `#ECE3CC`와 걸렸다. 새 캐릭터를 뽑을 때 12종 팔레트와 나란히 놓고 본다.

## 4. 프롬프트 축

넣는 것과 빼는 것의 분류는 `art-asset-spec.md` §6.3이 정본이다. 그 밖에 실제로 돌리며 배운 것:

- **모델은 태그 나열이 아니라 지시를 읽는다.** 문장으로 쓴다. 네거티브 칸은 없으므로 제외할 것을 본문에 자연어로 적는다("Do not draw …").
- **제외 문장에는 배치가 아니라 물건을 적는다.** "지팡이를 비스듬히 들지 마라"는 잘 듣지 않고 지팡이 자체를 흐린다. 배치는 "이렇게 해라" 쪽에서 지시한다.
- **지시마다 근거를 붙여 둔다.** 다음 사람이 함부로 빼지 않게. 2D 플레이어에서 근거가 있던 지시 — `four-head-tall proportions`(4등신, 사양서 §2.7) · `ending at the waist`(밑단이 엉덩이를 덮으면 하의 슬롯이 반토막) · `arms away from body`(가려진 자리를 없앤다) · `clearly different brightness so they read as separate pieces`(부위 명도 차) · 불 · 발광 계열 제외(이펙트를 캐릭터에 굽지 않는다, 사양서 §7.3) · `flat neutral gray background`(배경 제거가 쉽고, 바닥 발광이 살아나면 발 밑선 정렬 기준이 발이 아니라 빛이 된다) · `Both feet fully visible`(발 밑선을 맞추려면 발이 잘리면 안 된다).
- **세로가 긴 비율로 뽑는다**(캐릭터라면 3:4 등). 1:1로 뽑으면 좌우 빈 공간만큼 인물이 작게 들어와 해상도를 버린다. 한 번에 여러 장을 받아 고른다. 시드는 비우고, 마음에 든 컷이 나오면 결과에 찍힌 값을 적어 둔다(없는 모델이 많다).

## 5. 공통 합격 판정

모든 단계의 모든 컷에 돌린다. 세트(네 방향 · 여러 프레임)는 장마다 돌린 뒤 세트 고유 항목(같은 인물인가, 뒷모습에 얼굴이 없는가)을 본다.

- [ ] **팔이 둘, 손이 둘이다** — 여분의 팔 · 손 · 떠 있는 손이 없다. 여덟 항목을 전부 통과하고도 손이 셋인 컷이 실제로 나왔다
- [ ] 팔이 몸통에서 떨어져 있다
- [ ] 불꽃 · 발광이 그림에 구워지지 않았다
- [ ] 배경이 단색이라 제거가 쉽다 — 바닥 그림자와 지면 선도 없다
- [ ] 두 발이 모두 프레임 안에 있다
- [ ] 소품(무기 등)이 몸과 경계가 뚜렷하다
- [ ] 손이 소품을 쥔 모양이다 — 펴진 손에 나중에 소품을 얹으면 쥐지 않고 통과하는 것처럼 보이고, 그때는 고칠 방법이 없다
- [ ] 머리 높이가 전체의 등신비만큼이다
- [ ] 다리가 보인다 — 옷자락이 덮지 않는다(가림은 생성 시점에만 풀 수 있다. **한 번도 생성된 적 없는 부위는 편집으로 발명되지 않는다**)

**1차 테스트 게이트(art-direction §8-4 · 부록 B).** 대비 큰 3종(처녀귀신 · 구미호 · 마법사)을 같은 조건으로 뽑아 한 화면에 놓고 (a) 하나의 게임처럼 보이고, (b) 실루엣과 색으로 즉시 구분되며, (c) **실제 표시 크기(50~75 단위)로 줄여도** 무엇인지 읽히면 통과. 12종을 다 만들기 전에 3~4종으로 호드 가독성을 먼저 본다(백로그 F60 3단계).

## 6. 세트 규칙

`art-asset-spec.md` §6.0이 정본이다. 요지 — 한 세트는 한 번의 편집으로 함께 받는다(정면을 레퍼런스로), 마음에 드는 컷은 그 자리에서 내려받는다(되찾을 수단이 없다), 전신 시트를 먼저 확정하고 변형본(가림을 걷은 판 등)까지 그 세션에서 함께 뽑는다, 채택본만 `art-source/`에 기록 넷(서비스 · 생성일 · 프롬프트 전문 · 레퍼런스 경로 · 시드)과 함께 둔다.

## 7. 후처리 순서와 실측 판정

코드는 남아 있다 — `tools/art/SheetCrop.ts`(시트 가르기) · `tools/art/Postprocess.ts`(알파 문턱 · 정렬) · `tests/helpers/SpriteMetrics.ts`(판정 수치) · `tools/art/PngCodec.ts`. 명세는 `tests/logic/SpriteMetrics.test.ts`. fal 매팅 호출기와 모델 비교 실행기(`FalMatting.ts` · `judge.ts`)는 지웠다 — 배경 제거 도구는 다음 슬라이스가 고른다.

1. **시트를 인물별로 가른다 — 배경만 있는 열을 찾아 가른다.** 균등 분할을 가정하지 않는다. 첫 캐릭터의 네 인물은 56–285, 331–550, 605–811, 840–1047에 서 있었다. 폭을 나눠 자르면 팔이 잘리거나 옆 인물이 딸려 들어오고, 그러면 매팅이 무엇을 하든 결과가 틀린다(`panelColumns` · `cropColumns`).
2. **배경을 제거한다.** 손수 색 키잉하지 않는다 — 임계값이 그 시트에서만 잰 값이라 캐릭터가 바뀔 때마다 다시 재야 했고 하루에 세 번 샜다. 후보 도구를 견줄 때는 **정리 단계를 거치기 전 원본 응답에 대고 잰다** — 알파 임계값과 RGB 정리를 지난 뒤에 재면 잡음을 뱉는 모델도 통과한다.
3. **알파 문턱을 건다** — 16 이하를 0으로 누르고 그 자리의 색도 함께 지운다. 254 이상은 255로 올린다(내부를 254로 내놓는 양자화를 되돌린다). 배경 제거 도구가 바뀌어도 이 단계는 남는다(`normalizeAlpha`). 건너뛰면 알파 1~64의 희미한 잔여가 캔버스 전역에 깔려 `alpha > 0` 상자가 캔버스 전체와 같아지고 Cocos의 Trim이 아무것도 잘라내지 못한다 — 눈으로는 배경이 지워진 것처럼 보여 저절로 드러나지 않는다.
4. **정렬 — 같은 캔버스, 같은 발 밑선, 가로는 발 중심.** 트림 상자 중심은 못 쓴다. 머리카락이 뒤로 흘러 측면 두 장의 트림 상자를 23px씩 반대 방향으로 밀었다. Sprite의 Trim은 끈다(`alignToCanvas`). 사양서 §6.4.
5. **수치를 찍고 판정한다.**

| 재는 것 | 함수 |
|---|---|
| 알파 대역별 픽셀 수(0 / 1~16 / 17~254 / 255) | `alphaHistogram` |
| Cocos의 Trim이 잘라낼 상자 | `trimBox` |
| 배경색과 구별되지 않는 불투명 픽셀 | `backgroundLeak` |
| 알파 0인 픽셀에 남은 색 | `residualBackgroundRgb` |
| 네 방향을 잇는 발 밑선 | `footLineY` |
| 윤곽에 배경색이 섞인 띠 — 좌우를 따로 | `edgeHalo` |

**수치는 비율이 아니라 정수 픽셀 수로 읽는다.** "0.00%"로 쓰면 캔버스 121,278px에서 열두 픽셀까지 통과한다. `edgeHalo`는 좌우를 합치지 않는다 — 깨끗한 쪽이 더러운 쪽을 희석한다.

판정 항목:

- [ ] 희미한 알파(1~16)가 0px — 아니면 3번을 안 걸었다
- [ ] 트림 상자가 캔버스와 다르다 — 같으면 Trim이 무효다
- [ ] 세트의 발 밑선 y가 같다
- [ ] 몸통이 캔버스 가로 중심을 좌우로 고르게 걸친다
- [ ] 알파 0인 픽셀의 RGB가 (0,0,0)이다 — 바이리니어 샘플링이 그 값을 이웃으로 끌어와 외곽에 테두리를 만든다
- [ ] 스프라이트 안에 배경색 불투명 픽셀이 없다(배경색에서 거리 12 이내 · 알파 200↑). 그림이 배경색과 닮은 부위가 있으면 0을 요구하지 않고 자리를 확인한다
- [ ] 윤곽에 배경색이 섞인 띠가 없다 — 좌우 따로. 위 항목들이 전부 통과시킨 실패를 사람 눈이 두 번 잡은 뒤에 생긴 항목이다(2026-08-21 · 22)

6. **파일로 내보낸다.** 이름은 사양서 §9.2, 자리는 §9.1 · §9.1.1. 신규 파일의 `.meta`는 AI가 만들지 않는다.

## 8. 아직 프롬프트를 쓸 수 없는 것

| 대상 | 무엇이 막고 있나 | 어디서 열리나 |
|---|---|---|
| **적 12종** | 원전 도상 시트가 미작성이다(사양서 §11). 출처 없이 프롬프트를 쓰면 잘못된 도상이 12종 전체로 증폭된다. 귀신 표본 요구사항(2026-09-16)은 [G2 귀신 표본 요구사항](../development/sessions/2026-09-15-blender-3d-gate-round2-g2-toon-ghost-brief.md) §5에, 표본 넉 장은 `cloud-storage/art/evidence/enemies/2026-09-17-ghost-samples/`에 있다 | 적 로스터 생성 슬라이스(백로그 F60 3단계 · F108) |
| **마법 이펙트** | `ParticleSystem2D`가 코드 · 프리팹 · 씬에 0건이라 "파티클을 척추로 삼는다"는 방법이 실측된 적이 없다. 텍스처를 먼저 만들면 방법이 안 된다는 것을 나중에 안다 | 프리팹 하나로 검증한 뒤(사양서 §12) |
| **맵 · 환경** | 배경은 어둡고 조용해야 한다는 방향(art-direction §7)까지만 있고 규격이 없다 | 백로그 F41 |
| **UI** | 스타일이 미확정이고 `/design-consultation`이 미실행이다(사양서 §10). 한국어 · 영어를 같은 폰트가 커버해야 한다는 제약만 서 있다 | J4 |

## 9. 라이선스에서 지킬 것

- 서비스 이용 조건은 `ops-licensing.md` §2.3(ChatGPT 웹). 서비스를 바꾸면 그 표에 행을 먼저 붙인다.
- **서비스 출력을 다른 생성 모델의 학습 · 파인튜닝 씨앗으로 쓰지 않는다.** OpenAI 약관도, 다시 쓰게 될 경우 fal 약관(§14 — 호스팅 모델은 전부 Third-Party Materials)도 같다.
- **특정 작가의 그림이나 기존 지식재산을 겨냥해 뽑지 않는다.** 레퍼런스로 넣는 이미지의 출처를 가린다 — 약관에서도, 아트 방향(부록 C)에서도 나온다.
- 내려받은 원본은 후처리본으로 덮어쓰지 않는다 — 서명이 증빙이다(`ops-licensing.md` §5).
